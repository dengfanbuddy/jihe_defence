# 2026-07-29 工作日志

## 技能系统架构分析

分析了 `skills.json` + `SkillSystem.ts` + `SkillInstance.ts` + `ProjectileEntity.ts` + `Scene_Game_Stage.ts` + `CombatSystem.ts` 的完整伤害链路。

### 当前系统的伤害流转
1. `normal_attack` 技能配置 → HeroEntity 技能槽冷却 → emit `HERO_ATTACK`
2. Scene_Game_Stage 监听 → `spawnBullet()` 创建 ProjectileEntity
3. 子弹飞行 → `checkCollisions()` 距离判定 → `CombatSystem.calculateDamage()` → `enemy.takeDamage()`
4. `ProjectileEntity.onHit()` 也 emit `COMBAT_ON_HIT`（供被动技能监听附加效果）
5. `BattleEntity.takeDamage()` emit `COMBAT_ON_TAKE_DAMAGE` / `ENTITY_DEAD`

### 关键结论
- **基础伤害由碰撞系统处理，不需要为"子弹命中产生伤害"单独配被动技能**
- `COMBAT_ON_HIT` 事件是给被动技能（火焰附魔/子弹分裂/吸血等）用的，不是给基础伤害用的
- 被动技能只负责"附加效果"，基础伤害逻辑在 `checkCollisions()` 中

### 四种设计方案对比
- **方案A (当前)**: 碰撞系统处理 — 简单但伤害逻辑不可配置
- **方案B (推荐)**: 子弹自带伤害payload, onHit()调用伤害计算 — 子弹自包含
- **方案C (最灵活)**: 效果驱动, 技能配置 onHitEffects, 命中时执行效果链 — 全数据驱动
- **方案D (用户问的)**: 主动+被动联动 — 对基础伤害来说过度设计

### 其他游戏的做法
- Survivor.io/海彼: 被动技能增加攻击段数, 主动技能直接造成伤害
- 守个蛋"定义之门": 条件+效果分离配置 (when X, do Y)
- Unity塔防Demo: 事件驱动, 子弹负责飞行命中, 事件广播给监听者
- GAS(Unreal): TargetData 解耦命中检测和伤害应用
