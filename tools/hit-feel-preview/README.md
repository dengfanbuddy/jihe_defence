# 打击感演示台（hit-feel-preview）

**用 47 个开关把「无打击感 → 打击感全开」演示出来**，全几何图形绘制，配色 / 时长 / 数值全部取自工程真源。

```text
双击打开  tools/hit-feel-preview/index.html     ← 零依赖、零构建、不需要起服务
```

> 页面没有任何 `fetch` / 模块导入 / 外部资源，`file://` 直接可用。
> （运行时是在 `http://127.0.0.1:8791` 的临时静态服务上验的 —— 无头浏览器工具不接受 `file://` URL；两者对这份页面等价。）

---

## 1. 它解决什么问题

「打击感」是个形容词，吵架时谁也说不服谁。这个页面把它拆成 **47 个可独立开关的要素**：

- **每个开关都标注了工程落点**（哪个文件 / 哪个字段 / 哪个事件）与状态：`已有` / `待新增` / `口径冲突`；
- **总开关从 0% 拖到 100%**，就是「无打击感 → 全开」；
- **预设档**里有一档叫「**项目当前**」——只开 3 项，**那就是工程现在的打击感水位**，一眼看见我们站在哪；
- **场景按钮**里有「AoE 怪群 ×20」——塔防特有的终极大考（同帧 20 次命中）。

一句话：**拿它当需求评审的道具，而不是当特效预览。**

> ### 「本作建议」档（2026-10 新增）= 已拍板的设计档
>
> 47 项里 **开启 30 / 关闭 17**（关闭的 17 项里有 3 项是**降级/并档**：A1 前摇→起手印痕、C5 火花→刻度短线、C6 粒子→只保留在死亡碎裂里）。
> 6 项「口径冲突」的裁决：**做 3**（C10 墨闪限做 / D1 震屏改造成内容层位移 / **E1 命中音效 —— 2026-10 已落地，素材由 `tools/hit-feel-sfx/` 自研离线渲染**）· **不做 3**（C2 / C11 / F2）。
> 取舍理由、**档位表（T0~T7 的顿帧毫秒 / 位移像素 / 印痕形状）**、预算与合并口径、落地批次与验收标准，
> 全在 **`docs/打击反馈设计.md`** —— 本页是**菜单**，那份文档是**点菜结果**。
> 两边不一致时**以设计文档为准**：改这一档必须同步改那份文档。

## 2. 界面

| 区域 | 作用 |
|---|---|
| 顶部 **总开关** | 0→100% 把 47 项一起点亮/熄灭；右侧显示 `覆盖率 · 档位 · 平均强度` |
| 顶部 **预设** | `无打击感` / `项目当前`（默认）/ **`本作建议`** / `基础` / `全开` / `用力过猛` |
| 顶部 **场景** | `单发普攻` / `暴击` / `AoE 怪群×20` / `Boss 死亡` / `清场重置` |
| 顶部 **演示参数** | 暴击率(cap 60%)、暴击倍率、同屏怪数、音效音量、**按游戏真实概率** |
| 左侧 **7 组开关** | 每项：开关 + 强度滑杆 + 一句话原理 + **工程落点** + 状态徽章 |
| 舞台右上 **预算面板** | 同帧命中峰值 / 飘字并发 / 特效并发 / 超限丢弃 / **draw call 估算** / 震幅 / 时间缩放 |
| 舞台左下 **事件检查器** | 实时显示 `OnTakeDamage` 载荷 + 累计统计 |
| 舞台右下 **图层顺序** | 与预制件节点顺序一一对应，标明哪几层参与震屏 |

**它为什么能证明「不用改战斗逻辑」**：页面内部复刻了 `DamagePipeline` 发出的
`OnTakeDamage` 载荷 `{source, target, rawDamage, finalDamage, damageType, isCrit}`，
**47 个开关就是这同一个事件的 47 个订阅者** —— 正如 `DamageTextLayer.onTakeDamage` / `HitFlash.hit` 那样。
唯二要碰战斗侧的东西只有两条：**顿帧要缩 `dt`，震屏要拿到容器引用**。

操作：点舞台 = 启用音效 + 对最近的目标手动开火；`空格` = 暂停刷怪；`R` = 重开；`1` = 强制下一发暴击。

## 4. 五道必须先定的口径（否则开关会互相打架）

| # | 冲突 | 口径 |
|---|---|---|
| 1 | **缩放归属** | `HitFlash.apply` 现在独占 `node.setScale`（= `UNIT_VISUALS.scale`）。挤压拉伸必须**乘上去**：`最终 scale = 基准 scale × 瞬时形变倍率`，不能各写各的 |
| 2 | **位移归属** | 击退改**逻辑 `position`**（持久、影响 AI / 索敌）；抖动与倾斜**只能改表现层 offset**（瞬时），绝不能写回 `entity.position` |
| 3 | **飘字层与震屏容器** | 预制件里 `damege_layer` 与 `enimys` **同级同变换**（position 都是 `(0,0)`、scale 都是 1）。震屏若只位移 `enimys` 而不含 `damege_layer`，**飘字会与实体错位** —— 要么整块战斗内容一起震，要么飘字不参与（"飘字不震"也是一种风格，要选） |
| 4 | **颜色归属** | 飘字层铁律是"**一个视觉通道只承载一个含义**"，颜色已给"打谁"。所以"伤害类型配色"会直接打架 → 建议类型改由**形状/符号**承载 |
| 5 | **事件粒度** | `OnTakeDamage` 载荷够用，但 **DoT 与普攻都不带 `ability` 字段**（工程备注已记）。想区分"这一下是谁打的"（比如只给普攻上顿帧），需要给 `ApplyDamage` 的 options 加一个可选 tag |

## 5. 两个体检脚本

演示台是单文件 HTML，好处是双击即开，代价是**常量会跟工程漂移**。所以配两个脚本：

```bash
node tools/hit-feel-preview/check-drift.mjs   # 160 项：快照 vs 工程真源，漂移退出码 1
node tools/hit-feel-preview/audit.mjs         # 78 条：node 里打桩，真跑页面脚本做断言
```

### `check-drift.mjs` —— 常量对账（160 项）

把 `index.html` 里 `<script id="project-const">` 的快照逐字段与真源比对：

| 来源 | 比什么 |
|---|---|
| `common/EntityVisualConfig.ts` | `HIT_FLASH_DURATION` + 7 类单位的 color / scale / hitColor |
| `common/DamageTextConfig.ts` | 11 个全局标量 + 描边色 + 两档（normal/crit）的全部字段 + 英雄受击色 |
| `resources/tb/battle_constants.json` | `pxPerMeter` / `critDmgBase` / `critRateCap` / `atkSpeedCap` / 弹道速度 … 10 项 |
| `resources/tb/attributes.json` | 攻速 / 魔抗 / 暴击率 / 暴击倍率的 `base` 与 `stack_mode`（含 int = 值×100 换算） |
| `resources/tb/units.json` | 火枪 1001 与 5 只怪的全部数值（**含百分比型属性 int→比例**换算） |
| `resources/tb/abilities.json` | 技能 16 的三个参数（`pct 0.05` / `chance 0.15` / `knockback 1`）与 modifier 引用 |
| `docs/美术风格预设.md` | 12 个美术色号必须仍在该文档里（美术改底色会报警） |
| 文件存在性 | 页面引用的 18 个工程文件都必须在（防挪文件后落点表失效） |

改工程真源后此处报警，修法就一句：**把 ✗ 行的「真源」值写回快照，重跑**。

### `audit.mjs` —— 真跑页面的体检（78 条）

不重写一份逻辑，而是**把 DOM / canvas 2D / rAF 全部打桩，把 `index.html` 的主脚本原样 `vm.runInContext` 跑起来**，用确定性 rAF 时间戳驱动（对齐工程 `npm run audit:attr` / `audit:slot` 的套路）：

- ① 启动 / ② 开关注册表（47 项、分组 5-6-11-5-6-10-4、id 唯一）/ ③ **帧增量守卫**（rAF 成簇不得让仿真跑飞）
- ④ 预设与总开关 / ⑤ **47 项逐个单开各跑 60 帧不抛错** + 全开 120 帧 + 全关 120 帧
- ⑥ 伤害口径（Dota 双曲减伤逐档、端到端一发秒哥布林、暴击 1.5×、`hp≤0` 之后吃不到伤害）
- ⑦ 火枪技能 16（额外伤害 = 攻击力×5% = 2、飘字合并 34+2=36）
- ⑧ 击退（`pxPerMeter=50`、演示模式必触发 150px、真实模式 ≈15% 且 ≤1m、**英雄 immovable 不被推**）
- ⑨ 顿帧（时间缩放生效且倒计时走真实时间、不会卡死）
- ⑩ **多目标合并**（G2 开 = 20 只同帧只出 1 个冲击波；关 = 20 个）
- ⑪ 分级 + 钳制（D5 取最大 8.84px vs 相加 88.36px）
- ⑫ VFX 预算（G3 开不超上限且有丢弃计数；关则无上限）/ ⑬ 飘字（上限 24、合并、颜色通道、暴击档）
- ⑭ 常量快照 / ⑮ **全开连续跑 3600 帧（≈60s）**：无异常、怪数受门控、尸体不堆积、英雄不死

> 这两个脚本真抓出过东西：**帧增量守卫**（`(ts-lastT)/1000 || 0.016` 里 0 是 falsy → rAF 成簇时每个空帧白推 16ms 战斗，实测命中数是理论值的 3~5 倍）与**英雄未被击退**（少了 `immovable` 判断，与 `Entity.ApplyKnockback` 的口径不符）。

## 6. 与工程的已知差异（演示台的取舍，别当成实现方案）

| 方面 | 演示台 | 工程内应怎么做 |
|---|---|---|
| **数字字形** | 系统粗体 + `strokeText` 描边 | `GeometricDigits.ts` 手写几何字形（零字体资产）—— demo 不复刻字形，只复刻**字号/描边/尺度/寿命/tier 参数** |
| **粒子** | canvas 2D 图元（小方块 / 三角） | 项目禁贴图禁渐变 → 同样用几何图元；但要走**整层一个 `Graphics`** 的池化画法（参照 `DamageTextLayer`），而不是每颗粒子一个节点 |
| **音效** | Web Audio 程序化合成（方波 + 噪声 + 包络 + 70Hz 正弦） | 需要先有音频素材；接 `AudioMgr.ins.sfx`，并把"三层 + 音高随机 + 并发节流"这三条一起做 |
| **震屏** | 位移**战斗内容容器** | 同上（动相机会把 HUD 一起抖）；要真·相机震屏就得给战斗单分 layer + 独立相机 |
| **后处理** | 离屏画布做变焦模糊 + 色差（可演） | 项目无后处理管线，成本高；浅底上更推荐 **C3 描边脉冲 / C4 冲击波 / C10 墨色闪帧** 这三项替代 |
| **场景** | 用真实配表数值搭一个"英雄守点 + 怪从 650~800px 走进来"的最小战场 | 就是工程的实际战斗场景 |
| **美术与代码的张力** | 按 `UNIT_VISUALS` 给怪物**染色**（普通 `#6B8E9B` / 精英 `#9B59B6` / Boss `#E74C3C`） | ⚠ `docs/美术风格预设.md` 写的是"敌人本体：灰调墨线徽记，浅底上以**灰阶**区分，不靠彩色"，而代码实际按 `UNIT_VISUALS` 染色（与受击色配套）。**这是一处真实的规范冲突，演示照代码口径来**，需要美术/策划拍板 |

改这个演示台的三条纪律：

1. **改工程真源 → 必须同步 `index.html` 里的快照 → 跑 `check-drift.mjs`**（不然演示的数字会悄悄变成假的）。
2. **加/改开关 → 改 `<script id="features">` 那张表**（不是改代码）：`id` 稳定、`g` 分组、`why` 一句话原理、`file` 工程落点、`st` 状态、`d` 默认强度、`note` 满格的物理含义。然后跑 `audit.mjs`（它会验总数 = 47 与分组计数，改数量要同步改断言）。
3. **强度滑杆必须可验收**：`note` 里写清满格等于多少毫秒 / 多少像素 / 多少度 —— 对齐 `docs/游戏开发术语速查手册.md` §0 的"可验收的量化描述"，别写"更爽一点"。
