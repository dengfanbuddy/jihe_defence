# 火山方舟 · 图片风格迁移工具（透明背景 + 批量）

给**参考图**（风格来源）和**目标图**（内容来源），用火山方舟的 Seedream 图片生成模型把目标图重绘成参考图的风格，
再本地抠成**透明背景 PNG**，无水印。带一个本地 Web 操作台：单图调试 + 整目录批量。

```
参考图（画风/材质/配色）┐
                        ├─→ 方舟 Seedream（多图参考，双图角色分开说明）
目标图（造型/结构）────┘        ↓ 纯色背景直出图（_raw/）
                           本地色键抠图 + 去溢色 + 修边（sharp）
                                ↓
                           成品 PNG（透明背景 + _thumb/ 缩略图 + _report.json/csv）
```

## 1. 安装与启动

```powershell
cd tools\ark-style-transfer
npm install                # 只依赖 sharp
npm start                  # 默认 http://127.0.0.1:8788，会自动打开浏览器
```

其它参数：

```powershell
node server.mjs --port 9000        # 换端口（被占用会自动 +1 重试）
node server.mjs --host 0.0.0.0     # 局域网可访问（默认只绑 127.0.0.1）
node server.mjs --no-open          # 不自动开浏览器
```

**API Key**：打开界面右上角「设置」粘贴火山方舟**长效 API Key**（保存在本工具 `.data/config.json`，不上传任何地方）；
也可以先设环境变量再启动：

```powershell
$env:ARK_API_KEY = "你的key"; npm start
```

> Key 从火山方舟控制台 → **API Key 管理** 获取；模型要在 **开通管理** 里开通，否则会报「模型未开通」。
> 默认端点是北京区 `https://ark.cn-beijing.volces.com/api/v3`；换 BytePlus 就在设置里改端点。

## 2. 单图调试台（先把一张调好）

1. **选图**
   - **参考图**：风格来源。点虚线框选文件、把图片拖进去，或者直接把本地完整路径粘到输入框（回车生效）。
   - **目标图**：内容来源。同上。
   - 「互换」按钮可以把两张图的角色对调。
2. **提示词**
   - 内置 4 个预设（风格迁移中/英、高清重绘、像素卡通化），也可以自己手写。
   - 提示词里的 `{keyHex}` 会替换成「透明背景」卡片里的键色。
   - 勾选「自动声明图1/图2 各取什么」会在最前面加一句角色说明（方舟官方建议多图输入时显式说明每张图的用途）。
   - 展开「最终发送给模型的提示词」可以看实际发出去的内容。
3. **模型与出图**
   - 模型下拉（见下表）；也可以填**自定义模型 ID 或 Endpoint ID**覆盖下拉选择。
   - 图片尺寸：按档位（`1K/1.5K/2K/4K`，由模型决定宽高）或自定义 `宽x高`（须落在该模型允许的总像素区间）。
   - 图片品质 = 提示词优化档位：`不优化 / 极速fast / 标准standard`。
   - 输出格式：`png`（要透明就选它）/ `jpeg`。
   - **无水印**：默认就不加水印（勾选框保持不勾即可，方舟默认是加「AI 生成」角标的）。
   - 组图模式默认关闭（一次出 1 张，最省）。
4. **透明背景**（核心）
   - **色键抠图**（默认，推荐）：提示词要求模型把主体画在纯色背景上，本地按连通域抠掉 + 边缘去溢色。
     **双图（参考图 + 目标图）风格迁移要做透明背景，只能走这一条**。
   - **接口直出透明**：方舟的 `background=transparent`。⚠ 它**不是"去背景"**，见下面「透明背景的真实规则（实测）」——
     必须**恰好 1 张输入图**、且这张图**本身已经有透明像素**，所以和双图玩法冲突；界面会拦住「参考图 + 接口透明」这个组合。
   - **沿用目标图 alpha**：目标图本身已经是抠好的透明 PNG 时用。
   - **不处理**：保留模型直出的不透明图（**输出一定不透明**，提示词里写"背景透明"也没用）。
   - 可调：键色 / 容差 / 渐变生长 / 边缘收边 / 自动探测背景色 / 去溢色 / 裁掉透明边 / 补成正方形 / 最终边长。
5. **输出**：成品图 + `_raw/`（模型直出图）+ `_thumb/`（缩略图）。
6. 点 **生成**。右边出结果，并给出**质检信息**（键色、透明占比、主体范围、边缘修正像素、告警）。
   - **只重跑抠图**：拿 `_raw/` 里上次的直出图重新抠一遍，**不再调接口、不计费** —— 调容差/键色时用它，别重复花钱。

  到底能不能生图 —— **不会出图、不会计费**。结论会标成 ✓/✗ 存进配置，下拉里直接显示。

## 3. 批量处理

切到「批量处理」页：

1. **输入文件夹**：要处理的一批图，例：`E:\project2\AI\dota2_equip\output\icons`。点「扫描」会列出张数与**预估费用**。
2. **输出文件夹**：默认工具目录下的 `out\`。输入与输出不能相同（不会覆盖原图）；输出文件与输入**同名**。
3. **参考图**：批量共用「单图调试台」里选的那张（本页可以单独换）。
4. 选项：包含子文件夹 / 跳过已生成（断点续跑）/ 只处理前 N 张。
5. **模式**
   - **重新生成**：真的调接口，**会计费**。
   - **只重跑抠图**：用 `_raw/` 里已有的直出图重新抠，不计费（调抠图参数时用）。
6. 并发（默认 2，被限流就调成 1）/ 单张失败重试次数。
7. 点 **开始批量**：进度条 + 实时列表（缩略图/状态/耗时/失败原因），跑完出「原图 → 成品」结果网格。

批量产物（都在输出文件夹里）：

其它按钮：**取消**（正在跑的那张会跑完）、**打包下载 ZIP**、**导出报告**、**打开输出文件夹**。

## 4. 透明背景是怎么做到的（以及为什么不能只靠接口）

### 4.1 透明背景的真实规则（**真调用实测**，不是读文档猜的）

`background=transparent` 在官网文档里被标为「支持」，但它**不是"去掉背景"**，而是
**「保留输入图已有的透明通道」**。三条结论都是花了 3 次真调用问出来的（`npm run test:transparent` 可复跑，约 0.3 元）：

| 用例 | 输入 | 结果 |
|---|---|---|
| A | **2 张**输入图（参考图 + 目标图） | ❌ HTTP 400 `InvalidParameter`：<br>`transparent background requires exactly one input image` |
| B | **1 张**输入图，**有 alpha 通道但像素全不透明** | ❌ HTTP 400 `InvalidParameter`：<br>`transparent background requires a PNG input with at least one transparent pixel` |
| C | **1 张**输入图，**真的有透明像素** | ✅ 出图，透明像素 62.8%、半透明 32.9%、`alphaMin=0` |

所以：

1. **双图风格迁移（参考图 + 目标图）用不了接口透明** —— 它要求恰好 1 张输入图。
   界面会**拦住**这个组合（选了「接口直出透明」又勾了参考图 → 当场切回色键抠图并提示；后端也会在下单前拒绝，
   **不花钱**）。老版本的坑：`processOne` 里静默把参考图丢掉（`useRef && alphaMode !== 'api'`），
   用户以为在做风格迁移、实际是单图重绘 —— 批量时就是白花一整批的钱。
2. **dota2 图标这类"有 alpha 通道但全不透明"的图也不行** —— 它要的是**至少 1 个透明像素**，
   通道在不在无所谓。这一条免费就能判，工具在下单前就会拦住（省掉注定 400 的请求）。
3. **「背景必须透明」写进提示词是拿不到透明的** —— 模型没有 alpha 输出通道（实测 flash 的直出图 1024×1024 PNG
   **连 alpha 通道都没有**）。抠图模式下提示词这么写会当场告警：请改成「背景必须是纯色 #FF00FF」。
4. 用例 C 虽然"成功"，但它是**重新生成**了一遍而不是"搬运 alpha"：实测输出 63% 全透明 / 32% 落在 alpha 204~254 /
   只有 4.4% 完全不透明（输入是 44% 完全不透明）→ 主体整体被调成了 ~85% 半透明。
   游戏图标要的是**主体实心 + 背景透明**，所以本工具不把它当默认路径。

### 4.2 本工具的做法：纯色背景 + 本地色键

因为上面三条，双图场景的透明只能**本地抠**：

1. 提示词里硬性要求模型把主体画在**纯品红 `#FF00FF`** 背景上（键色可改）；
2. 本地从画面边框向内泛洪，只吃掉**与边缘连通**的背景 —— 主体内部恰好同色的区域会被保住；
3. 泛洪同时要求「接近底色」**和**「与相邻像素颜色连续」，所以主体边缘的颜色突跳会自然挡住泛洪；
   模型就算无视提示词换了背景色、画了渐变/暗角，也能靠实测边框底色抠出来；
4. 边缘像素按到「贴边底色」的距离给半透明，并用反混合 `F = (P - (1-a)K)/a` 还原真实颜色 —— 不会留品红描边或黑边；
5. 可选收边 1px + 裁掉透明边 + 补正方形 + 缩放（缩放走 premultiplied alpha，半透明边缘不会发黑）。
6. **成品自检**：写完盘后重新量一遍成品图的 alpha（不信任中间态），若"要求了透明却没有透明像素"
   会在质检区、批量 `_report.csv` 的 `alphaOk` 列里明确报出来 —— 不会再出现"拿到不透明图却没人说"。

- **安全阀**：如果抠图会去掉 >96% 或 <1% 的画面（明显把主体一起吃了 / 根本没抠到），
  这张图**整张回退成不透明**并在质检里报出来 —— 批量时不会静默毁图，你按报告里的话调参重跑即可。

### 4.3 「换了参考图，出图却差不多」是不是真的？（实测）

是**真的**，而且主因有两个：一个是本工具自己的 bug（已修），一个是这类模型对「风格参考图」本来就服从得很弱。
下面每组数字都是真调用测出来的（7 次调用 ≈ 0.9 元）。产物留档在 `.data/ref-effect/`：
A~D 是「2 张参考图 × 放大/原尺寸」四格对照（`summary.json` 是量化指标），F/G 是「改提示词 / 换 pro」两次杠杆测试（`levers.json`），
可以直接打开这 6 张成品自己看（同名 `_raw/` 是模型直出图）。

**① 本工具的 bug：把 88×64 的图标放大 5.8 倍再送接口（已修）**

| 图标 | 原图 | 老口径送出去的 | 细节量（相邻像素亮度差） |
|---|---|---|---|
| aegis | 88×64 | 512×372 | 17.16 → **3.05**（掉 82%） |
| desolator_2 | 88×64 | 512×372 | 38.89 → **6.82**（掉 82%） |

风格的"信号"全在细节里（描边粗细、笔触、材质），放大只会把它糊平 —— 参考图送进去是一团糊，
**不同参考图之间的风格差异被抹掉了一大半**。方舟对输入图的要求只是「宽高都 > 14px、≤ 6000×6000、单张 ≤ 30MB」，
小图原样送完全合法。现已改成**只缩小、不放大**（`normalizeInput({ allowUpscale: false })`，界面上有开关，
默认关）。顺带一个反直觉的数据：**光是"放大 vs 原尺寸"这一项造成的输出差异（16.5/255），
和"换一张风格迥异的参考图"造成的差异（17.4~29.2/255）是同一量级** —— 也就是说这个 bug 注入的噪声，
跟风格信号一样大。

**② 参考图确实起作用，但很弱**

同一张目标图（aegis），只换参考图，输出的风格指纹变化（参考图本身：dota2 饱和度 0.665 / 中间调 36.2%；扁平矢量 0.202 / 4.8%）：

| 参考图 | 输出饱和度 | 中间调 | 近黑描边 | 独特色 |
|---|---|---|---|---|
| dota2 厚涂（desolator_2） | 0.249 | 10.6% | 13.2% | 618 |
| 扁平矢量（自制粗描边） | 0.313 | 8.7% | 17.2% | 445 |

四项**方向全对**（换扁平矢量后：更饱和、更少中间调、描边更重、颜色更少），说明参考图真的被读了；
但**幅度很小**，而且输出的饱和度（0.25~0.31）离 dota2 参考图的 0.665 差得很远 ——
模型并没有在"临摹"参考图的色彩与材质，它更像是在参考图里找**内容线索**，画风则用它自己那套默认的"游戏道具图标"先验。

**③ 两个常见杠杆都拉不动它（各测一次）**

| 做法 | 饱和度（离参考差距） | 中间调 | 结论 |
|---|---|---|---|
| 基准：flash + 现在的提示词 | 0.249（差 0.416） | 10.6% | — |
| **改成"严格照抄图1 的画法"的提示词** | 0.295（差 0.370） | 12.2% | 略好，但形状跑了（宽高比 0.89 → 1.22，内容保真变差） |
| **换 5.0 pro** | 0.285（差 0.380） | 9.8% | 略好、颜色更少更"设计感"，但 42 秒 / 约 2.5 倍价 |

**④ 所以怎么用才对**

1. **把画风写成文字**（这是最有效的杠杆）：界面新增「风格描述」字段，会以"最高优先级"追加进提示词。
   例：`厚涂写实、金属高光锐利、暗部偏紫、边缘一圈暖色轮廓光；不要扁平化、不要矢量感`。
2. **参考图要"够大够不同"**：拿另一张 **88×64 的本系列图标**当参考图基本等于没换（它们本来就是同一个画风、同一套渲染）；
   想改风格就用 512×512 以上的成品画作/宣传图当参考。
3. **先确认参考图真的发出去了**：质检面板新增「输入图」一行，写着每张图的角色、文件名、原始尺寸 → 实际发送尺寸
   （被放大时会标 ⚠）。看不到参考图那一行 = 它根本没发出去。
4. 目标图本身只有 88×64 时，模型是在"补画细节"而不是"重绘你给的东西"——想要更贴原图，目标图也尽量给大图。

### 4.4 抠图默认参数是怎么定出来的（真实出图实测）

用一张真实的 flash 出图（`out/_raw/smoketest_aegis.png`，1024×1024）量出来的事实：

- 键色（自动探测）`#F709D7`，**边框平坦区很干净**：到键色的距离 p50=8 / p99=18 / σ=4.1；
- 但主体边缘有一圈「背景与主体混色」的**过渡带**，最远到 150 左右；
- 渐变上界若按「容差的 1.6 倍」写死（≈109），过渡带外圈会以 alpha=255 留下 → **约 0.745px 的键色描边**；
- 把渐变上界放到实测的过渡带宽度（自适应，`rampHi = 泛洪区距离 p98`），并把**默认容差 68 → 88**：

| 容差 | 透明占比 | 贴边杂边厚度 |
|---|---|---|
| 50 | 53.7% | 0.991px（肉眼可见一圈） |
| 68（旧默认） | 54.2% | 0.745px |
| **88（现默认）** | **54.7%** | **0.237px** |
| 110 | 55.2% | 0.052px（但主体被啃得更多） |

所以**默认容差是 88**；边缘留色边就加大、啃到主体就减小。质检里会给出 `fringePerEdge`
（贴边杂边厚度），>0.5px 会直接在界面与报告里提示「调大容差 + 只重跑抠图」。

想自己量：`npm run tune -- out/_raw/xxx.png`（一次跑 8 组参数并打出客观指标，不花钱），
加 `--diag` 还能打印背景底色分布与建议容差。

## 5. 命令行 / HTTP 接口（想接进别的流程时用）

服务是本机 HTTP 接口，全部 POST + JSON：

| 接口 | 作用 |
|---|---|
| `GET /api/config` | 模型表、默认参数、提示词预设、Key 状态 |
| `POST /api/config` | 保存 `apiKey` / `baseUrl` / `params` |
| `POST /api/models` | 拉取账户模型列表（`GET /models`，仅发现用） |
| `POST /api/models/probe` | **免费**校验模型 ID 能否生图（`{model}` 或 `{all:true}`） |
| `POST /api/prompt/preview` | 看最终提示词（含 `{keyHex}` 替换与角色声明）|
| `POST /api/generate` | 单图：`{params, ref, target, outDir, outName, mode}`，`mode=realpha` 表示只重跑抠图 |
| `POST /api/scan` | 扫目录：张数 + 预估费用 |
| `POST /api/batch` | 起批量任务，返回 `jobId` |
| `GET /api/batch/:id` | 任务快照（含逐条状态）|
| `GET /api/batch/:id/events` | SSE 实时进度（`progress` / `item` / `step` / `log` / `finished`）|
| `POST /api/batch/cancel` | 取消任务 |
| `POST /api/zip` | 把输出目录打包成 ZIP |
| `GET /api/report?dir=` | 读 `_report.json` |
| `GET /api/image?path=&w=` | 读本地图片（`w` 出缩略图），界面预览用 |
| `POST /api/reveal` | 在资源管理器里打开某个路径 |

`ref` / `target` 支持两种形态：`{"path": "E:\\...\\a.png"}` 或 `{"dataUrl": "data:image/png;base64,..."}`。

## 6. 自测

```powershell
npm test                      # 抠图链路 + 下单前守卫 + 界面接线（不需要 Key、不花钱）
npm run test:alpha            # 21 项：纯色/渐变/JPEG/深色背景/安全阀 + 主体保留 + 色边厚度
npm run test:alpha -- "D:\icons"   # 换成你自己的图标目录
npm run test:guard            # 透明背景的 3 条下单前守卫（接口透明×参考图 / 无透明像素 / 放行）；免费
npm run test:ui               # index.html 与 app.js 的接线契约（选择器/参数字段/控件/互斥拦截）
npm run test:e2e              # 批量端到端（SSE/报告/ZIP/断点续跑）—— 需先 npm run dev 起着服务
npm run test:models           # 免费校验内置模型 ID/别名能不能生图
npm run test:transparent      # 真调用查清 background=transparent 的边界（3 例，约 0.3 元）
npm run tune -- out/_raw/x.png   # 对着已有直出图试 8 组抠图参数（不花钱）；加 --diag 看背景底色分布
```

`test:alpha` 会在 `.data/test/` 里留下「直出图」和「抠图结果」各 3 份，可以直接对着看抠图质量。
图标目录不存在时会用内置合成主体（带一块「接近键色的宝石」用来验证主体内部不被误抠），所以自测是自包含的。

## 7. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `未配置 API Key` | 右上角「设置」填 Key，或设环境变量 `ARK_API_KEY` 后重启 |
| `The model or endpoint … does not exist or you do not have access to it` | **最常见**：用了不带日期的别名，或该模型没开通。点「校验模型 ID（免费）」看 ✓/✗，下拉里选 ✓ 的那一版；也确认「开通管理」里开了 |
| `触发限流` | 批量并发调成 1；或稍后重试 |
| `内容审核未通过` | 换提示词 / 换参考图；图标类素材偶发 |
| 抠不干净（残留背景） | 调大「容差」（默认 88，可试 100~110）；模型没照做就靠「自动探测背景色」；用「只重跑抠图」反复试，不花钱 |
| 主体被吃掉 | 调小「容差」和「局部连续」；换一个主体上不会出现的键色；或关掉「自动探测背景色」 |
| 边缘有彩色描边 | 看质检里的「贴边杂边厚度」；>0.5px 就把容差加大 15~25 再「只重跑抠图」；「去溢色」保持勾选，「边缘收边」可调 1~2 |
| 输出尺寸不对 | 「补成正方形」+「最终边长」控制成品尺寸；不勾补方形就只按最长边等比缩放 |
| 结果网格空白 | 批量任务需要保持界面开着（进度走 SSE）；刷新页面后用「导出报告」看结果 |
| 想彻底重跑 | 取消勾选「跳过已生成」，或换一个输出文件夹 |

## 9. 已知边界

- 服务**只绑 127.0.0.1 且没有鉴权**，是单人本机工具；不要暴露到公网。`.data/config.json` 里存着明文 Key。
- 只处理**图片**（png/jpg/webp/bmp/gif/avif/tiff）；输入按文件名排序，输出同名同格式（成品统一 PNG/JPG）。
- 批量任务**不落盘续跑队列**：关掉服务后重开，任务列表会清空，但「跳过已生成」能让它接着跑。
- 组图模式（`sequential=auto`）一次返回多张时只取第 1 张。
- 4.x 模型在部分场景只返回 jpeg；jpeg 也能抠图（自测覆盖），但 PNG 输出的边缘更干净，**建议用 5.0 系列**。
- 模型 ID 带版本日期，官方发新版后**旧 ID 可能失效** —— 报「模型不存在」就点「校验模型 ID（免费）」，
  把 ✓ 的那一版填进「自定义模型 ID」（会记住），并按 `src/config.mjs` 顶部注释同步登记表。
