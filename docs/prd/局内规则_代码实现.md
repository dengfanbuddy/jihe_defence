## 1. 对局流程（一次对局跑什么）

### 1.1 阶段状态机（`game_stage/GameStateType.ts`）

```
HeroSelection → PreBattle → Battle →（PhaseBoss → FinalBoss）→ Victory / Defeat / Pause
```

`GameStageContext`：`gold / killCount / currentPhase / phaseRemainingTime / activeEnemies / isPaused / bossRemainingTime`。
`useBattleStore`（响应式）：初始 `phase=1, maxPhase=4(0=无尽), phaseRemainTime=300, hp/maxHp=100, level=1, exp=0, expToNext=60, gold=0, refreshGold=100`。

### 1.2 当前实际运行（`Scene_Game_Stage.ts`）

运行顺序（`update`）：
```
if (isPaused) return
if (!ctx || finished || !hero) return
if (hero.IsDead()) return
checkStage(dt)   // 阶段倒计时 + 刷怪计时
tick(dt)         // 单步推进
```

- **选英雄** `selectHero`：`heroId = Number(payload.ID)`，非 team=1 英雄时回退 `config.heroUnitId`(默认 3 赏金猎人)，`getUnitDef(heroId) ?? config.heroUnitId`。英雄放置 `config.center`，`immovable=true`（锚点：实体分离时只推怪不推英雄）。
- **默认玩法参数 `defaultConfig`**：
  ```
  heroUnitId: 3            // hero_bounty
  monsterPool: [4,5,6,7,8,9]  // 哥布林/巨魔/游荡者/环绕魔/重击者/深渊领主
  skillPool: [1,2,4,5]     // 火球术/霜冻新星/战吼/闪电链
  relicPool: [2,1,3,4]     // 吸血獠牙/荆棘护甲/烈焰之剑/巨人之心
  spawnInterval: 2.5, spawnIntervalMin: 1.0, spawnCountStart: 1
  shopEvery: 20, winTime: 90, maxSkillSlots: 3, killHeal: 6
  spawnRadius: [650,800]
  ```
- **刷怪 `spawnWave`**（当前为**简化版**）：固定刷 `monsterId=4`（哥布林）；`bornCount = min(3, 50 - 场上存活数)`，从 `spawnRadius` 随机角度、半径刷出；`getSpawnInterval()` 恒返 `1`（每秒刷一次，最多 3 只/波）。
- **阶段推进 `checkStage`**：
  - `stageRemainTime` 倒计时；`phase=stage` 写入 store（每整秒更新 HUD）。
  - 归零时：`stage==5`（Boss 阶段超时未击杀）→ `finished=true, victory=false`（TODO 结算面板）；否则 `spawnBoss(stage)`（**空 stub**，仅 `console.log`），`stage++`，`stageRemainTime=300`（到 stage 5 则 `120`）。
  - 起始 `resetRun`：`stage=0, stageRemainTime=10`。
- **单步 `tick(dt)`**：
  1. `heroAI()`（普攻索敌 + 自动施法，见 §7）
  2. `updateProjectiles()`（为新弹道建视图）
  3. `ctx.Tick(dt)`（实体/Modifier/DoT/冷却/弹道推进）
  4. 商店计时 —— **被注释**（`openShop()` 不触发）
  5. 胜负判定 `checkEnd()` —— **被注释**（当前对局不自动判胜负）

### 1.3 胜负判定（代码有，当前未接）

```ts
checkEnd() {
  if (hero.IsDead()) finish(false);                 // 失败
  else if (elapsed >= config.winTime /* 90 */) finish(true);  // 胜利
```

### 2.2 属性合成规则（`AttributeSystem.combine`，Dota2 风格）

最终值 = 基础值，按固定顺序叠加，最后钳制到 `[min,max]`：

1. **add**：`result = base + Σv`
2. **multiply**：`result = base × Π(1 + v)`（倍率型，如攻速/伤害倍率）
3. **complement**：`result = 1 − (1 − base) × Π(1 − v)`（用于魔抗/闪避，叠乘越趋近 100%）
4. **best**：`result = Math.max(base, ...v)`（用于暴击倍率，取最高）

被修改时标记 `dirty`，下次读取统一重算（Property Resolution）。

## 3. 伤害计算（`DamagePipeline.ts`）

仿 Dota2 的分层结算，顺序如下（递归深度保险丝 `MAX_DEPTH=10`，超过直接判 0，防反射/连锁无限循环）：

```
guard
 → 1. 攻击者增伤(DamageOut=11，乘法)
 → 2. 暴击(CritRate=14 / CritDmg=15)
 → 3. 护盾/格挡(on_block_damage，Modifier 拦截，可吞伤害)
 → 4. 目标受伤增减(IncomingPhys=12 / IncomingMag=13)
 → 5. 抗性减免(护甲/魔抗)
 → 6. 扣血(先扣，事件监听者能看到扣血后的 HP)
 → 7. 事件广播(吸血/反伤/荆棘/受击后效)
 → 8. 死亡检查
```

### 3.1 无伤判定（guard）
- 目标已死 / `rawDamage<=0` → 0
- 目标 `Invulnerable` → 0
- 物理 vs `Ethereal`（虚灵）→ 0
- 非物理 vs `MagicImmune`（魔法免疫）→ 0

### 3.2 各阶段公式

| 阶段 | 公式 |
|---|---|
| 攻击者增伤 | `damage *= attrs.get(11) ?? 1` |
| 暴击 | `rollCrit`: 若 `CritRate>0 && CritDmg>1 && random<CritRate` → `damage *= CritDmg` |
| 护盾/格挡 | `damage -= on_block_damage 累积的 blocked`；`<=0` 返回 0 |
| 目标受伤增减 | `damage *= attrs.get(物理→12 / 魔法→13) ?? 1` |
| 抗性·物理 | `multiplier = 1 − (0.06×armor)/(1 + 0.06×|armor|)`（armor≥0 时等价 `1/(1+0.06×armor)`；负甲放大） |
| 抗性·魔法 | `damage *= (1 − magicResist)`（魔抗缺省 0.25） |
| 抗性·纯粹 | 不减免 |
| 最终 | `finalDamage = Math.max(0, damage)`（**无 `minDamage` 保底**） |

> 注意：`battle_constants.defenseFormula`（`def/(def+100)`）**未使用**；实际是上式 Dota2 护甲公式。

## 4. 普通攻击与弹道（`Entity.ts` / `Projectile.ts`）

### 4.1 普攻冷却
```
getAttackInterval() = attackBaseInterval / max(0.1, attrs.get(AtkSpeed=4))
```
- `attackBaseInterval` 默认 1.7s（近战骑士 1.7，法师 1.7，赏金猎人 0.85@攻速1.2 → **0.708s**，巨魔 2，Boss 2.5）。
- 攻速越快普攻越短；**无 `atkSpeedCap`**（实际上限=属性4的 max 1000 → 10.0 倍）。

### 4.2 普攻流程 `Attack(target)`
- 冷却中 / `!canAttack`（被眩晕/缴械等）/ 目标已死 → 不攻击。
- 进入攻击并开始冷却。
- 发 `OnAttackStart` + `on_attack_start`（Modifier 可 consume）。
- 若有普攻技能（`behavior=attack`，如飞镖）→ 交给 `ability.OnAttack(target)`。
- 若是远程（有 `attackProjectile`）→ `launchProjectile`（延迟命中）；近战 → 立即 `resolveAttackHit`。
- 普攻原始伤害 = `getAttackDamage()` = 属性3（攻击力）。

### 4.3 命中结算 `resolveAttackHit`（闪避在此）
```ts
evasion = target.attrs.get(Evasion=8) ?? 0;
if (evasion > 0 && Math.random() < evasion) return 0;   // 闪避，0 伤害
```
> 闪避**无 `dodgeCap`**；实际上限 = 属性8的 max `0.95`。

### 4.4 暴击
- 在 `DamagePipeline` 里由攻击者属性 `CritRate/CritDmg` 掷出（见 §3.2）。无 `critRateCap`，上限=属性14 max `1.0`。

### 4.5 弹道（两阶段结算）
- 发射时对**终点快照**，飞行到达后**才结算**命中。
- 速度：普攻用 `attackProjectileSpeed`（默认 **1200 px/s**）；技能伤害弹道用 `action.projectile_speed`；多目标弹道用 `action.speed`。
- **无最大飞行距离**（`projectileMaxDistDefault:2000` 未用）；`totalDistance = hypot(end-start)`，飞满即到。
- **无飞行中途碰撞检测**（`collisionDetectThreshold` 未用）；到达后 `snapToEnd()` 再 `onHit()`。
- `onHit()` 重新校验（目标死/无敌/虚灵/魔免 → miss；`isAttack` 走 `resolveAttackHit`→闪避→伤害管线→`OnAttackLanded`）。

> 结论：现版本弹道是「锁定目标、命中无折返、也无穿透判定」的简化实现。

## 5. AI 与索敌

### 5.1 索敌策略（`Targeting.ts`）
| 策略 | 规则 |
|---|---|
| `nearest`（默认） | 到参考点（英雄）距离最近 |
| `lowest_hp` | 当前 HP / MaxHP 比例最低（优先斩杀） |
| `farthest` | 距离最远 |
| `random` | 均匀随机 |
| `strongest` | `getAttackDamage()` 最高（威胁最大） |

`pickTarget` 选 1 个；`pickTargets` 排序后取 N 个（多目标弹道/群攻用）。

### 5.2 怪物 AI 类型（`ai/*`）
| 类型 | 行为 |
|---|---|
| `chase` | 全场索敌最近 team-1 目标（英雄），直线追；可选 `speedMul` |
| `wander` | 游荡，`wanderRadius/aggroRange/wanderSpeedMul/chaseSpeedMul` |
| `orbit` | 绕圈（`orbitRadius/angularSpeed/attackInterval`） |
| `attack_stop` | 前摇后停下重击（`stopDuration/windupTime`） |
| `boss` | 按 `hpRatio` 多阶段切换行为；定时 `skillInterval` 施放 `skillId` 技能 |

- 移动：`speed = getMoveSpeed()*speedMul; step = speed*dt; move = min(step, dist)`。
- 攻击距离：`distance <= getAttackRange() × attackRangeMul(默认1)`。
- **Boss AI 施法坑**：`BossAI.tryCastSkill` 用 **字符串** `skillId`（如 `"fireball"`）去调 `CastAbility(id:number)`，而 `CastAbility` 按**数字** `getCfgById` 匹配 → **永远打不中（潜在 bug）**。

## 7. 技能 / 能力系统（`abilities.json` — 🟢 LIVE）

> ⚠️ 运行时的「技能」并非 AGENTS.md 说的 `BaseSkill/PassiveSkill/ActiveSkill`（那套**不存在**），而是 `Ability` / `AbilitySystem` / `EffectExecutor` / `Modifier` 这套 Dota2 风格系统。

### 7.1 Ability 结构
- 行为 `behavior`：`passive | attack | no_target | unit_target | point | aoe | toggle`
- 字段：`cooldown(秒)`、`mana_cost`、`cast_range`、`damage_type`、`damage`、`effects[]`、`script_id`、`targeting`、`upgrades_to`、`projectile_prefab`。

### 7.2 施放规则（`Ability.Cast`）
`canCast()` 需满足：非被动/非普攻、不在冷却、`status.canCast()`（未被 **眩晕/妖术/沉默**）、`mana >= mana_cost`。
- 施放扣 `mana_cost`；`cooldownRemaining = cooldown`；发 `OnAbilityCast`。
- 法力恢复：`Entity.Tick` 每秒 `+ManaRegen(max)`，上限 `MaxMana`；初始法力=满。
- ⚠️ 技能消耗的是 **法力（mana）**，不是 `battle_constants.initialEnergy`（energy=体力，属局外元数据）。

### 7.3 自动施放（`heroAI`）
每帧对英雄：先普攻；再遍历 `getCastableSkills()`（仅自动施放型，排除普攻/被动）：不在冷却且 `canCast` → 按技能 `targeting`/`cast_range` 选敌人施放；`no_target` 技能有敌人即可施放。

## 8. Buff / 状态 / Modifier（`modifiers.json` — 🟢 LIVE）

### 8.1 Modifier 系统
一个 Modifier = 挂在实体上的「效果容器」，有：
- **生命周期** `OnCreated → (OnRefresh / OnTick / 事件回调) → OnDestroy`
- **Property** 属性贡献（`value × stackCount`）
- **State** 硬状态（眩晕/无敌等）
- **Event** 事件回调（攻击/受伤/死亡等）

### 8.2 叠加规则（`ModifierStackMode`）
| 模式 | 行为 |
|---|---|
| `none` | 移除旧的，新建（不刷新时长） |
| `refresh` | 只重置剩余时间，不叠加层数 |
| `stack` | 层数+1（上限 `max_stack`，缺省999），刷新时长，属性值 = `entry.value × stackCount` |
| `renew` | 新建**独立**实例，与旧的共存 |

> ⚠️ `element_effects.json` 里的 `stackRule: "intensity"/"exclusive"` 与上述枚举**无关**，且无代码消费。

### 8.3 免疫 & 驱散
- **施加**：目标处于 `Invulnerable` 且 modifier 是 debuff → 不施加。
- **时长**：`def.duration`（秒）；`-1` 永久（不衰减）。
- **驱散**：`Purge(level, debuffsOnly)` 移除 `dispel_level !== None && <= level`；`RemoveByState` 移除施加某状态的。

### 8.4 周期效果（DoT/HoT）
`Tick`：若 `def.tick`，累积 `tickTimer`，每满 `tick.interval` 执行一次：
- `tick.damage` → 走伤害管线（默认魔法）→ 会被目标魔抗/受伤倍率减免
- `tick.heal` → 治疗
- `tick.apply_modifier` → 概率掷出后 `AddModifier`

非永久的 `remainingTime -= dt`，耗尽则移除。

## 11. 商店 / 肉鸽构筑（`ShopSystem` — 🟡 对局未接）

- 商店卖两类：**能力**(`ability`) + **遗物**(`relic`)，从 `skillPool + relicPool` 混合抽取。
- `rollOptions(3)`：Fisher-Yates 洗牌后取前 3（不足则全取）。**无稀有度权重、无价格、无刷新费用** → 选择免费。
- `equip`：
  - 能力：已拥有 → `UpgradeAbility` → `'upgraded'`（重复=升级到 `upgrades_to`）；否则槽位满(`>= maxSlots`) → 失败；否则 `AddAbility` → `'equipped'`。

- `maxSlots` 默认 **3**（`maxSkillSlots:3`）。
- `canEquip`：能力已拥有→有升级目标即可；未拥有→槽未满。遗物→未拥有即可。

## 12. 局内成长（等级 / 经验）

- **局内英雄等级**（`battleStore.level`，局内体系，局终清零）：起始 Lv.1，上限 `battleLevelMax=30`。

  ```
  expToNext(L) = floor(60 × 1.18^(L-1))      // battleExpFormulaBase=60, ratio=1.18
  ```

## 13. 经济（对局内 = 金币 gold）

- **对局货币是金币**（`hero.gold`，投影到 `battleStore.gold`）。energy/体力/钻石/荣誉属**局外元数据**。
- 英雄初始金币 = 单位配置 `def.gold`（赏金猎人 0）。`initialGold:100` 常量**未调用**。
- **击杀奖励**（`grantKillReward`）：
  ```
  goldBase = def.goldReward ?? 1 (enemyDropGoldDefault)
  expBase  = def.expReward  ?? 10 (enemyDropExpDefault)
  scale    = phaseMul × timeMul
  phaseMul = 1 + max(0, stage-1) × 0.15
  timeMul  = 1 + min(elapsed × 0.00067, 0.4)
  gold = round(goldBase × scale); exp = round(expBase × scale)
  rewardType === 'gold_boss' → gold × 10   // rewardBossGoldBonus
  rewardType === 'exp_boss'  → exp  × 10   // rewardBossExpBonus
  ```
  金币→局内 `hero.gold`；经验→局内英雄等级。**不写局外 DataCenter**。
- **偷钱**（Modifier13）：命中偷取目标 `≤20` 金币（上限=目标剩余金币）。
- **击杀回血**（`config.killHeal=6`）：非英雄被英雄击杀 → 英雄恢复 6 生命。
- 对局内金币**没有实际消费入口**（商店被注释；`HeroSelectPanel` 的刷新价 `refreshGold=100` 仅显示，无扣费逻辑）。结算时才发 `clearRewardPlayerExpBase`（×100%胜/×30%负）与 `clearRewardHeroExpBase` 的局外经验。
