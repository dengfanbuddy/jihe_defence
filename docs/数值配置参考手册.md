## 0. 读前须知：哪张表是"活的"

当前**战斗运行时唯一权威数据源** = `assets/resources/tb/` 下由 `TbRoot` 管线加载的 JSON（入口 `Main.ts → TbRoot.ins.loadTbs()`，查询走 `BattleContext` / 各 `Tb_*Config` 容器）。

| tb 文件 | 容器 / 解码器 | 当前消费方 | 状态 |
|---|---|---|---|
| `attributes.json` | `Tb_AttributeConfig` | `AttributeSystem`（属性字典） | ✅ 权威 |
| `units.json` | `Tb_UnitConfig` | `BattleContext.getUnitDef`（英雄+怪物实体） | ✅ 权威（英雄与怪物的家） |
| `modifiers.json` | `Tb_ModifierConfig` | `ModifierSystem`（Buff/DoT/事件效果） | ✅ 权威 |
| `abilities.json` | `Tb_AbilityConfig` | `AbilitySystem`（技能） | ✅ 权威 |
| `relics.json` | `Tb_RelicConfig` | 遗物系统 / 肉鸽商店 / 局外收集 | ✅ 权威（**一件遗物一行**：身份列共用，`modifiers_inner` / `modifiers_outer` 分两侧，`scope` = inner/outer/both） |
| `battle_constants.json` | `Tb_BattleConstConfig` | `BattleConstUtil`（全局常量/公式参数） | ✅ 权威 |
| `shop_constants.json` / `shop_draw.json` / `shop_skills.json` / `kill_buffs.json` | `Tb_ShopConstConfig` / `Tb_ShopDrawConfig` / `Tb_ShopSkillConfig` / `Tb_KillBuffConfig` | 肉鸽商店（规则常量/抽取概率/额外技能/击杀 Buff） | ✅ 权威 |

> 以上 **10 张表**即 `assets/resources/tb/` 的**全部**现有 JSON。
> 曾存在但**已删除**：`equipments.json`（2026-07 并入 `relics.json`，先落成 `scope=outer` 段、再改造成「一件遗物一行」的局外版）、
> `growth_curves.json`、`enemies.json`、`phases.json`、`passive_combos.json`、`element_effects.json`、`shop_items.json`（连同其容器一并移除，代码无残留引用）。

> **经验法则：加一个英雄/怪物/技能/遗物（局内道具或局外装备）主要改 `units.json` / `abilities.json` / `relics.json`；加属性条目改 `attributes.json`；加全局参数改 `battle_constants.json`。旧表已删除，无需再回避。**

## 1. 属性字典（16 个属性，编号即 `AttributeType`）

| ID | 名称 | 语义 | 叠加方式 | 属性字典 base/min/max | 是否百分比型（配置 ×100） |
|---|---|---|---|---|---|
| 1 | 最大生命 | 血量上限 | add | 100 / 1 / 99999 | 否 |
| 2 | 最大魔法 | 蓝量上限 | add | 50 / 0 / 9999 | 否 |
| 3 | 攻击力 | 单次伤害基数 | add | 10 / 0 / 9999 | 否 |
| 4 | 攻击速度 | 攻速倍率（运行时 float） | multiply | 100 / 10 / 1000 | ✅（100 = 100%） |
| 5 | 移动速度 | 像素/秒 | add | 300 / 50 / 1000 | 否 |
| 6 | 护甲 | 物理减伤输入 | add | 0 / -20 / 100 | 否 |
| 7 | 魔法抗性 | 魔法减伤（补数乘法） | complement | 25 / 0 / 95 | ✅（25 = 25%） |
| 8 | 闪避 | 补数乘法 | complement | 0 / 0 / 95 | ✅（20 = 20%） |
| 9 | 生命恢复/秒 | 续航 | add | 0 / 0 / 999 | 否 |
| 10 | 魔法恢复/秒 | 续航 | add | 0 / 0 / 999 | 否 |
| 11 | 伤害输出倍率 | 攻击者增伤 | multiply | 100 / 0 / 1000 | ✅（150 = 150%） |
| 12 | 物理受伤倍率 | 目标受伤增减 | multiply | 100 / 0 / 1000 | ✅ |
| 13 | 魔法受伤倍率 | 目标受伤增减 | multiply | 100 / 0 / 1000 | ✅ |
| 14 | 暴击率 | 概率 | add | 0 / 0 / 100 | ✅（30 = 30%） |
| 15 | 暴击倍率 | 爆伤 | best | 100 / 100 / 1000 | ✅（150 = 150%） |
| 16 | 攻击距离 | 攻击射程（像素级，见 §2 注） | add | 100 / 50 / 2000 | 否 |

### 1.1 关键口径（写错必炸）

- **配置表里百分比型属性写成 int（100 = 100%）**：攻速 `100`=1.0、魔抗 `25`=25%。代码经 `AttributeScaling.normalize` 在写入时 ÷100 变 float，运行消费浮点语义（`battle/core/AttributeScaling.ts`）。
- **`units.json` 的 `base_attributes`**：二维数组 `[[属性编号, 配置int值], ...]`，走上面的 int 口径。
- **`units.json` 的 `growthValues`**（英雄每级成长）：二维数组，**直接写运行时 float 语义**（如暴击 `0.005` = 0.5%/级、护甲 `0.5` = 每级 +0.5、生命 `25` = 每级 +25；**攻速已全局禁止随等级成长，见 §4.3 铁律**）。代码 `applyHeroGrowth` 内部会按 `scale × 值` 转 int 再入库 —— **别在这里写成 ×100 的 int！**
- `attack_interval`：普攻基础间隔（秒），实际冷却 = `attack_interval / atkSpeed`（`Entity.getAttackInterval`）。
- 距离/速度量纲：移动速度≈像素/秒（现怪 100~260、英雄 200~320），攻击距离 `attr16` 与弹道距离按像素理解（现英雄 100~500、技能 `cast_range` 500~600、刷怪半径 650~800）。**单位换算前先对着该字段在代码里的用法确认一次**（AttributeScaling 未缩放它就是原样 int）。

## 2. 关键战斗公式（数值的数学地基）

全部以代码为准（`battle/DamagePipeline.ts`、`battle/Entity.ts`、`Scene_Game_Stage.ts`）：

```
普攻间隔(秒)  = attack_interval / atkSpeed(运行时 float)
单发普攻DPS   = 攻击力 / 普攻间隔
伤害期望      = 单发伤害 × (1 + 暴率 × (暴伤 - 1))      // 含暴击后每次攻击的数学期望
物理减免系数  = 1 - 0.06 × armor / (1 + 0.06 × |armor|)   // ⚠️ Dota 公式，见下
魔法减免      = 1 - magicResist                            // 补数乘法叠加后取(1 - r)
目标最终伤害  = raw × 攻击者增伤 × 暴击 × (1/受伤减免) × 物理或魔法减免系数
击杀奖励      = base(goldReward/expReward) × 阶段难度系数 × 时间通胀系数
```

> ⚠️ **护甲公式陷阱**：`battle_constants.json` 里的 `defenseFormula: "def/(def+100)"` 是一段**没被 DamagePipeline 使用的字符串**。代码实际用 Dota 双曲公式 `0.06·a/(1+0.06·|a|)`（100 甲 ≈ 减伤 86%、50 甲 ≈ 减伤 75%——比 def/(def+100) 的 33% 猛得多）。配置护甲前务必先统一公式口径（要么改代码，要么只按代码公式回填期望减伤）。

常用减伤速查（按 Dota 公式 0.06）：5 甲≈23%、10 甲≈37%、20 甲≈55%、35 甲≈68%。

全局上限（`battle_constants.json`，消费于各处/文档设计口径）：暴率 ≤60%、闪避 ≤40%、攻速 ≤3.0、射程上限 15、护甲减伤建议 ≤70%。

## 3. 数值设计方法论速览（没有数值经验也能照做）

完整出处见调研报告；这里给可直接抄的锚点与五步法。

### 3.1 黄金锚点表

| 锚点 | 常见取值 | 说明 |
|---|---|---|
| 普通怪击杀时间 TTK | 0.5~3 秒 | 手感核心输入 |
| 关底/独立 Boss 战时长 | 10~30 秒（收官 30~60s） | Boss HP = 玩家满配 DPS × 秒数 |
| 怪打死英雄所需命中 | 普通怪 3~8 下 | 英雄被小怪淹没前有反应窗口 |
| 攻击 : 生命 换算锚 | **1 DPS ≈ 10 HP** | 装备/天赋/成长预算的汇率 |
| 1% 暴率 ≈ 2% 暴伤 | 定价汇率 | 同战力等价 |
| 每级经验需求底数 | ×1.10~1.20/级 | 指数或分段等效 |
| 装备品质每档 | 白值 +20~40%，顶级≈底档 2~2.5× | 本游戏 4 档 ×1.0/1.3/1.6/2.0 合格（见 `docs/配置规则_品质与词条门禁.md` §1） |
| 难度指数底数 | 1.05~1.15 | HP/伤害分开给 |
| 局外养成总膨胀 | **≤ +50% 永久乘区** | 防局外撑爆局内 |
| 减伤公式 | DR = D/(D+k)，k≈100 | 本项目代码用 Dota 公式（见 §2 警告） |

### 3.2 五步配数法

```
① 定手感：确定该英雄/该波怪的目标 TTK、英雄被击中几次死亡。
② 定锚：从「1DPS≈10HP」出发确定基础攻击与生命数量级。
③ 拆乘区：把输出预算拆成 攻击力、攻速、暴击率、暴击伤害 的组合（战力等价互算）。
④ 验生存：EHP = HP/(1-减伤)，闪避折算减伤，生命回复折算等效 HP。
⑤ 封口：配消耗（金币/经验/局外资源）、封顶（暴率60%/闪避40%/攻速3.0/总膨胀≤2倍）。
```

详细换算表、行业区间、案例校验见 `docs/数值设计调研报告_肉鸽塔防.md`。

## 3.3 三模式与局外成长框架（先读这一节）

> 2026 确认的模式定义。所有英雄/装备/怪物/经济的数值目标，都要先在下面三模式里选一个基准，再往下套 §4~§9。

### 3.3.1 三种游戏模式

| 模式 | 玩法 | 数值目标 | 局内等级 |
|---|---|---|---|
| **难度模式** | 难度 1~100（上限可再扩），每 5 难度换一个**不同关底最终 Boss**；前 3 难度偏简单，玩家首日可勉强通过 | 每难度是"关卡"，难度曲线决定关卡强度；难度推进 ≈ 局外成长推进 | **无上限**（默认设计目标；代码现状 battleLevelMax=30 需放开或按模式走参数） |
| **无尽模式** | 先选难度作为基础，局内无阶段限制，持续刷怪直到英雄死亡 | 怪物强度随时间/波次持续增长（曲线见下），挑战"能活多久/拿多少局内资源" | 无上限 |
| **Boss 模式** | 选英雄 → 自选/挑战 Boss → 掉 Boss 碎片 → 集齐合成该 Boss → 永久收集属性 | Boss 是"可重复挑战的副本 BOSS"（与难度模式关底 Boss **两套独立 Boss 池**） | 无上限 |

**玩家进度流（难度模式）**：局外成长（每个英雄独立成长 + 局外公共装备 + 成就 + Boss 收集等）→ 每天小步变强 → 匀速 **3~4 天过 1 难度** → 看广告可额外加速。核心乐趣 = 英雄成长 + 局内肉鸽构筑（每局不同的技能/遗物/装备搭配）的互相成就。

### 3.3.2 局外成长来源与预算（重要：将来还会加系统）

局外加成统一走 `OuterAttributeCalculator`（`final = base×(1+Σpercent) + Σflat`，按 feature 分组可叠加）。**当前代码现状**：
- ✅ 数据层/配置已建：`EquipmentCollectionModule` + `relics.json`（有局外版的遗物 = `modifiers_outer`）+ `EquipmentConfig.getAllEquipmentBonuses()` → 图鉴式收集（重复收集属性累加）。
- ⚠️ **尚未接线**：`OuterAttributeCalculator` 目前没有调用方把它应用到战斗实体（无 `applyOuterBonuses`/`getFinalAttributes` 的运行时消费点），属"框架已备、待接入"。
- ⚠️ `HeroData`（英雄独立等级/经验）与 `PlayerInfo`（玩家等级）已建数据模块与经验曲线，但**局外等级暂未回乘属性**。

**局外成长分层建议（设计层，供未来系统扩展）**：每一层都是一个 feature 组注册进 `OuterAttributeCalculator`：

| 层 | 建议 | 预算上限参考（占总战力增幅） |
|---|---|---|
| 英雄独立成长（等级/星级） | 每英雄自己的永久小乘区 | ≤ +15~25%（单英雄） |
| 局外公共装备（图鉴收集） | 跨英雄共享，随收集增长 | ≤ +15%（总量），单件 ≤ 品质档位 |
| 成就加成 | 全局小奖励 | ≤ +5~10% |
| Boss 收集（合成后永久属性） | 见 §3.3.4 | ≤ +5~10% |
| 广告/活动加速 | 一次性/限时 | 不入永久池，单独乘区 |
| 未来新增系统 | 继续追加 feature 组 | **全部永久层合计 ≤ +50%**（行业防膨胀上限） |

> 设计铁律：**永久局外总和封顶 +50% 乘区**，新系统只允许在总预算里切份额，不允许无限叠加。局内临时（技能/遗物/局内等级）不算入此池。

### 3.3.3 局内等级：默认不限级

- 目标：**所有模式局内等级无上限**（经验曲线用 `battleExpFormulaBase/Ratio`，当前 60/1.18 可继续用；升级所需逐级指数上升即天然"越升越慢"，无需硬上限）。
- ⚠️ 代码现状：`battle_constants.battleLevelMax = 30` + `Scene_Game_Stage.addBattleExp` 的 `while(st.level < maxLevel)` 会卡 30 级——**若做无尽/Boss 长局需放开**：要么删 maxLevel，要么加"难度模式 30、无尽/Boss 不限"的按模式参数。
- 升级属性成长照旧走 `units.json.growthValues`（float/级，线性）；怪物强度曲线若也线性，玩家永远不死——所以**无尽模式的怪必须按时间/波次超线性增长**（见下）。

### 3.3.4 难度曲线、无尽曲线、Boss 收集设计速查

**难度曲线（难度模式，1~100+）**
```
基准：难度 1 ≈ 玩家"初始局外 + 基础构筑"可过（首日目标，TTK 0.5~2s）
难度 N 怪物 HP    ≈ 基准 × (1 + dHp)^(N-1)，dHp 建议 0.08~0.15
难度 N 怪物伤害  ≈ 基准 × (1 + dAtk)^(N-1)，dAtk < dHp（如 0.06~0.10）
每 5 难度：切换关底最终 Boss（Boss HP 用"满配 DPS × 10~30s"反推）
难度间隔(3~4天)：每难度要求的玩家净战力增幅 ≈ 玩家 3~4 天能积累的局外成长
```
- 参照 §2/§4.2 先用 DPS/TTK 在难度 1 打底，再按公式外推 1~100 全表（建议做 Excel 表：难度 | HP倍 | 伤害倍 | 关底Boss | 要求局外净成长）。
- 局外成长与难度要双向校准：**若"每天局外净成长 2%，而难度 dHp=1.15"则永远追不上**——先定"3~4 天/难度"体验节奏，反推每日投放，再反推 dHp/dAtk。

**无尽曲线（无尽模式）**
```
怪物强度随"局内经过时间/波次"增长：HP/伤害 ×= 每 60~120s 乘 1+ (如 每波×1.03~1.08)
玩家局内成长 ≈ 线性(等级 growthValues) + 肉鸽构筑(技能/遗物乘区) → 曲线低于怪
目标：普通玩家约 15~40 分钟自然死亡；"极限波数"成为排行榜/成就锚
建议单独一张"时间/波次 → 强度倍率"表（可复用难度倍率但改为每波增长）
```
- 无尽模式的局内金币/经验收益：建议随时间通胀系数继续，但要**设局内收益 cap** 防单局刷爆局外（见 §7）。

**Boss 模式（独立 Boss 池 + 碎片合成收集）**
```
Boss 池与难度关底分开设计（用户确认两套独立）。
Boss 强度分档（如 Ⅰ~Ⅴ 或按"推荐局外战力/难度"标注），Boss HP = 该档满配 DPS × 10~30s。
碎片掉落：挑战成功掉 1~3 片，收集 N 片合成一个 Boss → 解锁其"属性收集"（进局外预算池，≤+5~10%）。
奖励循环：掉落碎片 + 局外货币/经验；可加"每日首胜额外碎片/扫荡"。
```

### 3.3.5 三种模式 × 局内经济复用

局内规则（金币→肉鸽抽卡、经验→升级、击杀→商店/技能）三模式共用一套；区别只在：难度模式**有终点**（通关=该难度胜利）、无尽模式**无终点**（持续到死，收益逐步衰减封顶）、Boss 模式是**短对局打单目标**（可弱化小怪经济、放大 Boss 掉落）。

## 4. 局外英雄基础属性 + 成长配置

英雄实体定义在 **`units.json`（team=1 的条目）**。**id 分段规则**：英雄 = 1000 段（现役 1001 火枪 / 1002 赏金猎人 / 1003 宙斯 / 1004 斧王，`Scene_Game_Stage.defaultConfig.heroUnitId=1002`）；怪物 = 2000 段（2001 起）。条目带分类字段：`category`（hero / monster）+ 怪物 `subtype`（normal 普通 / elite 精英 / boss Boss·经济Boss），与 `team`、`rewardType` 并存（team 管阵营、rewardType 管奖励与 Boss 加成）。

### 4.1 英雄条目字段（`UnitCfg`）

| 字段 | 含义 | 必填 |
|---|---|---|
| `id` / `name` | 编号 / 显示名 | ✅ |
| `team` | 1 = 我方英雄 | ✅ |
| `base_attributes` | 初始属性：`[[属性编号, int值],...]`（百分比属性 ×100）。**英雄只允许 5 项：最大生命(1) / 最大魔法(2) / 攻击力(3) / 攻击速度(4) / 攻击距离(16)** | ✅ |
| `attack_interval` | 普攻基础间隔秒 | 建议 |
| `growthValues` | 每级成长：`[[属性编号, float值],...]`（成长用 float 语义！）。**英雄只允许 3 项：最大生命(1) / 最大魔法(2) / 攻击力(3)** | 英雄建议 |
| `abilities` | 技能 id 列表（`abilities.json` 的 id） | ✅ |
| `attack_projectile*` / `prefab` | 弹道/预制件 | 表现层 |

> **射程的可视上限（本次踩过的坑）**：设计分辨率 750×1334 + `fitWidth`，屏幕**横向半宽只有 375px**（英雄在中心，范围圈 `hero/range` 由 `Scene_Game_Stage.syncHeroRangeCircle` 按 attr16 实时绘制）。

### 4.4 攻速铁律（2026-06 定案，仍然有效）

**全局铁律——攻速不进任何成长 / 局外加成**：
- `growthValues` 一律**不写攻速行**（现役 1001~1004 均无）。攻速 = Lv.1 基础值（如火枪/赏金 `120` = 1.2 次/秒、斧王/宙斯 `100` = 1.0）后**全局长不变**。
- 攻速只能来自**局内**：遗物 / 局内道具 / 临时 Buff（同类相加，总攻速 ≤ cap 3.0）。
- **局外永久加成（装备收集 / 成就 / Boss 收集 / 未来新系统）一律不许给攻速**。攻速是"局内构筑杠杆"：让攻速流（如火枪：攻速 = 鹰眼叠层速度）靠局内决策成长，同时防无尽/高难度无限等级把攻速顶爆上限、防局外强度稀释构筑。
- ⚠ **当前数据有 9 件局外装备给了攻速**（赏金面罩/敏捷手套/狂战斧/蝴蝶/强袭胸甲/金箍棒/斯嘉蒂之眼/贤者之石/海盗帽），
  与 2026-07 的「百分比属性从黄档起」口径冲突（那条允许黄档装备给攻速）。**尚未定案**：要么删这 9 条、要么废止本铁律。
  现状由 `npm run check:affix` 作为**警告**列出（不判失败），清单见 `docs/配置规则_品质与词条门禁.md` §8。

**成长自检（区分局内/局外，别混为一谈）**：
- **局内成长（growthValues）允许较大膨胀**：线性固定值叠加 30 级后攻击累计 2~5× 都属肉鸽常态（如现役火枪 40→Lv.30 127≈3.2×、宙斯 26→≈99≈3.8× 可行）。它的合理性不由"倍数"判定，而由 **目标模式的怪 HP 曲线（难度 N / 无尽时间轴）÷ 该基准下玩家输出曲线 → TTK 是否稳定在 0.5~3s** 判定。
- **暴率**：成长 + 装备给的总绝对点数需给抽卡/词缀留空间，最终不超 cap 60%（现在英雄基础暴率为 0，全部要靠遗物/装备）。
- **局外永久养成**（未来把局外等级做成乘区时）：总量才建议 ≤ +50%，防止永久膨胀撑爆局内（见 §4.5）。

### 4.5 局外英雄等级（`HeroData`）

- 局外 `HeroData.heroes[id].level/exp` 目前**只记录**局外经验升级（`battle_constants.heroExpFormulaBase/Ratio` 决定曲线），暂未把局外等级反向乘到战斗属性（战斗成长 = 局内等级走 `growthValues`）。
- 若未来把局外等级做成战力乘区：**永久加成总量封顶 +50%**（调研报告建议），并按难度递增「每难度需局外净成长 +X%」来同步吸收，避免局外撑爆。

## 5. 局外遗物系统配置（relics.json 里有局外版的遗物）

**2026-07 变更（两步）**：
① 局外装备表 `equipments.json` 并入 `relics.json`；
② `relics` 表改成「**一件遗物一行**」—— 局内版与局外版是同一件遗物，共用 `id` / `name` / `code` / `icon` / `rarity` / `category`，
只有**效果与描述分两侧**（`modifiers_inner` / `description_inner` 与 `modifiers_outer` / `description_outer`），
`scope` 说明这件遗物在哪几侧出现（`inner` 只有局内版 / `outer` 只有局外版 / `both` 两侧都有）。
字段、id 段与商店池过滤口径见 `docs/配置规则_品质与词条门禁.md` §1.1。

**系统现状**：局内掉落/收集 → `EquipmentCollection` 记录次数（存的是**遗物 id**，与局内共用一套）→
`EquipmentConfig.getAllEquipmentBonuses()` 按 收集次数 × 单件加成 汇总 → `OuterAttributeCalculator` 计算
`final = base × (1 + percent) + flat`。（⚠ 该链路**尚未接线**：没有运行时消费点，见 §3.3.2。）

### 5.1 遗物条目的两侧字段（写局外版 = 写 `*_outer`）

| 字段 | 含义 | 说明 |
|---|---|---|
| `id` / `name` / `icon` / `rarity` | 身份列（**两侧共用**） | 有局外版的遗物用**局内 id**（1001~1293）；只有局外版的是 **1294~1302**；品质 4 档，两侧同一个档 |
| `scope` | 这件遗物**在哪几侧出现** | `inner` / `outer` / `both`；必填，且必须与两侧的 `description_*` / `modifiers_*` 对得上 |
| `description_inner` | **局内版**效果描述 | 进肉鸽商店的那一版（商店卡片显示的就是它） |
| `modifiers_inner[].kv.attrs` | **局内版**属性加成 `[[属性id, 值, 叠加方式]]` | 口径同下表；局内允许多给百分比（**黄档起**） |
| `description_outer` | **局外版**效果描述 | 局外收集/图鉴显示的那一版 |
| `modifiers_outer[].kv.attrs` | **局外版**属性加成 | **统一 int 口径**（百分比型属性 ×100：`dodge 0.08` → `[8, 8, "add"]`）；`add` = 固定值 / `percent` = 对基础属性的百分比（**黄档起**） |
| `code` | 唯一英文代码（程序引用用） | **英雄专属装备已删除**（`code=spc_*` 与 `hero_id` 列都不再存在） |
| `category` | 局外分类 | `d2_basic` / `d2_upgrade` / `d2_neutral` |
| `allPercent`（旧列，已展开） | 全属性百分比加成 | 合并时只对**数值属性**展开成 `percent` 条目（百分比型属性基础值为 0，percent 无效），旧列已废弃 |

**加成分层**：`flat`（固定值，加在 base 上、不被百分比放大）与 `percent`（乘在 base 上）。局外公式 `final = base×(1+Σpercent) + Σflat`。

**分层口径（v3，2026-07）**：`add` → `flat`（运行时 float：`[8, 8, "add"]` → `+0.08` 闪避）；
`percent` → percent 层且需**黄档起**（低档会被降级为 flat 并 warn），按「品质 × 词条」门禁，而不是"品质高就全都乘算"。
⚠ 旧装备表（v2）是「`quality ≥ 2.5` → 该件**所有**属性都进 percent 层」，于是 `atk: 30` 被当成 3000% 的乘区 —— 合并进 relics 后每条属性都自带叠加方式，该坑已消失。

### 5.2 品质定价参考（4 档，局内局外同一阶梯）

| 品质档 | `rarity` | 白值预算 | 可给的特殊效果 |
|---|---|---|---|
| 白（普通） | `common` | 基准 1.0× | 只有数值属性的**固定值** |
| 蓝（稀有） | `rare` | ≈×1.3 | 可加**功能性固定值**（如击杀金币 +2） |
| 黄（史诗） | `epic` | ≈×1.6 | 可给**百分比加成**与**百分比型属性**（局外攻速见 §4.4 铁律） |
| 红（传说） | `legendary` | ≈×2.0 | 可给**功能性百分比**（如金币获取 +13%），最高品质专属 |

> **"多少不同"的量化基准**：低档给固定值时的折算锚点（100% 对应多少白值）见
> `docs/配置规则_品质与词条门禁.md` §6（攻击 60 / 生命 500 / 护甲 10 / 回血 2 / 射程 300 / 移速 300）。
>
> 高品质「特殊效果」当前 schema 没有独立字段 —— 两种落地方式：
> ① 用 `modifiers` 的 `effects`/`events`（如灼烧/吸血/反弹/偷钱，见 §8.2）；
> ② 复杂逻辑走 `script_id`（逃逸口）。
> 无论哪种，机制型效果按「等效增伤% × 0.7~0.9 风险折扣」定价（见调研报告 §3），单条别超过品质主倍率。
>
> 门禁自检：`cd tools/excel_export && npm run check:affix`（违规即退出码 1）。

> 三种模式共用同一套怪物条目（units.json team=2），强度增长方式不同：

## 8. 技能 / 能力数值（abilities.json + modifiers.json）

### 8.1 ability 字段

`behavior`（unit_target/aoe/no_target/passive/attack）、`cooldown`、`mana_cost`、`cast_range`、`damage_type`、`targeting`、`effects[]`（damage/heal/aoe_damage/apply_modifier/projectile/steal_gold/execute_script）、`upgrades_to`（升级链）。

### 8.2 modifier 字段

生命周期：`duration`、`stack_mode`（refresh/stack/renew/none）、`max_stack`、`strongest_only`、`dispel_level`、`cd`（该效果自己的冷却）。

**时长口径（只有 `-1` 表示永久）**：`modifiers.json` 的 `duration` 必填，`-1` = 永久（不衰减）、正数 = 秒。
引用方（`relics.modifiers_*[].duration`、`abilities.effects[].duration`、`apply_modifier.duration`）**留空即 `null`**（Excel 空单元格导出成 `null`），
语义是**「没写」而不是 0 秒** —— 一律回落定义值（遗物走「默认永久」，见下），绝不能把 `null` 当成显式时长
（踩过：`remainingTime = null` → 首帧 `null - dt` 为负数 → 效果一帧后就被移除，表现为"遗物加的属性过一会儿又变回去了"）。
遗物效果**默认永久**（`BattleEquip.Apply` 里 `entry.duration ?? -1`）：遗物是一次性获得、整局生效的被动，
不回落效果模板自带的时长（模板是给技能/临时 Buff 用的，如 mod 11「吸血」= 5 秒）；要限时的遗物在表格里写正数。

**两处「配了也不生效」的静默陷阱（2026-09 补，门禁已拦）**：
- **`percent` 打在基础值为 0 的属性上恒为 0**：护甲(6) / 生命恢复(9) / 魔法恢复(10) 的 `attributes.json.base` 都是 0
  （英雄收口后不再配这三项）→ `0 × (1+Σv/100) = 0`。一律用 `add` 给固定值（基准见品质门禁 §6）；
  规则真源 `affix-rules.mjs` 的 `ZERO_BASE_ATTRS`，`npm run check:affix` 报错、`npm run migrate:affix` 自动折算。
- **暴击倍率 base 必须是 150**：`DamagePipeline.rollCrit` 要求 `倍率 > 1` 才可能暴击，base=100 → 1.0 → **全项目永不暴击**；
  且暴击倍率词条要显式写叠加方式 `best`（条目 mode 覆盖属性默认 mode，写 `add` 会变成 `base + Σv` 累加）。
  合同见品质门禁 §2.2，修复脚本 `npm run fix:crit`。

**改完属性相关配置后跑一次属性体检**：`npm run audit:attr`（`tools/attr-audit/`）——
它把真源码 + 真配表跑一遍，逐属性打印「买一件给该属性的遗物 → 运行时值 前⇒后」，**「加了却没变」即退出码 1**。

**效果一律写在 `effects[]`（原子效果，一条一件事）**：

| type | 参数 | 说明 |
|---|---|---|
| `modify_attr` | `attrs: [[属性id, 值, 叠加方式], …]` 或 `attrs_var` | 属性贡献；`叠加方式` 缺省 `add`，百分比用 `percent`（见 §铁律）；`attrs_var` = 整表由施加方 kv 传入（共享模板用） |
| `apply_state` | `state`、`value?` | 无敌/眩晕等硬状态（见 `StateType`） |
| `tick_damage` | `interval`、`value`、`damage_type?` | DoT，每条自带计时器 |
| `tick_heal` | `interval`、`value` | HoT |
| `tick_apply_modifier` | `interval`、`modifier`、`duration?`、`chance?` | 周期施加别的 Modifier |

触发式：`events`（on_attack_landed/on_take_damage… + 动作 reflect/lifesteal/steal_gold/apply_modifier）。
条目里的 `var`（`{"attr":5,"value":-90,"var":"slow"}`）= 该数值由施加时 `kv.slow` 覆盖。
**纯属性加成不要新增 Modifier**：全项目共用「属性修改」共享模板（id = `MODIFY_ATTR_TEMPLATE_ID` = 1000），
道具的属性与数值写在 `relics.modifiers[].kv.attrs` 里。

### 8.3 技能数值预算速查（把"技能"折成 DPS）

```
技能每次期望伤害(单体) = Σ effects 直伤 + DoT(每秒伤害×持续) 
技能总 DPS 贡献      = 期望伤害 / (冷却 + 前摇估算)（受蓝量约束时再乘施放率）
建议：普攻 DPS 与技能 DPS 总和 = 设计目标 DPS；
      主动大技能占单发预算的 1.5~3×普攻单发（用冷却对冲）；
      DoT/控制技能按覆盖率折扣（例如 20% 触发率 → 价值 ×0.2~0.4 再报价）。
蓝耗建议 = 冷却(秒) × 10~20（配合魔法恢复看续航）。
```

## 9. 常见坑与配表自检清单

**坑**：
1. growthValues 写 int 而 base_attributes 又写 ×100 —— 两处语义不同（§1.1）。
2. 护甲按 `def/(def+100)` 脑算，代码实际是 Dota 公式（§2 警告）。
3. 擅自新增 JSON 配表而没有容器注册/消费代码 —— 不会被 TbRoot 读到（加新表须同步建 `Tb_*Config` 容器并 `@tb_config` 注册；旧表已删，别再引用）。
4. 百分比属性写 0.5 而非 50。
5. 伤害与 HP 不按汇率锚定（§3.1），导致后期怪一下秒/打不动。
6. **英雄条目又配了护甲/魔抗/闪避/暴击/回血/移速** —— 英雄只允许 5 项基础属性 + 3 项成长（§4.2/§4.3），
   多写的会被 `npm run check:affix` 判失败，且运行时并不消费（回落 `attributes.json.base`）。
7. **低品质给了百分比词条** —— 白/蓝档只能给固定值（`docs/配置规则_品质与词条门禁.md` §0）。
8. **百分比型属性用 `percent` 写**（闪避百分比 / 暴击率百分比）—— base 为 0 时恒为 0，必须用 `add`（百分点）。

**自检清单**：
- [ ] 配置前先确认目标模式（难度 N / 无尽基准难度 / Boss 档位）与局外成长预算（见 §3.3）
- [ ] 每档怪 TTK：普通怪在对应难度/模式英雄 DPS 下 0.5~3s 击杀
- [ ] 英雄 EHP：被同档普通怪 3~8 次命中才死
- [ ] 1DPS≈10HP 汇率在英雄基础、装备、成长间一致
- [ ] 难度曲线 dHp/dAtk 与"3~4 天/难度"的局外净成长匹配（§3.3.4）
- [ ] 百分比属性全部 ×100、成长 float 语义正确
- [ ] 全部数值在 attributes 字典 min/max 与战斗 cap 内（暴率≤60 等）
- [ ] 新增 unit/ability/modifier JSON 能被 `JSON.parse`，字段名与容器接口一致
- [ ] 局外永久加成总量 ≤ +50%（含装备/英雄/Boss 收集/未来系统各层之和）
- [ ] 经济：单局收入可覆盖目标抽取次数；局外税类消耗 ≥85%；无尽模式局内收益有 cap
- [ ] **门禁自检跑过**：`cd tools/excel_export && npm run check:affix`（错误必须为 0）

## 10. 一键工作流（给 AI / 新手策划的 SOP）

```
① 先定位：目标模式（难度 N / 无尽基准难度 / Boss 档位）+ 局外成长预算层（§3.3）
② 拿到英雄/怪物/装备/技能的文字设定（定位、节奏、特色机制）
③ 按 §3.2 五步定锚：TTK → 1DPS≈10HP → 拆乘区 → 验生存 → 封口
④ 填 §4/§5/§6/§7/§8 对应模板表（数值落在该模式该难度基准上）
⑤ 转成目标 tb JSON（遵守 §1.1 口径与 §0 权威表）
⑥ 跑 §9 自检清单（含模式×难度×局外预算匹配项），改动尽量一栏一改、逐项验证
```
