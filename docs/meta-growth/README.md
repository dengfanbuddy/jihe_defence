# 局外成长与兑换规则 · 遗物抽取 + 账号等级加成 + 局内广告券

> **本文是规则的口径真源**（2026-11 规则修改定案）。代码**尚未落地** —— §6 是施工清单，§7 是验收清单。
>
> 这次改了三条**互相咬合**的规则：
> ① **局外遗物不再来自"打完一局"，改为局外花金币抽取**（顺手切断"局内抽到 → 写局外图鉴"那条泄露）；
> ② **账号等级对局内加成**（每级 金币获取 +1% / 局内经验 +1%，里程碑给开局金币等）；
> ③ **局内广告券**（局外看广告攒券 → 局内**免广告**抽卡 / 取遗物，见 §3）。
>
> ⚠ ①**推翻**了 `docs/gdd_reward/tabs/settle.html` 的两条既有定案：**「结算产出 = 英雄经验 + 遗物」**与
> **「局外遗物按 数量→品质→id 三段概率抽」**。好消息是那两条**都还没写进代码**（`endRun()` 现在只发英雄经验），
> 所以是**纯纸面推翻**；而"结算发遗物"的三段概率表里，**品质权重那一层被本次复用**（见 §1.2）。

## 0. 一句话：三条规则的账

```
一局打完（通关）         →  只发【通用英雄经验】（80 × 难度收益倍率，已实现）
                          ⛔ 不发遗物（旧定案作废）
局内肉鸽商店抽到的遗物    →  只在本局生效（⛔ 不再写局外图鉴 —— 这条**是现在代码里就有的漏洞**，见 §0.2）
局外【遗物】页花金币抽取  →  局外遗物**唯一来源** → 永久属性（`EquipmentCollection` → `OuterAttributeCalculator`）
账号等级涨               →  每级 +1% 击杀金币 / +1% 局内经验；Lv10/20/30 给开局金币
局外看广告攒【局内广告券】→  局内**免看广告**抽卡 / 补选遗物（§3；券**不增加**局内次数上限）
```

### 0.2 那条必须一起堵的漏洞（**先做这个**）

`RelicShop.grantRelic` 现在会回调 `Scene_Game_Stage.onRelicCollected`，它**无条件**把遗物写进局外图鉴：

```ts
// Scene_Game_Stage.ts:1516 附近
private onRelicCollected(relicId: number): void {
    DataCenter.ins.equipCollection.addCollected(relicId);   // ← 要删的就是这一行
}
```

而局内可出池 = **268 件**（`scope` 含 `inner` 的 240 件 + 28 件两侧都有），**抽后不放回** ——
一局打满能抽 200+ 次，那 28 件"两侧都有"的**必然全部到手一遍**。
`EquipmentCollection` 记的是**份数**，而 `getAllEquipmentBonuses()` 是**按份数线性累加**的
⇒ **打两局，局外属性就翻倍**。

今天看不出来，只因**局外属性还没接进战斗**（`OuterAttributeCalculator` 没有运行时消费点）。
一旦"局外遗物"变成真正的成长线（本次就是），这条漏洞会立刻显形。
**结论：局外遗物只有"金币抽取"一个来源**，局内那条接线删掉。

## 1. 局外遗物抽取（花金币）

### 1.1 池子 = 37 件（`scope` 含 `outer`）

| 品质 | 配置值 | 颜色 | 局外池件数 | 概率（权重） |
|---|---|---|---|---|
| 白 | `common` | `#DDDDDD` | **12** | **60%**（6） |
| 蓝 | `rare` | `#5096FF` | **8** | **25%**（2.5） |
| 紫 | `epic` | `#CF68FF` | **11** | **10%**（1） |
| 红 | `legendary` | `#FF6464` | **6** | **5%**（0.5） |

- 池子**只含这 37 件**：另外 240 件只有局内版（`scope='inner'`），抽出来没有局外属性，**不进池**。
- ⚠ 这个池子的品质分布**本身偏高**（紫 + 红 = 17/37 = 46%）—— 所以"品质权重"与"品质件数"是两个独立的东西：
  你抽到一档之后，**在该档内部优先给"还没收集过的"**，该档收集齐了才随机重复。
  这条规则的作用只有一个：**让图鉴能集齐**（否则 10% 的紫档要在 11 件里靠运气凑齐，实际等于永远集不齐）。

### 1.2 品质权重 6 : 2.5 : 1 : 0.5

抽取**只有两步**（比旧定案的三段更简单，因为不再需要"数量"那一层）：

```
① 掷品质：白 60% / 蓝 25% / 紫 10% / 红 5%
② 掷 id ：该品质池里【优先未收集】，全收集后等概率随机
```

> **复用了什么**：旧定案 `settle.html` 的品质权重那一层（四档、随关卡变）**被本次取代** —— 局外抽取没有"关卡"语境，
> 固定 6 : 2.5 : 1 : 0.5 更简单、也更好向玩家交代。**数量权重那一层整层删掉**（那层是为"结算掉 0~3 件"设计的）。

**集齐 37 件要多少抽**（coupon collector，逐档算）：

| 品质 | 集齐该档期望抽数 | 占总抽数 |
|---|---|---|
| 白（12 件） | 62 抽 | 8% |
| 蓝（8 件） | 87 抽 | 11% |
| 紫（11 件） | 332 抽 | 43% |
| 红（6 件） | 294 抽 | 38% |
| **合计** | **≈ 775 抽** | 100% |

**紫档 + 红档占 81% 的抽数** —— 这就是 6:2.5:1:0.5 的代价（也是抽卡游戏的常态）。
嫌慢的话**只有一个旋钮**：把②改成「未收集的权重 ×2」而不是"优先未收集"，集齐抽数会降到 **≈ 500 抽**。

### 1.3 价格：递增 + 每日 0 点重置

| 常量（新增） | 值 | 说明 |
|---|---|---|
| `outerDrawCostBase` | **200** | 每天第一次抽取的价格 |
| `outerDrawCostStep` | **100** | 每抽一次 +100 |
| `outerDrawCostCap` | **600** | 封顶（第 5 次起都是 600） |

- **每天 0 点回到 200**（日键 `YYYYMMDD`，与 `TaskData.todayKey()` 逐字同口径）。
  为什么重置：局外是"每天玩一会儿"的节奏，价格不重置的话第二天开局就是 600，玩家会觉得"昨天把价格打贵了"。
- 当天价格序列：`200 / 300 / 400 / 500 / 600 / 600 / …`
- ⚠ **只有花金币的抽才抬价**：用抽取券（`outer_draw_ticket`）抽**不扣金币、也不抬阶梯**
  （与局内"广告免费刷新不抬高后续费用"逐字同口径）。所以日键旁边记的是"当日**付费**抽数"，
  不是"当天抽了几次"（`EquipmentCollection.drawPaidCount`）。
- ⚠ **十连没有折扣**：`十连的价钱 = 接下来 10 抽的价格逐个累加`（`200+300+…+600×5 = 5000`），
  与连点 10 次单抽**分毫不差**。要加折扣就改 `OuterRelicDraw.plan()` 一处（那里是唯一的算法）。
- **和金币收入对一下账**：日常任务 6 条合计 **810 金/天** ⇒ 光靠日常**每天 2 抽**（200+300=500；第 3 抽 400 →900 > 810）。
  一次性金币（成就 185,650 + 账号升级 29,040 ≈ **214,000**）按封顶 600 算 ≈ **350 抽**。
- **折算成时间**：集齐 775 抽 ≈ **每天 2 抽 × 10 个月 ≈ 25 万金币**。这就是"金币的长期深坑"该有的样子
  （对照：现在金币的唯一深坑是解锁英雄，10 位合计 **27,295**，而成就一次性就给 185,650 → 后期金币本来是过剩的）。

### 1.4 份数**无上限**（已拍板）

- 同一件可以反复抽到，`EquipmentCollection.collected[id]` 累加；`getAllEquipmentBonuses()` **按份数线性累加** ⇒ 属性线性成长。
- **必须知道的后果**：局外属性**没有天花板**。日增速被 §1.3 的价格递增限住（日常金币只够 2~3 抽/天），
  但长期（一年 ≈ 1,000 抽 ⇒ 每件平均 27 份）会让"难度 100 档 vs 局外成长"的配平**由抽数决定**。
- 有上限的属性（护甲 200 / 暴击率 100 / 闪避 45 / 攻速 5 / 魔抗 95 …）仍由 **`attributes.json` 的 `max` 钳制**；
  无上限的（攻击力 / 生命）就按份数无限涨 —— 这是**刻意选的**（长线无限养成）。
- 真要加天花板，**唯一改动点**是 `getAllEquipmentBonuses()` 里那份 `count` 的 clamp（一处），不要动数据层。

### 1.5 红档的**特效词缀**（6 件，各一条，全部复用现成的 10 条 effect code）

红色遗物除了属性，还给一条**局内开局特效** —— 用的是**成就系统已经在用的那套 `AchEffectCode`**
（`game/common/AchievementEffectMeta.ts`，10 条，`Scene_Game_Stage.show()` 开局快照），所以**零新机制**：

| 遗物 id | 名字 | 词缀 | 每份 | 合计封顶（沿用 `ACH_EFFECT_META.cap`） |
|---|---|---|---|---|
| 1302 | 巅峰之器 | 开局金币 `run_start_gold` | +25 | 200 |
| 1190 | 代达罗斯之殇 | 击杀金币 `gold_gain_bonus` | +5% | 25% |
| 1194 | 蝴蝶 | 局内经验 `battle_exp_bonus` | +5% | 20% |
| 1202 | 斯嘉蒂之眼 | 开局英雄等级 `hero_start_level` | +1 | 2（**次数型取 max**） |
| 1300 | 泰坦石板 | 肉鸽抽取费用 `shop_draw_discount` | −5% | 30% |
| 1301 | 海盗帽 | 击杀商店价格 `kill_buff_discount` | −5% | 20% |

- **叠加口径**（沿用旧定案）：**数值型按份数 Σ**（`start_gold` 这类），**次数型取 `max`**（`hero_start_level` 这类"质变"效果，
  否则"无上限份数"会让开局英雄等级无限涨）。给效果表加一个 `stack: sum | max` 字段最省事，别每加一条就改代码。
- ⚠ **词缀必须参与同一个 cap clamp**（与成就、与等级加成共用那一张 cap 表）。
  "份数无上限" + "词缀不 clamp" = 开局金币无限涨，一开局就能把肉鸽商店抽干。
- 白 / 蓝 / 紫 **不配词缀**（`effects` 留空数组）—— 与旧定案"只给高品质配特殊效果"一致。

### 1.6 入口与流程（**✅ 已落地 2026-11**）

```
左侧「遗物」页（Cmp_OuterRelics，已有：图鉴 + 属性总览）
  └─ 总览页顶部那一行（**固定不动**，在 ScrollView 之外）：
       [已收集 N/37 进度卡 250×72] [☐十连抽 78×72] [抽 取 · 金币 200  170×72]
                                                      ↑ 按钮上那行就是"这次要花什么"
       └─ 点击 → DataCenter.previewOuterDraw(1|10)   ← 界面**只读**它（消耗/亮不亮）
                 DataCenter.drawOuterRelic(1|10)     ← 局外金币的**唯一**抽取出口
                      ├─ OuterRelicDraw.plan()       ← 纯规则：先排"这次要付哪几步"
                      ├─ 按方案执行：① 有券 → 扣券（不扣钱、不抬价）② 否则扣金币（抬一档）
                      ├─ OuterRelicDraw.roll(...)    ← 纯规则（品质权重 → 档内优先未收集）
                      ├─ equipCollection.addCollected(id, 1)
                      ├─ 写当日**付费**抽数（日键）→ 抬高下一次价格
                      └─ saveAll() → 返回结果给界面（重铺列表 + 高亮刚抽到的那几行）
```

- **按钮上显示的消耗 == 真正扣的钱**：两处都出自同一个 `OuterRelicDraw.plan(count, 付费抽数, 券数, 金币)`
  —— 界面拿它拼文案、`DataCenter` 拿它逐步执行（与商城 `previewShopDailyGift` 同一套路）。
  让界面自己按阶梯累加，迟早出现"按钮写 200、实际扣 300"。
- **勾选框「十连抽」**是一次操作的**本页状态**（`Cmp_OuterRelics._tenDraw`，不落盘）：
  勾上之后消耗那行立刻换成"十连的总价"，点一下抽 10 个。
  十连**没有折扣**，价钱 = 接下来 10 抽的价格逐个累加（与连点 10 次单抽分毫不差）。
- **金币不够抽满时是部分成功**（`drawn < requested`，抽得动几个抽几个）：
  十连中途买不起不该把已经能抽的那几次也吞掉；界面据 `drawn` 在消耗那行播一下"抽到 N 件"。
  一次都抽不动时（0 券 + 金币 < 当天的第一抽价）→ `ok=false / no_resource`，**一分不扣、一件不抽**。
- **规则类拆出来了**：`game/battle/OuterRelicDraw.ts`，照 `RelicDraw.ts` 的套路 —— **纯函数、不碰 UI、不扣钱**
  （品质权重、档内优先未收集、价格阶梯、付费方案都是纯计算，体检脚本直接跑）。
- **券的优先级写死在 `plan()` 里**：`券 ＞ 金币`；**券抽不占价格阶梯**（与局内"广告免费刷新不抬高后续费用"逐字同口径）。
  券由商城 A4 发（`outer_draw_ticket`，每天 2 张），存量在**背包**（`docs/bag/README.md` §1）。
- ⚠ 与 `LevelFeature.RelicOuterUpgrade`（'relic_outer_upgrade'，表里**还没有任何等级声明它**）的关系：
  本方案**不做遗物升阶**（份数无上限已经承担了成长），那个标识留给以后真要做"阶数上限 + 升阶消耗"时再用。
  · `LevelFeature.RelicOuter`（'relic_outer'，Lv5 解锁）**有声明**，但**界面还没按等级锁抽取按钮**
  （现在谁都能抽）—— 要接就是 `Cmp_OuterRelics` 里加一条 `LevelConfig.hasFeature` 判据。

### 1.6.1 ⚠ 落地时一并修掉的一个**真 bug**：图鉴存量读档会被整片丢掉

`EquipmentCollection` 的 `collected` 原来是 `{遗物id: 份数}` 这种**动态字典**，而
`DataModule.mergeDeep` 只合并「默认数据里已经存在的 key」—— 默认值里 `collected` 是空对象，
于是**每一个 id 都不在 target 里、整片被 `continue` 掉**：读档等于没读，重启一次图鉴就归零。

- 之前看不出来：那时唯一的写入方是"局内抽到遗物"那条**漏洞接线**（§0.2），图鉴归零看着像"还没接数据"。
- 现在抽到的遗物是**玩家花金币换来的**，读档丢一次就是真丢东西 ⇒ **必须**走数组
  （口径同 `BagData.items` / `TaskData.records` / `ShopData.itemUsed`）：`collected: EquipCollectedRecord[]`。
- 旧存档里那种字典形态由 `EquipmentCollectionModule.migrateCollectedShape()` 在 `DataCenter.init()` 里
  就地转成数组（能救一点是一点）；`addCollected` 写之前也兜一次底（不假定启动迁移跑过了）。
- **判据在 `npm run audit:draw` 的 E/F 段**（抽完 → 新实例读档 → 份数还在；字典形态 → 迁移后照常读）。

### 1.7 红档词缀 → 与等级加成、成就的三源合流

局内开局参数的**快照只有一个**（`Scene_Game_Stage.show()` 读一次，本局全程用它），本次改成三个来源相加：

```
开局快照 = 成就效果（AchievementData.getEffects）
         + 等级加成（LevelConfig，见 §2）
         + 局外红遗物词缀（EquipmentCollection → relics 局外版 effects）
         ↓ 三者各自按 code 相加，然后**统一过一遍 cap**（ACH_EFFECT_META.cap）
```

**开局金币的总上限要单独定**：三个来源各自的 cap 都是 200，相加就是 600 ——
但 `battle_constants.initialGold = 100`，600 是它的 6 倍、一开局就能抽 14 次（50/次）。**推荐总上限 = 400**
（= 4 × 基础；= 开局最多多抽 8 次）。这条 clamp 写在快照合并那一处（**一处**，别散在三个来源里）。

## 2. 账号等级 → 局内加成

### 2.1 加成的表

| 等级 | 击杀金币 | 局内经验 | 开局金币 | 备注 |
|---|---|---|---|---|
| **每级（连续轴）** | **+1%** | **+1%** | — | 30 级 = **+30% / +30%** |
| Lv5 | | | | 功能解锁：局外遗物（`relic_outer`，**表里已有**） |
| **Lv10** | | | **+50** | 里程碑 |
| **Lv20** | | | **+100** | 里程碑 |
| **Lv30** | +30% | +30% | **+200** | 满级（`all_content`） |

- 为什么是 **+1%/级**而不是你最初写的 +0.1%：满级 30 级时 +0.1%/级 = **+3%**，
  局内一次击杀 3 金币变成 3.09 → **玩家完全感知不到**。+1%/级 的满级 **+30%** 与现成的成就 cap
  （`gold_gain_bonus` 25% / `battle_exp_bonus` 20%）同量级，才是一份"看得见的长期成长"。
- **开局金币为什么是里程碑而不是每级 +50**：`run_start_gold` 的现成 cap 是 **200**，而 `initialGold` 只有 **100** ——
  每级 +50 在 30 级就是 +1,500（基础的 15 倍，一开局抽 32 次），局内经济会当场失效。
  按 10 级一档给（50/100/200）正好贴着 cap 走，也让"整十级"有仪式感。

### 2.2 三源合流后的总量（**这是玩家真正看到的数**）

| 通道 | 成就 | **等级（本次新增）** | 局外红遗物 | 局内遗物属性 21/22 | 合计 |
|---|---|---|---|---|---|
| 击杀金币获取 | ≤ +25% | ≤ **+30%** | ≤ +25%（1190，按份数） | `attributes.json` 钳制 | ≤ **+55%** + 遗物属性 |
| 局内经验获取 | ≤ +20% | ≤ **+30%** | ≤ +20%（1194，按份数） | 同上 | ≤ **+50%** + 遗物属性 |
| 开局金币 | ≤ 200 | ≤ **200** | ≤ 200（1302，按份数） | — | **总 clamp 400**（§1.7） |

- 消费点**只有一处**：`Scene_Game_Stage.grantKillReward`（`Scene_Game_Stage.ts:1811-1818`）。
  它现在已经是 `achievement + relicAttr` 两个来源相加，**加第三个来源就是一行**：

```ts
const goldBonus = this.achGoldGainBonus() + relicGoldBonus + this.levelGoldGainBonus();
const expBonus  = this.achBattleExpBonus() + relicExpBonus + this.levelBattleExpBonus();
```

- 开局金币的消费点是 `selectHero` 里的 `hero.gold = getInitialGold() + N`（成就效果那段），同样并一个来源。
- 与**属性 21/22（金币获取/经验获取）**是**加法**，不是乘法 —— 沿用现有口径（`goldBonus = ach + relic` 那两行）。

### 2.3 配表与代码落点

| 落点 | 做什么 |

## 3. 局内广告券（局外攒 / 局内花）

**一句话**：广告是**全屏原生层**，局内播它要把本局**置为暂停**（`Scene_Game_Stage.playAd`）——
曲子在打正紧的时候被一段 30 秒视频切断，体验很差。所以给玩家一条**把广告挪到局外看**的路：
在商城里看广告换**局内广告券**，局内拿券**直接免看广告**完成同样的两件事。

| 项 | 口径 |
|---|---|
| 获取 | **只在商城**：看 1 次激励视频 → **+1 张**（`AdPlacement = 'shop_ad_ticket'`），**每天最多 2 张** |
| 存放 | **背包**：`DataCenter.ins.bagData.getCount('ad_ticket')`（**跨局累积**，不是每局清零）—— ⚠ 2026-11 从 `ShopData.adTickets` 搬到了 `BagData`（口径见 `docs/bag/README.md` §1） |
| 消费 | **只在局内肉鸽商店的两个广告位**（用户点名的这两处）：<br>① **免广告抽卡** = `RelicShop.refresh` 的 `playAd('relic_refresh')` 那一支<br>② **免广告获取遗物** = `RelicShop.pick(id, viaAd=true)` 的 `playAd('relic_extra_pick')` 那一支 |
| 不覆盖 | **选英雄刷新**（`hero_refresh`）与**击杀商店刷新**（`buff_shop_refresh`）**照旧走广告**（本次不放开；要放开就是一个开关）<br>**暂停广告**（`pause_resume`）永远不收券 —— 它没有奖励，用券没意义 |
| 优先级 | `金币够 → 花金币` **＞** `有券 → 用券` **＞** `还有广告次数 → 看广告` **＞** 置灰 |

### 3.1 ⚠ 一条硬口径：券**不增加**局内次数上限

局内那两处的次数是**每局配额**，配置在 `shop_constants`：
`adFreeDrawPerRun = 3`（广告免费刷新）+ `adExtraPickCount = 1`（广告补选），另有成就效果
`ad_free_draw` / `hero_select_free` 各叠加上去。

**券只是"把看广告这一步换成扣券"，配额照扣** —— 所以：
- 券的**一局消费上限就是局内配额本身**：`adFreeDrawPerRun`(3) + `adExtraPickCount`(1) = **每局最多用 4 张**
  （成就效果会把这个上限再抬高一点）；
- 每天 2 张 ⇒ 正常节奏下一局用 2 张左右，**不会**变成"每天多 2 次抽卡"；
- 券**跨局累积**，但**配额每局清零**（`RelicShop.reset()`）—— 所以哪怕攒了一周 14 张，一局也只能花 4 张，
  **攒券攒不出无限次数**（这是这条口径真正的护栏）。

> 如果让券"额外加次数"（不扣配额），那**每局上限就由"券的存量"决定**：券跨局累积 ⇒ 攒一周就有 14 张，
> 一局白拿 14 次（而这个上限本来是配表里写死的 3+1）。同时局内遗物池是 **268 件、抽后不放回**，
> "一局吃 70~85% 池子"的旧目标会被券推高。**"券替换广告、不替换配额"是本次刻意选的保守口径。**

### 3.2 判据点只有一处：`RefreshGate`（**✅ 已落地 2026-11**）

`battle/RefreshGate.ts` 是三个商店面板「刷新按钮能不能点」的**唯一真源**（文件头就是为这件事写的）。
本次给它**加一个可选输入与一个字段**，其余两个面板**逐字不变**：

```ts
export interface RefreshGate {
    enabled: boolean;
    canPay: boolean;        // 货币够 → 直接扣钱
    viaTicket: boolean;     // ★ 新增：货币不够、但有广告券 → 点了免看广告
    viaAd: boolean;         // 货币不够、也没券、但还有广告次数 → 点了看广告
}
// 缺省 ticketLeft = 0 ⇒ 选英雄 / 击杀商店的判据与今天完全一致
evaluateRefreshGate(balance, cost, adFreeLeft, ticketLeft = 0)
```

- ⚠ **`refreshButtonKey()` 必须带上新这一位** —— 那个函数存在的唯一理由就是"判据变了、按钮必须重画"
  （文件头第 45-53 行写了两个坑：返回值是新对象不能直接 watch、必须带上 `cost`）。漏了 `viaTicket` 就是
  "有券了按钮还写着看广告"。
- `RelicShop.refresh()` 里那一支从「`gate.viaAd` → `playAd`」改成「`gate.viaTicket` → 扣券；否则 `viaAd` → `playAd`」。
- `pick(id, viaAd=true)` 同理：进 `playAd` 之前先看一眼券。

> **落地形态（2026-11，与上面逐字一致）**：`RefreshGate` 的 `evaluateRefreshGate(balance, cost, adFreeLeft, ticketLeft = 0)`
> + 结果里多了 `viaTicket`；`refreshButtonKey` 的指纹是 `enabled/canPay/viaTicket/viaAd|cost`；
> `RelicShop.tryUseAdTicket()` 是**唯一扣券点**（先扣券、扣不动就退回看广告那一支）；
> 券的张数由宿主注入的两个 getter 提供（`Scene_Game_Stage` → `bagData.getCount/consumeItem('ad_ticket')`），
> 因为**战斗功能类不认识数据层**（与 `spendGold` 同一分工）。

## 5. 数值后果（诚实版，别到时候才想起来）

1. **局外属性无上限**（§1.4）：长期会让高难度档的挑战性被"抽数"稀释。**已知并接受**；要收就在 `getAllEquipmentBonuses` 一处 clamp。
2. **紫 + 红占 81% 的集齐成本**（§1.2）：图鉴最后 17 件要 626 抽。这是 6:2.5:1:0.5 的直接结果。
3. **金币从"过剩"变"紧缺"**（§1.3）：解锁英雄 27,295 是唯一深坑、而成就给 185,650 的时代结束了 ——
   抽取会是新的主深坑，所以**成就/任务给的金币数值不要在本次一并下调**（否则前期抽不动）。
4. **局内金币获取 +30%（满级）会推高每局抽取次数**：局内遗物池 268 件、
   `shop_constants` 的抽取费用 50 → +25 → 封顶 200 —— 收益 +30% ⇒ 抽取次数 +30%，
   "一局吃 70~85% 池子"的旧目标会逼近上限（甚至吃光）。**要不要同步抬 `drawCostCap`，等属性接线后拿真机数据再定**。
5. **局外属性必须接进战斗**（§6 第 8 条）：不接的话，这次改的三条规则里有两条**看不见效果** ——
   抽到的遗物只是图鉴里的一格，等级加成只有局内那两行百分比是真的（只有广告券这条不依赖它）。
6. **广告券是"1 次广告换 1 次免广告"，价值全在"不打断局内节奏"**（§3）：它**不增加**局内次数上限，
   所以对"愿意看广告的玩家"它等价于零收益 —— 这不是 bug，是刻意选的保守口径（换成"加次数"就会
   同时顶破局内池子与跨局累积两道闸）。
   若实测发现**没人愿意换**，两个旋钮按代价从小到大：① 一次广告给 **2 张**券（改一个常量）；
   ② 把券开放到选英雄 / 击杀商店那两个广告位（`evaluateRefreshGate` 的调用方多传一个参数）。
