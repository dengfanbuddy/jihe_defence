  · **⚠⚠ 落地时发现并修掉的 3 个实现口径问题**（都不是配表错，都是"写下去才发现"）：① **119 雷链首跳伤害写错** —— 写成"每跳都先乘一次 decay"→ 首跳只有 50% 攻击力，与文案「首跳 100%」不符；修法是 `chain` 回调带 index 后 `if (i > 1) dmg *= decay`；② **109 首击不能挂 `on_attack_landed`** —— 「目标满血？」必须在**扣血之前**判定，而 landed 是在 `ApplyDamage` **之后**派发的（`:395-399`），在那里读 `hp/maxHp` **永远为假**（第一版就是这么写的）→ 正确分工是 `on_attack_start` 记标记（按 uid，顺带解决对象池复用认错实体）、landed 消费；③ **`percent` 打在 base=0 上的老问题又出现两次**（108 护甲 / 128 破甲必须 `add`），而同一批里 110 的「伤害输出倍率」（attr 11 base=100）与 128 的自身增伤用 `percent` 才对 —— **同一个词条里两种写法并存是属性 base 决定的，不是风格选择**。
  · **写这 25 个类时踩到的三组"只有跑了才知道"的陷阱**（已写进 `audit:skill` 的注释）：① **`Entity.ChangeHp` 会把 hp 钳在 `maxHp`** → 用 `raw=400` 打满血 320 的英雄量"格挡减半"，量出来是 320 不是 400，**测试伤害不能超过目标当前生命**；② **`DamagePipeline` 对每一次伤害都会 roll 暴击**（不是只有普攻）→ 精确断言必须先把攻击者暴击率清零，否则伤害随机翻 1.5 倍；③ **不能假设"属性 base 就是 `attributes.json` 的默认值"** —— 怪物行会覆盖它，而属性 5 移速有 `min: 50`，实测某怪 base=100、减 120 被钳成 50，于是「每层 -60」的断言**两层和一层都是 50、假通过**；测试木桩要显式钉住它依赖的属性。
  · **让文档自己证明"已落地"**：`docs/skill-icons/skills.md` 的**「落地形态」与「落地机制」两列是每次 `gen-prompts.mjs` 现读 `abilities.json` + `modifiers.json` 推导出来的**（`kind` 也是推导：引用的 Modifier 里没有带 `script_id` 的 = 纯声明式 / 有带的有没带的 = 混装 / 全是脚本 = 脚本），手写的只有 `skills.json` 的 `landed.indirect`（脚本**运行时自己挂**的那些 Modifier，配表看不见）与 `landed.note`。生成器还会做三向对账：`indirect` 里的号必须在 `modifiers.json` 存在**且**在 `ShopSkillModifiers.ts` 里按号引用到；`SHOP_MOD` 表的每个号必须存在、且每个 `script_id=Modifier_X` 的行的号必须等于 `SHOP_MOD.X`（**编号漂移是独立于类名的一条链**，类名全对、号错了技能照样静默失效）。改完跑 `node tools/skill-icon-prompts/set-landed.mjs` → `gen-prompts.mjs`。
  · **⚠⚠ 退碎图那轮踩到的坑：「绝不删」名单里的说明是没人验过的一句话**：`retire-loose-skill-icons.py` 的 `NEVER_DELETE` 把 `baotou.png` / `huoqiang.png` 写成「既有遗留资源（128×128，**无人引用**）」—— 这句是凭印象写的，而事实是**两者各被 `Scene_Menu.prefab` 按 uuid 引用 5 次**（`cc.Sprite._spriteFrame`，选人卡英雄槽占位图），于是它们被清掉、预制件留下 **10 处悬空引用**。修法两道：说明改成事实 + **加闸 0「保底名单自检」**（每次运行现场扫引用数，`why` 声称「无人引用」却扫出引用 → **直接拒绝执行**），并把 `scan_uuid_refs()` 抽给闸 0 与闸 3 共用 —— 原来只有"待删的那批"被扫描，"保底的那批"谁都没查。**教训：一张安全名单的危险不在于它拦得不够，而在于它自己没被验证；"闸 3 查得严、保底名单没人查"这种半覆盖比没有名单更危险。**（`魔棒·去背景.png` 经扫描确实零引用，已一并清掉；三张图的字节保留在 `tools/skill-icon-prompts/backup-legacy-skill-orphans.zip`。）
  · **决定这 30 条设计的引擎口径（每条都真跑源码核过，AGENTS.md 与源码注释里原有的说法有几处是过时的）**：① **只有 5 个事件会派发给 Modifier** —— 全工程 `DispatchEvent` 只在 `Entity.ts:343`(`on_attack_start`) / `:379`(`on_attack_landed`) / `DamagePipeline.ts:108`(`on_block_damage`) / `:132`(`on_take_damage`) / `:134`(`on_deal_damage`) 五处被调用；`BattleEvents` 里另外 15 个（`on_kill` / `on_death` / `on_heal` / `on_projectile_hit` / `on_ability_cast` / `on_state_changed` / `on_entity_added` …）**只 `bus.publish`、从不派发** → `modifiers.events[].event` 写这些名字**永远不触发**（静默失效）。要用总线事件只能写脚本 `ctx.bus.on(...)` 并在 `OnDestroy` 里 `off`（实体走对象池复用）。② **`on_attack_landed` 不带 `isCrit`**（`Entity.resolveAttackHit` 只发 `{attacker,target,damage,damageType}`），而 `on_deal_damage` 带 → 「暴击时」必须挂 `on_deal_damage`。③ **护盾不是实体字段** —— `DamagePipeline:103-110` 造一个带可变字段 `blocked` 的事件派发出去再 `damage -= blocked`，所以护盾/格挡**只能写脚本**（声明式动作写不了这个字段）。④ **伤害数值是绝对数** —— `damage`/`aoe_damage`/`heal`/`tick_damage` 只有 `value:number`，**没有 `var`/`pct`**；**只有 `modify_attr` 的属性条目支持 `var`/`attrs_var`**（`EffectTypes.ts`）→ 「造成 X% 攻击力」的伤害一律要脚本按 `atk` 算（写死数值在肉鸽里会迅速贬值），而「减速 20%」「破甲 N」这类**属性类减益能做**（`kv:{slow:-60}`）。⑤ **`modifiers.cd` 是死代码** —— `Modifier.Trigger()`/`OnTriggered()` **全工程零调用方**（`ModifierSystem.Tick:257` 只在递减 `cdRemaining`，没有任何触发方），「每 N 秒触发」只能在脚本 `OnTick(dt)` 里自己计时（`Modifier_ZeusThunder` 四阶就是这么做的）。⑥ **`tick_damage` 不随层数放大**（`processTickEffect` 用 `eff.value` 原值），只有属性条目乘 `stackCount`。⑦ **`percent` 打在 base=0 上恒为 0**（护甲 6 / 闪避 8 / 生命恢复 9 / 魔法恢复 10 / 暴击率 14）。⑧ **护甲是双曲曲线**（`1-0.06a/(1+0.06|a|)`）→ 原稿「护甲减伤 +18%」不能直接抄成 18（护甲 +7 就≈30% 减伤）。⑨ **`on_take_damage` 派发在死亡检查之前**（第 7 阶段派发、第 8 阶段才 `IsDead()`）→ **在事件里把血补回来能真的拦住死亡**，「死亡时逆转时间」这类设计不需要改引擎。⑩ **英雄永远不会施放技能**（`getCastableSkills()` 零调用方）→ 一切挂在「释放技能」上的设计都不可达；**「友军」在本作不存在**（单英雄局）；**召唤物没有任何表现路径**（`MonsterPool` 把 prefab 硬编码成 `prefabs/unit/monsters/one`，team=1 召唤物没有 EntityView 分支）→ 123 哨兵炮台 / 124 镜像分身 / 125 元素军阵 三条「召唤流」需独立立项，本轮改成**零基建的等价机制**（周期性自动开火 / 普攻概率追加一击 / 击杀攒层转化为追加伤害）。
  · **⚠⚠ 本轮修掉的两个真 bug（都只有肉鸽技能才暴露，英雄技能踩不到）**：① **`AbilitySystem.RemoveAbility` 只 `filter` 数组、不摘该技能挂上的 Modifier**（`Ability.removeOwnModifiers()` 原是 private、只被 `setLevel` 调），而 `SkillSlots.grant` 顶掉旧技能走的正是它 → **肉鸽技能被替换后它给的属性加成永久留在英雄身上**（30 条肉鸽技能全是 passive + `modify_attr`，所以对它们是致命的；英雄自带技能因槽 0 永久锁定不可替换，所以一直没暴露）。修法：`removeOwnModifiers()` 改 **public**，`RemoveAbility` / `Clear()` 丢弃技能对象前先调它（按 `origin === 'ability:<id>'` 过滤，与换级重挂同一条路径）。② **最大生命「下降」时当前生命不钳** —— `Entity.ApplyWithMaxHpCarry` 原先只处理上限上涨，而「恶魔契约 -40% 最大生命」是下降，实测满血买完三级是 **`hp 320 / maxHp 192`** 脏数据。修法四处：新增 `Entity.ClampHpToMax()`；`ApplyWithMaxHpCarry` 加上限下降分支；**`EffectExecutor` 的 `modify_attr` 在 `duration < 0` 时改走 `ApplyWithMaxHpCarry`**（此前技能改属性**绕过**了那个包裹器，所以「遗物有满血口径、技能没有」）；`Ability.removeOwnModifiers()` 收尾也钳一次。**仍存的既有缺口**：**临时**上限到期回落时没接钩子（要动 `ModifierSystem` 才能拿到"上限变了"的时机）。
  · **6 条纯声明式技能已落表（`tools/skill-effects/apply-skill-effects.mjs`，幂等，全程零新增 TS）**：103 嗜血（`apply_modifier` 34/35/36，**这是唯一需要新增 Modifier 的一条** —— `lifesteal.ratio` 是动作字段、没有 `var` 绑定，只有 `modify_attr` 的属性条目能绑）、104 迅捷 `[4,+8/+15/+35,add]`、105 鹰眼 `[16,+12/+20/+45,percent]`、106 强健 `[1,+12/+22/+35,percent]`（三阶追加 `[9,+2,add]`）、107 暴击机芯 `[14,+8/+15/+24,add]`（三阶追加 `[15,170,best]`）、130 恶魔契约 `[3,+40/+60/+100,percent]`+`[1,-15/-25/-40,percent]`。原稿做不到的半句**明确删掉**（不是省略）：过量转护盾（无护盾池）/「攻速≥2.5 必暴击」「射程内无敌人 +10%」（条件式）/「每秒 1% 最大生命」（`tick_heal` 是定值 → 改固定 +2/秒）/技能冷却缩减（无该属性）。**新增体检 `npm run audit:skill`**（= `tools/skill-audit/verify-skills.mjs`，**116 条断言**（2026-10 复核实跑）：换技能不漏属性 / `Clear()` 干净 / 五条技能 1~3 级属性逐级对账 / 暴击倍率走 `best` 不是累加 / 负向最大生命 + `hp>maxHp` 回归 / 嗜血升级摘旧挂新 / 嗜血**真普攻命中**后回复量 == 最终伤害 × 比例 / icon 文件真的存在）。⚠ **它就是当场抓出上面第 ② 个 bug 的**（D 组一条断言红）—— `npm run check` 与 `verify` 只验配表**格式**，验不出「配表对了但运行时是脏数据」。

- **重新选英雄**: 等级 / 经验 / 装备（遗物）/ Buff / **技能槽**都**不变** —— 遗物由 `RelicSystem` 持有、Buff 层数由 `BuffShop` 持有、技能槽状态由 `SkillSlots` 持有（都不属于英雄实体），英雄实体重建后由 `Scene_Game_Stage.selectHero` 调 `RelicSystem.RebindOwner(hero)`、`BuffShop.rebind()`、`SkillSlots.attachHero(hero, unitSkillIds)` 把已获得的内容重新挂到新英雄上（见 `Scene_Game_Stage` 英雄创建分支）。

- **技能槽（2026-09 落地）**: 设计稿口径见 `docs/prd/阶段模式_局内规则详解.md` §7.1；实现在 `battle/SkillSlots.ts`（纯 TS 规则类）+ `cmps/skill_slot/SkillSlot.ts`（格子组件）+ `SkillDetailPanel.ts`（长按详情浮层）+ `FloatText.ts`（飘字）。四条硬口径：

  · **新技能落槽**（`grant`）：① 已拥有 → **原地升 1 级**（`max_level` 封顶，满级后商店不再出）；② 否则**优先填「索引最小的未锁定空槽」**；③ 未锁定槽都满了 → **替换「索引最小的未锁定槽」**（被顶掉的技能从英雄实体 `RemoveAbility`，于是它重新回到商店抽取池）；④ 一个未锁定槽都没有 → 返回 `all_locked`，`RelicShop` 调宿主注入的 `onSkillAllLocked` → HUD **飘字提示**「技能槽已全部锁定」，并把那一格标成"本轮拒发"（置灰、**不消耗本次选择**，玩家可以改选别的）。
  · **归属要记下来、不能反推**：`SkillSlots` 内部有 `granted` 集合（商店发过的技能 id）。**踩过**：`attachHero` 换英雄时若用"不在新英雄 `unitSkillIds` 里就算肉鸽技能"来判，上一任英雄的自带技能（如火枪的 12）会不认识自己了 → 被当成肉鸽技能一路带走 → 槽位被旧英雄的技能占满、真正的肉鸽技能反而被挤掉（`npm run audit:slot` 第 ⑨ 条就是抓这个的）。
