  · **决定这 30 条设计的引擎口径（每条都真跑源码核过，AGENTS.md 与源码注释里原有的说法有几处是过时的）**：① **只有 5 个事件会派发给 Modifier** —— 全工程 `DispatchEvent` 只在 `Entity.ts:343`(`on_attack_start`) / `:379`(`on_attack_landed`) / `DamagePipeline.ts:108`(`on_block_damage`) / `:132`(`on_take_damage`) / `:134`(`on_deal_damage`) 五处被调用；`BattleEvents` 里另外 15 个（`on_kill` / `on_death` / `on_heal` / `on_projectile_hit` / `on_ability_cast` / `on_state_changed` / `on_entity_added` …）**只 `bus.publish`、从不派发** → `modifiers.events[].event` 写这些名字**永远不触发**（静默失效）。要用总线事件只能写脚本 `ctx.bus.on(...)` 并在 `OnDestroy` 里 `off`（实体走对象池复用）。② **`on_attack_landed` 不带 `isCrit`**（`Entity.resolveAttackHit` 只发 `{attacker,target,damage,damageType}`），而 `on_deal_damage` 带 → 「暴击时」必须挂 `on_deal_damage`。③ **护盾不是实体字段** —— `DamagePipeline:103-110` 造一个带可变字段 `blocked` 的事件派发出去再 `damage -= blocked`，所以护盾/格挡**只能写脚本**（声明式动作写不了这个字段）。④ **伤害数值是绝对数** —— `damage`/`aoe_damage`/`heal`/`tick_damage` 只有 `value:number`，**没有 `var`/`pct`**；**只有 `modify_attr` 的属性条目支持 `var`/`attrs_var`**（`EffectTypes.ts`）→ 「造成 X% 攻击力」的伤害一律要脚本按 `atk` 算（写死数值在肉鸽里会迅速贬值），而「减速 20%」「破甲 N」这类**属性类减益能做**（`kv:{slow:-60}`）。⑤ **`modifiers.cd` 是死代码** —— `Modifier.Trigger()`/`OnTriggered()` **全工程零调用方**（`ModifierSystem.Tick:257` 只在递减 `cdRemaining`，没有任何触发方），「每 N 秒触发」只能在脚本 `OnTick(dt)` 里自己计时（`Modifier_ZeusThunder` 四阶就是这么做的）。⑥ **`tick_damage` 不随层数放大**（`processTickEffect` 用 `eff.value` 原值），只有属性条目乘 `stackCount`。⑦ **`percent` 打在 base=0 上恒为 0**（护甲 6 / 闪避 8 / 生命恢复 9 / 魔法恢复 10 / 暴击率 14）。⑧ **护甲是双曲曲线**（`1-0.06a/(1+0.06|a|)`）→ 原稿「护甲减伤 +18%」不能直接抄成 18（护甲 +7 就≈30% 减伤）。⑨ **`on_take_damage` 派发在死亡检查之前**（第 7 阶段派发、第 8 阶段才 `IsDead()`）→ **在事件里把血补回来能真的拦住死亡**，「死亡时逆转时间」这类设计不需要改引擎。⑩ **英雄永远不会施放技能**（`getCastableSkills()` 零调用方）→ 一切挂在「释放技能」上的设计都不可达；**「友军」在本作不存在**（单英雄局）；**召唤物没有任何表现路径**（`MonsterPool` 把 prefab 硬编码成 `prefabs/unit/monsters/one`，team=1 召唤物没有 EntityView 分支）→ 123 哨兵炮台 / 124 镜像分身 / 125 元素军阵 三条「召唤流」需独立立项，本轮改成**零基建的等价机制**（周期性自动开火 / 普攻概率追加一击 / 击杀攒层转化为追加伤害）。⑪ **⚠⚠ `OnKill` 载荷里的死者位置已经作废**（2026-11 修）：派发顺序是 `publish(OnDeath)` → 场景在那里 `recycleMonster`（`MonsterPool.release` → `EntityPool.release` → `Entity.ResetForPool()`，`Entity.ts:171` 把 `position` 换成新对象 `{x:0,y:0}`）→ **然后**才 `publish(OnKill)`。所以「以死者位置为圆心」的范围效果拿 `victim.position` 会**恒以地图原点为圆心**，画面上几乎看不出来 —— 技能 122「击杀回响」与遗物「死亡回响」两处都中过招（`Scene_Game_Stage` 的掉落点坐标是第三个受害者，它早就靠"在 `recycleMonster` 之前取"自救）。修法：`DamagePipeline` 第 8 阶段在 `publish(OnDeath)` **之前**取 `deathPos` 快照，两个载荷都带上，消费者读 `event.deathPos`；**不要**改派发时机（那要重排整条事件链）。⚠ 附带两条：① `findEntitiesInRadius` 读的是 `center.position`，**裸坐标点会被当成 (0,0)**，快照必须包成 `{ position: deathPos }`（`RelicHooks.centerAt`）；② `audit:skill` 里的 `findEntitiesInRadius` 是**手写副本**（真 `BattleContext` 在体检里是空类桩），改真实现不会同步副本 —— 现在有 **L0** 断言把两者钉在一起；同组的 `makeCtx` 还**复刻了场景的 `recycleMonster`**，否则体检环境比真实环境宽松，这类 bug 在体检里永远全绿。
  · **⚠⚠ 本轮修掉的两个真 bug（都只有肉鸽技能才暴露，英雄技能踩不到）**：① **`AbilitySystem.RemoveAbility` 只 `filter` 数组、不摘该技能挂上的 Modifier**（`Ability.removeOwnModifiers()` 原是 private、只被 `setLevel` 调），而 `SkillSlots.grant` 顶掉旧技能走的正是它 → **肉鸽技能被替换后它给的属性加成永久留在英雄身上**（30 条肉鸽技能全是 passive + `modify_attr`，所以对它们是致命的；英雄自带技能因槽 0 永久锁定不可替换，所以一直没暴露）。修法：`removeOwnModifiers()` 改 **public**，`RemoveAbility` / `Clear()` 丢弃技能对象前先调它（按 `origin === 'ability:<id>'` 过滤，与换级重挂同一条路径）。② **最大生命「下降」时当前生命不钳** —— `Entity.ApplyWithMaxHpCarry` 原先只处理上限上涨，而「恶魔契约 -40% 最大生命」是下降，实测满血买完三级是 **`hp 320 / maxHp 192`** 脏数据。修法四处：新增 `Entity.ClampHpToMax()`；`ApplyWithMaxHpCarry` 加上限下降分支；**`EffectExecutor` 的 `modify_attr` 在 `duration < 0` 时改走 `ApplyWithMaxHpCarry`**（此前技能改属性**绕过**了那个包裹器，所以「遗物有满血口径、技能没有」）；`Ability.removeOwnModifiers()` 收尾也钳一次。**仍存的既有缺口**：**临时**上限到期回落时没接钩子（要动 `ModifierSystem` 才能拿到"上限变了"的时机）。
  · **6 条纯声明式技能已落表（`tools/skill-effects/apply-skill-effects.mjs`，幂等，全程零新增 TS）**：103 嗜血（`apply_modifier` 34/35/36，**这是唯一需要新增 Modifier 的一条** —— `lifesteal.ratio` 是动作字段、没有 `var` 绑定，只有 `modify_attr` 的属性条目能绑）、104 迅捷 `[4,+8/+15/+35,add]`、105 鹰眼 `[16,+12/+20/+45,percent]`、106 强健 `[1,+12/+22/+35,percent]`（三阶追加 `[9,+2,add]`）、107 暴击机芯 `[14,+8/+15/+24,add]`（三阶追加 `[15,170,best]`）、130 恶魔契约 `[3,+40/+60/+100,percent]`+`[1,-15/-25/-40,percent]`。原稿做不到的半句**明确删掉**（不是省略）：过量转护盾（无护盾池）/「攻速≥2.5 必暴击」「射程内无敌人 +10%」（条件式）/「每秒 1% 最大生命」（`tick_heal` 是定值 → 改固定 +2/秒）/技能冷却缩减（无该属性）。**新增体检 `npm run audit:skill`**（= `tools/skill-audit/verify-skills.mjs`，**116 条断言**（2026-10 复核实跑）：换技能不漏属性 / `Clear()` 干净 / 五条技能 1~3 级属性逐级对账 / 暴击倍率走 `best` 不是累加 / 负向最大生命 + `hp>maxHp` 回归 / 嗜血升级摘旧挂新 / 嗜血**真普攻命中**后回复量 == 最终伤害 × 比例 / icon 文件真的存在）。⚠ **它就是当场抓出上面第 ② 个 bug 的**（D 组一条断言红）—— `npm run check` 与 `verify` 只验配表**格式**，验不出「配表对了但运行时是脏数据」。

- **换局必须把上一局的英雄实体作废（踩过：点「确定」退出后再进游戏，上一局的结算面板立刻又弹出来）**: `resetRun()` 里除了 `finalBoss` / `attackTarget` / `heroRelics` / `ctx`，还**必须**清 `this.hero = null` + `heroNode?.getComponent(Hero)?.unbind()`。漏掉逻辑那行的后果不是"残留一点表现"，而是**新一局第一帧就判负**：`update` 的守卫是 `if (!this.ctx || this.finished || !this.hero) return`，而上一局阵亡的英雄 `IsDead()` 恒 true（`!alive || hp <= 0`）→ 直接命中那条「英雄已阵亡但本局未结束」的兜底断言 → `endRun('defeat','hero_dead_fallback')` → `showEnd()` 把结算面板**重新打开**（复用缓存视图时 `View_Game_Stage.onShow` 刚把它收起过，所以现象是"面板自己又冒出来"，很容易误判成 onShow 复位失效），并且 `settleMetaRewards` 会**再发一次局外经验**（每次进出都白刷）。上一局是胜利（英雄还活着）时不会弹面板，但会带着旧英雄一路 `tick`，同样不对。表现侧解绑顺带保证 `selectHero` 里 `if (hero.entity) RemoveEntity(...)` 不会去动**别的 ctx** 的实体（`Hero.unbind()` 会把 `entity` 置 null）。清掉之后不变式成立：`hero` 要么是 null、要么属于当前 `ctx`——而 `hero === null` 是**合法开局态**（第一局选英雄前就是它），读 `this.hero` 的地方（`syncHeroToStore` / `spendGold` / `syncHeroRangeCircle`）已判空，`BuffShop` 的 `getHero()` 也判空。

- **「连击」（`RelicHook_AtkSpeedStack` / `modifiers.json` #212）的窗口口径 —— 2026-11 修掉「满层永驻」**（用户口径：「应该是第一次击中开始计时 3s…3s 后效果消失，下次击中重新计算；而且这种效果没有 cd 么？」）:
  · **原 bug（两处叠加，缺一不可成灾）**：① 层数**只增不减**（只有"距上次命中 > 3 秒"才归零）；② 每次命中都把承载属性的共享模板实例**重放成满时长**（`reapplyAttrs(..., HIT_STACK_SEC)`，同 `origin` 重放 = 删旧建新、时长从头算）。而本作普攻间隔 0.64~1.42 秒（`units.json` 的 `attack_interval ÷ (攻速/100)`），**永远小于 3 秒** ⇒ 层数与时长双双被刷新 ⇒ **满层永驻 = 一件永久遗物**（黄档 `+3%×10 层 = +30% 攻速` 常驻、红档 `+60%` 常驻），文案里的「持续 3 秒」纯属摆设。
  · **新口径（3 条，改之前先读）**：① **窗口锚在「第一次叠层成功」那一击**（不是每次命中，也不是第一次命中 —— 概率没掷中时什么都不做、也不开窗）；② 窗口内的命中**只叠层、窗口截止时刻一动不动**；③ 重放共享模板时传的时长 = **窗口剩余**（不是恒定 `sec`）⇒ 到点那一刻属性贡献自己到期摘掉，`OnTick` 顺手把层数清零；下一击命中另开一个新窗口。**结果 = 一个窗口一循环**。
  · **两个新旋钮（配表 `kv`，不写死代码）**：`sec` = 窗口秒数（缺省 3）、`chance` = 每次命中的叠层概率 %（缺省 **100 = 必叠**，与旧行为一致）。概率走公共的 `rollPct()`（`Math.random()*100 < pct`），与「重击/点燃/震荡」同一口径。
  · **为什么没有额外 CD**：`modifiers.cd` 是**死代码**（见上文 ⑤），填了也不触发；而这个效果**本身就是"一窗口一循环"**的机制 —— 层数一定会在窗口末掉到 0，谁都拦不住。要"归零后再等 N 秒"是另一条设计，得先定数值。
  · **定的数值（用户从 5 套候选里选的 E 案）**：蓝 `per 2→4 / max 6 / sec 4 / chance 25`、黄 `3→6 / 10 / 6 / 25`、红 `4→8 / 15 / 8 / 25`。**25% 概率下 3 秒窗口连蓝档都叠不满**（实测只剩 `+1.4%` 攻速 ≈ 没有效果），所以**窗口随档拉长 + per 翻倍补偿层数减半**。时间加权平均额外攻速（`node tools/relic-combo-sim/sim.mjs`，火枪裸装 0.83s/次 → 中后期 0.40s/次）：蓝 `+3.5% → +6.2%`、黄 `+7.0% → +13.3%`、红 `+12.1% → +22.9%`；对照**旧 bug 值** `+12 / +30 / +60`（满层永驻）与**只修计时不调参**的 A 案 `蓝 35%/黄 21%/红 14%`。**换算口径写在脚本里：平均层数 = ∫层数dt ÷ 时长，与普攻间隔强相关** —— 改 `per/max/sec/chance` 前后都要跑它对账（`--json` 可出数据）。
