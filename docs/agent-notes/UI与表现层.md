- **飘伤害字（表现层）**: `game_stage/entityview/DamageTextLayer.ts`（整场一个中央层）+ `common/DamageTextConfig.ts`（**字号/描边**/配色/寿命/合并与上限的唯一数据源，不依赖 cc）+ `entityview/GeometricDigits.ts`（手写几何数字字形，零字体资产）。**节点由编辑器摆位**：`Scene_Game_Stage.damageLayerNode` 指向预制件里的 `damege_layer`（挂在场景根下、与 `enimys` 同级，排在 hero/弹道之后、`uiViewNode` 之前 → **数字压在所有战斗实体之上、UI 之下**；改层级就是拖节点顺序，不用改代码）；取用顺序见 `Scene_Game_Stage.ensureDamageTextLayer`（① 拖了引用 → 用它；② 没拖但子树里有组件 → 直接用；③ 都没有 → 运行时建一个挂在 `monsterParent` 最后）。**一个视觉通道只承载一个含义**：颜色 = 打谁（英雄受击红 = `UNIT_VISUALS[Hero].hitColor`，其余白），尺度/形状 = 打击分量（暴击 = 1.6× 字号 + 左侧实心菱形标 + pop 回弹），寿命 = 优先级。**颜色不用来区分暴击**（否则与单位配色/受击色三义）。**战斗背景是浅色的，白字必须描边**：每个飘字画两遍 —— 先 `outlineColor`（暗墨色）且线宽比正文多 `outlineGrow` 的一层描边、再画彩色正文，白字+深边在浅底深底上都能读（`outlineGrow: 0` 即关掉描边）。**换字号只动 `DAMAGE_TEXT.baseFontSize` 一处**（= 普通伤害的实测字高，世界单位；暴击/英雄受击都是它的倍率），间距类参数一律用**相对字号的倍率**（如 `ladderGapRatio`），否则改小字号后相邻数字会叠在一起。反噪声：同目标 + 同档位 + 同来源 0.15s 内**累加合并**（英雄受击不分来源）、全场并发上限 24 按优先级淘汰（英雄受击 +6）、同目标连击沿 y 阶梯错开、按 `target.uid` 横向稳定抖散。四处关键口径：① **所有飘字画在同一个 `Graphics` 上 → 整层恒定 1 次 draw call**（不是每个数字一个 Label 节点，池化的是纯数据对象）；② 位置必须在 `OnTakeDamage` 回调里**立刻快照**（该事件发生在 `ChangeHp` 之后、`Die` 之前，实体死后位置不再同步）；③ 飘字层节点的 layer 必须是 UI_2D（`new Node()` 默认不是，运行时创建那条路要显式 `node.layer = monsterParent.layer`，否则 UI 相机看不到）；④ **坐标系靠契约、不做转换**：`entity.position` 处于 `monsterParent` 的局部空间，而飘字层必须与它**同坐标系** —— 预制件里 `damege_layer` 与 `enimys` 同为场景根子节点、position 都是 `(0,0)`、缩放都是 1，两个局部空间完全重合，所以 `entity.position` 拿来即用（**曾经写过的 `inv(本层世界矩阵) × 参照世界矩阵` 换算已删除**：该摆法下它 ≡ 单位矩阵，白算还多一层"世界矩阵何时就绪"的依赖）。改层级时别动层节点的 position/scale；`bind(ctx, monsterParent)` 的第二个参数只用于 bind 时的一次自检（`checkSpace`，同父但局部变换不同 → `console.warn`）。设计稿与改手感用的渲染器：`docs/damage-text-mockup.png` + `node tools/damage-text-preview/gen-mockup.mjs`（从 TS 源解析真实字形与参数出图，不用开编辑器）。**尚未做**：伤害类型配色（物理白/魔法紫/纯粹青）、DoT 弱化档、治疗/反伤/闪避·免疫几何符号、大额伤害档 —— DoT 与普攻目前无法从事件里区分（`ModifierSystem.tick_damage` 与普攻都不带 `ability`），要做需先给 `ApplyDamage` 的 options 加一个可选 tag。

- **单位血条（表现层）**: `entityview/HpBar.ts`（控制器）+ `common/EntityHpBarConfig.ts`（**唯一数值源**：节点名 `hp_bar` / 隐藏延时 `hideDelay`=2 / 世界高度 `worldHeight`=5）+ `EntityView`（按 `HP_BAR.nodeName` 在预制件根节点下查子节点，bind 时 `attach`、unbind 时 `reset`）。口径：**默认隐藏**（预制件里 `hp_bar` 的 `_active` 也置了 false）→ 受击显示（同一个 `OnTakeDamage` 入口；该事件在扣血之后 → 读到的就是实时百分比）→ **未受击 2s 隐藏**（每次受击重新计时）；**宽度 = 生命百分比**（锚点在左 → 从左往右掉），满血宽度只在**首次 attach** 记录（之后 width 被百分比改写，池化复用再读就只能读到上一只的残血长度）。四处关键口径：① **父预制件缩放**：血条是单位根节点（按体型 ×1/1.3/1.5/2）的子节点，**高度定死 5 世界单位** → `node.scale.y = 1/父节点worldScale.y`（`worldScale` 的 getter 内部会先 `updateWorldTransform()`，取到的是最新值，不怕"本帧刚 setScale"）；**长度不抵消**，随体型一起放大 → 血条始终横跨身体（普通 20 / 最终 Boss 40），要改成"长度也定死 20"就是 scale.x 同样取倒数一行的事；② **预制件里 `hp_bar` 上挂着的 Widget（LEFT\|RIGHT 拉伸 + AlignMode.ALWAYS）必须关掉** —— 它会在自身/父节点 transform 一变（单位每帧移动）就把宽度改回"父节点宽度"，百分比会被逐帧覆盖（血条永远满格），所以 `HpBar.attach` 里 `widget.enabled = false`，**宽度的唯一写入方是 HpBar**；③ 计时**帧驱动**（同 HitFlash：池化节点上 scheduleOnce 会跨生命周期残留），`tick` 必须排在 `update` 的死亡早退**之前**（怪死了血条也要按时收尾）；④ 池化契约：`unbind → HpBar.reset()`（隐藏 + 复位长度/缩放），`onDestroy` 只断引用（血条是子节点，销毁流程里它先被销毁）。**英雄未挂**（HUD 的 `View_Game_Stage.hp_bar` ProgressBar 已承担），要挂就在 `Hero.ts` 里同样 `new HpBar().attach(...)`。

- **打击反馈（打击感）的落地口径（✅ B0+B1+B2+B3 已落地 2026-10）**: 设计唯一决策文档 = `docs/打击反馈设计.md`（定调「图纸印痕」+ 档位表 T0~T7 + 预算/合并 + 不做清单）；**数值唯一真源** = `common/HitFeelConfig.ts`（`HIT_FEEL_TIERS` 按档画几条 / `HIT_FEEL_MARK` 怎么画 / `HIT_FEEL_INFO` 屏幕层口径 / `HIT_FEEL_BUDGET` 预算 / `HIT_FEEL_DENSITY` 衰减 / `HIT_FEEL_TIER_RANK` 档位强弱）。**四个实现件**：`game_stage/entityview/HitFeelDirector.ts`（**全局**决策层：顿帧 / 慢动作 / 战斗内容层位移 / 墨闪 α / 账本 / 密度统计，**纯 TS 无 cc**）、`entityview/HitVfxLayer.ts`（**战斗内容层**：刻度 / 细环 / 对位十字 / 死亡碎片 / 起手虚线 / 闪避斜杠）、`entityview/HitScreenLayer.ts`（**屏幕层**：墨闪渲染 / 四角角标 / 连击计数 / 击杀落款 / 奖励飞入）、`entityview/HitFlash.deform()` + `EntityView`（**每个受击者自己**的抖动 / 膨胀 / Z-Pop）。三层都是「**整层一个 `Graphics` = 恒定 1 draw call**，池化的是数据对象」（照抄 `DamageTextLayer` 的三件套）。
  · **为什么本作只能靠"时间 + 位移 + 线条"**：战场底 `#EBF4FB` 是浅底图纸风 → **加法发光/白闪做了也看不见**（趋白）、"粒子/光晕"在风格禁用清单里、工程无后处理管线且**只有一个 UI 相机**（动相机会把 HUD 一起抖，所以"震屏"改造成**战斗内容层位移**）。
  · 六条判据（踩过才写下来的）：① **顿帧只缩 `ctx.Tick`**（`tick(dtReal, dtCombat)` 双时钟），`checkStage`/`elapsed`/`bossScheduler` 一律走**真实 dt** —— 刷怪节奏按 `elapsed` 索引 `SPAWN_BEATS`、成就「闪电战」也按它判，缩了就是**静默改难度**；② 因此顿帧是**对 DPS 的隐性征税**，必须记 1s 滑动账本（≤30ms/s），**峰值档位**（T5/T7）才能一次吃满那一秒且绝不叠加；③ `stopTimeScale` 用 **0.02 不用 0**（`ctx.Tick(0)` 会让 Modifier/DoT/AI/弹道/缓动一整条链路吃 dt=0）；④ **表现层位移绝不写 `entity.position`**（那是 `ApplyKnockback` 的领域，会影响 AI 与索敌），只写"基准位置 + 偏移"、每帧先还原；⑤ 印痕层走**真实时间**（不吃顿帧/慢放，否则 T7 那 90ms 顿帧里印痕几乎不动 = 白画），密度系数 **k 在出生那一刻快照**（否则同一批印痕会一边扩散一边缩水）；⑥ 合并要按"**档位相同 + 颜色相同 + 40ms 内 + 80px 内**"（同帧去重太脆：AoE 的 N 次命中可能被分到相邻两帧 → 本该合成一片的印痕在帧边界裂开）。
  · **英雄是特例**（不参与抖动/膨胀）：英雄节点下挂着 `range`（射程圈 `GraphCircle`），缩它会连射程圈一起缩、位移它会让圈离开真实判定圈 —— 两种都会被读成"射程变了"。英雄的反馈 = 染色 + 方向性内容层位移 +（B3 的）角标/墨闪。
  · `vfx` / `screen_vfx` 两层都是**运行时建**的（`ensureHitVfxLayer()` / `ensureHitScreenLayer()` 三级取用：① 根下按名字找到的节点 ② 子树里有组件 ③ 运行时建）。⚠ 位置是硬约束：`vfx` 必须**插在 `damage_layer` 之前**（`addChild` 追加到最后会让印痕**盖在 `ctlrs_right`（HUD）上**），`screen_vfx` 必须**插在 HUD 之前**（奖励飞过去要"钻进"HUD 里消失）；新建节点还要显式继承参照节点的 `layer`（`new Node()` 默认不是 `UI_2D`，UI 相机看不到）。`vfx` 与 `enimys`/`projectile`/`projectile_cache`/`damage_layer` 一起**参与内容层位移**且**必须同偏移**；`screen_vfx` **不参与**。
  · **两个层的分界线只有一条：抖不抖。** `vfx` 是战斗内容（跟着沙盘一起被推），`screen_vfx` 是信息（贴在屏幕上、飞进 HUD）。把信息画在抖动的层里 → 震屏那 200~320ms 内整块 HUD 读数都在晃，而那正是最需要读清的时候。
  · **屏幕层的击杀三件（连击 F4 / 落款 F8 / 奖励飞入 F9）由场景显式调用**（`grantKillReward` 里 `hitScreen.killReward(x, y, gold, exp)`），**不订阅总线**：奖励金额是场景算出来的（基础值 × 阶段系数 × 通胀 × 成就/遗物加成 × Boss 倍率），而 `OnKill` 的载荷只有 `{killer, victim}` —— 表现层自己算会算出**另一个数**。调用点放在"金币经验都为 0 就早退"**之前**，所以白给奖励为 0 的击杀一样算连击、一样有落款。
  · **奖励落点是每次击杀现算的**（`Scene_Game_Stage.resolveRewardAnchor` 闭包 → `UITransform.convertToNodeSpaceAR`，把 HUD 上金币/经验数字的位置换算到屏幕层局部坐标）：**不缓存** —— 缓存会在换分辨率/转屏/改 HUD 布局后指到错的地方，而"飞错地方"比"不飞"更糟。任何一环缺失（HUD 未就绪 / 数字节点被停用）都返回 null → 退化成"朝右上飞一小段"，**绝不静默不画**。
  · **延迟掉血条（F6）的三条口径**：① 残影条是 `hp_bar` 的**兄弟节点**、**插在它之前**（Cocos 的绘制顺序是"父节点自己的 Sprite 先画、子节点后画"——挂在 hp_bar 下面会**盖在血条上**，正好反了）；② 它**借 hp_bar 的 SpriteFrame**（不新增资源、不做异步 load —— 异步在池化组件里是生命周期雷区）；③ 它**不是"白色的残影"**而是墨色 α0.45（血条本体是红 `#F52121`、战场底是 `#EBF4FB`，白条在上面等于没画）。曲线是 **ease-out**（掉血那一刻迅速收掉大半、末段慢慢贴），**回血时直接跟到位**（追"回血"没有信息量，反而像卡了一下）。
  · **HUD 数值弹跳（F10）** 是**帧驱动**的（同一条"不用 tween"的纪律），且**收尾必须复位 scale**（否则下一次弹跳从 1.25 起算、越弹越大）；同一个节点重复触发只**刷新剩余时长**、不叠倍率（连击时金币每 0.3s 跳一次，叠加会把数字吹成气球）。
  · 体检 = `npm run audit:hitfeel`（**145 条**；它把 `cc` 桩成"记账画布 + 极简假节点树"，真跑四层验"每档画出的图元数 = 档位表"、墨闪冷却、角标贴边、连击清零、奖励落锚点、残影条单调收敛）。详见 `docs/agent-notes/工具与工作流.md` 的同一主题条目。
  · **✅ B4 听觉已落地（2026-10）**：素材**不是"找来的"而是"渲出来的"** —— `tools/hit-feel-sfx/`（`design.mjs` 声音配方 + `render.mjs` **零依赖** DSP + `audition.html` 试听页 + `check-drift.mjs` 三方对账 + `README.md`）产出 `assets/resources/sfx/` 的 **16 个音**（11 个音 + 5 个音高变体；139KB；16bit WAV / 22050 单声道 / 逐条峰值 0.80；**零第三方素材 → 零授权义务**）。参数来自演示台 §3 那份为本作调过的 Web Audio 合成（`noiseHit` / `toneHit`），所以风格与设计稿天然一致。
    代码链路：`HitFeelConfig`（`sfxVolume` / `sfxVariants` + `HIT_FEEL_SFX_EXTRA` + `hitFeelSfxKey` / `hitFeelSfxKeys` / `shouldPlayAttackSfx`）→ `HitFeelDirector.requestSfx`（**50ms 内 ≤2 声的节流账本 + 同帧只出最强档**）→ `Scene_Game_Stage.initBattle` **注入播放回调**（`hitFeel.sfxPlayer = (key, volume) => AudioMgr.ins.playSFX(key, volume)`）+ `preloadSfx(hitFeelSfxKeys())` → `AudioMgr`。
    三条口径：① **播放回调由场景注入**，导演保持纯 TS 无 cc —— 这是它能被 `audit:hitfeel` 真跑的前提；② **只给英雄响出手音**（怪走同一个 `Entity.Attack()`，怪群围住英雄时全响会变底噪）；③ `AudioMgr.loadAudioClip` 改成**先 `resources.load` 再退回 bundle**（原来反着来，音效带 `sfx/` 前缀 → 首段被当分包名 → 每次首载都白打一条 `分包:sfx加载失败`）。
    ⚠ 三条踩过的坑：**DoT 与普攻在总线载荷里完全同形**（`ability == null` 且不暴击）→ 设计稿写的"DoT 不发声"做不到，实际是**也响 `hit_light`**（节流兜住）；**引擎 3.8 的 `playOneShot(clip, volumeScale)` 没有音高参数、`AudioSource` 也没有 `playbackRate`** → E3 音高随机只能**预渲染变体**；**`.meta` 要等编辑器首次导入才生成，必须随提交入库**。改音量后依次跑 `node render.mjs` → `node check-drift.mjs --write`。

- **表现层 `onDestroy` 里绝不碰别的组件**（踩过：结束面板点「确定」报 `Cannot read properties of null (reading 'equals')`，且**画面卡死、回不到主界面**）: 节点销毁时 Cocos **先销毁子节点、再按注册顺序销毁本节点组件**，并对每个已销毁对象跑 `_destruct()`（对象字段一律置 null：`Sprite._color`、`Graphics._impl`、组件自己的引用字段…）。所以在 `onDestroy` 里回滚外观（`sprite.color = c` / `g.clear()` / `node.setScale`）会读到 null 抛 TypeError —— **真正致命的不是这条报错**：`onDestroy` 由引擎 `CCObject._deferredDestroy()` 在 `director.tick` 里调用，而它排在 `uiRendererManager.updateAllDirtyRenderers()` / `_root.frameMove()`（提交渲染）**之前**；抛异常会让**销毁队列不清空**（下一帧从同一个对象重新抛，控制台每帧刷同一条）且**此后每帧都不再绘制** → 画面永久卡在上一帧（"点确定没回到主界面"就是这么来的；队列只在整段循环跑完才清空，所以一个坏 `onDestroy` 能永久废掉渲染）。口径：**`unbind()`（对象池回收、节点不销毁）才回滚表现；`onDestroy()` 只退订 + 断引用**（`entityview/EntityView.ts`、`game_stage/Hero.ts`、`entityview/DamageTextLayer.ts` 都按这个口径），`HitFlash.paint` 内部再判一次 `sprite.isValid` 兜底。**同一个坑的 UI 变体（踩过：一局战斗结束回主界面「过了一会儿」开始刷屏报错）**：`UIWidget.onDispose()`（或任何组件 `onDestroy`）里对**后代节点**调 `node.off(...)` 一样会炸 —— 报 `Uncaught TypeError: Cannot read properties of null (reading 'off')`（`Node.off` = `this._eventProcessor.off(...)`，而 `_eventProcessor` 已被 `_destruct()` 置 null）。**触发链**：`Scene_Game_Stage.exit()` → `UIManager.showUI(Scene_Menu)` → 战斗视图进 **60s 缓存** → `cleanupExpiredCache()` → `node.destroy()` → 帧末销毁级联**先把后代节点 `_destruct()`**，随后这些组件的 `onDispose` 再 `off()` 就打空了；`HeroItem.onDispose` 是第一个撞上的（它在 `hero_select_panel/pannel/items/*` 上，比 `View_Game_Stage` 更深 → 先被销毁 → 抛异常把整条级联打断 → 销毁队列不清空 + `errorID(5000)`「destroy a object twice or more」刷屏 + 画面冻结），**修了它只会把异常顺位让给 `View_Game_Stage`（HUD 的按钮同样是它自己的后代）**，所以这一层的 `off` 必须全查一遍。口径：**组件 `onDestroy`/`onDispose` 里摘节点事件一律用 `UIComponent.offNodeEvent(node, type, handler, target)`**（内部判 `node.isValid`，已销毁节点直接跳过；`node?.off()` 的**可选链挡不住**这个错 —— `node` 不是 null，是它内部字段被清空了），跳过不会泄漏（监听随节点的事件处理器一起消亡）。同时 `UIWidget.onDestroy` 已
