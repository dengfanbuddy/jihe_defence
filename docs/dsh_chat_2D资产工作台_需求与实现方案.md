# dsh_chat 2D 资产工作台 —— 插件功能拆分与实现方案（v0.2）

> **v0.2 修订说明**：上一稿（v0.1）从"本工程缺什么"切入，跑偏了。
> 本文改成**插件视角**：这个插件该有哪些功能、怎么分类、每类要给什么界面、
> 怎么给 AI 一套**统一调用接口**让它统一调度、外部模型（云 / 本地）怎么用一个**统一配置页**收口。
> 本工程的现状数据降级为**附录 A 的选材参考**，不构成设计依据。

---

## 0. 结论速览

**一句话**：把 dsh_chat 从"AI 对话 + 操控编辑器"扩成**2D 游戏资产生产中台**：
按**产物类型**分大类，每类一个独立界面（可与 Scene 同区停靠），功能内部自洽完备；
所有功能登记进**一份能力注册表**，人通过界面调、AI 通过**三个统一工具**调、CLI 用同一份语义调；
一切外部模型（内置算法 / 本地 ComfyUI / 云 API）由**一个设置页**统一配置、路由与降级。

**四条设计原则**（后面所有取舍都从这里推出来）

| # | 原则 | 它决定了什么 |
|---|---|---|
| 1 | **大分类 = 一个界面**，每类内部**闭环完备**（建 → 改 → 预览 → 采用 → 历史） | 面板划分与每个面板的功能下限 |
| 2 | **面板 / CLI / AI 共用同一份能力注册表** | **加功能 ≠ 加工具**：AI 侧永远只有 3 个工具，功能数量与工具数量解耦 |
| 3 | **一切异步作业进统一任务中心**，人与 AI 写同一份台账 | "手动"和"自动"是同一条流水线的两端，不是两套系统 |
| 4 | **一切外部依赖走统一提供方配置 + 路由 + 降级链** | 云/本地/内置可换、可混用、可离线；密钥与预算只有一个口 |

**一句话形象**：
> 插件 = 一个**资产 IDE**。每个大类是一个工作台面板；背后是一套**能力（capability）**；
> AI 不是"点按钮的机器人"，而是**拿着同一套能力表在调度流水线**的同事。

## 1. 需求 → 界面 → 能力（总览）

| 你说的 | 落成界面 | 主要能力域 | 是否已有 |
|---|---|---|---|
| AI 对话、操控 Cocos | **DSH 对话**（已有面板） | — | ✅ 已有 |
| 美术资产：AI 生成 UI/icon/logo/海报 | **美术** | `image.*` | ✖ |
| 美术资产：UI 分层 / UI 编辑 / UI 元素提取 | **UI 工作台** | `ui.*` | ✖ |
| 美术资产：图片压缩 / 尺寸更改 | **美术**（单图后处理）+ **资源库**（批量与工程级） | `image.*` / `asset.*` | ✖ |
| 声音资产：音效、背景音乐 | **音频** | `audio.*` | ✖ |
| 动画（主要是帧动画 AI 生成） | **动画** | `anim.*` | ✖ |
| 特效 | **特效** | `vfx.*` | ✖ |
| ——（你没提但必然要有） | **资源库**（批量优化 / 图集 / 引用 / 台账 / 预算） | `asset.*` | ✖ |
| "让 AI 统一调度" | **任务中心** | `job.*` | ✖ |
| "云 / 本地 ComfyUI 让用户选" | **设置与提供方** | `provider.*` | ✖ |

**共 8 个新面板 + 1 个已有面板**，全部 dockable、可与 Scene 同区（§6.1 给了实测探针与两条退路）。

> **为什么是"产物类型"分类而不是"技术手段"分类**：
> 用户脑子里想的是"我要一个图标 / 我要一段 UI / 我要一个音效"，
> 不是"我要跑一个扩散模型"。按产物分类，界面才和用户的意图对齐，
> 而技术手段（程序化 / 本地模型 / 云 API）被下沉到**设置页的路由**里 —— 这正是你提的那一点。

## 2. 大分类拆分（8 个界面）

### 2.1 分类总表

| 界面 | id | 定位 | 产物落在哪 | 异步？ |
|---|---|---|---|---|
| **美术** | `art` | 图像类资产的生成与处理（单图为主） | 任意输出目录 → 采用进 `assets/` | 生成类异步，处理类同步 |
| **UI 工作台** | `ui` | UI 稿 ↔ 分层切图 ↔ 预制件 ↔ 元素提取 | 切图 + `layout.json` + `.prefab` | 切图/落预制件异步 |
| **动画** | `anim` | 帧动画生成、精灵表、AnimationClip | `.png` 表 + `.anim` | 异步（可能数分钟） |
| **特效** | `vfx` | 粒子 / 序列帧特效 / 特效预制件 | `.plist` + 贴图 + `.prefab` | 准同步 |
| **音频** | `audio` | 音效与 BGM 的生成、编辑、归一 | `assets/resources/audio/**` | 异步 |
| **资源库** | `assets` | 工程级批量优化、图集、引用、预算、台账 | 原地改 / 新目录 | 批量异步 |
| **任务中心** | `jobs` | 所有作业的统一调度、进度、审阅、历史 | 作业台账 | ——（它就是异步本身） |
| **设置与提供方** | `settings` | 提供方、路由、密钥、预算、默认、预设、诊断 | 本机配置（不入工程） | 同步 |
| （已有）**DSH 对话** | `default` | 自然语言入口 + 统一调度的"人话侧" | —— | —— |

### 2.2 每个面板都必须有的"完备性基线"

光有功能点不算"功能完备"。下面这些是**每个面板的下限**，缺一个这个界面就不能算做完：

| 维度 | 必须有 |
|---|---|
| **浏览** | 搜索 / 筛选（状态·类型·来源·时间）/ 排序 / 分页或虚拟滚动 |
| **选择** | 单选 / 多选 / 全选 / 反向选择 / 拖拽入列 |
| **批量** | 批量执行、批量采用、批量丢弃、批量删除（都要能预览"将影响 N 项"） |
| **预览** | 缩略图网格 / 大图 / 放大 / **before-after 对比** / 用系统看图器打开 |
| **参数** | 表单（由能力 schema 自动渲染）/ 记住上次参数 / 存为预设 / 从预设载入 |
| **作业** | 进度 / 取消 / 重试 / 日志 / 失败原因人话化 / 一键复制诊断 |
| **审阅** | 采用（写回工程）/ 丢弃 / **撤回**（从工程退回作业区） |
| **历史** | 作业历史 + 参数历史 + 产物版本（同一目标的多次生成可比） |
| **导出** | 清单导出（CSV/JSON）、报告导出（Markdown） |
| **与 AI** | 任意选中项 → **「交给 AI」**；AI 起的作业在本面板可见并可审阅 |
| **空态** | 第一次打开时给出"下一步做什么"（对齐本插件既有习惯：`cocos_editor_state` 会给"下一步用哪个工具"） |

## 3. 逐个大类的功能拆分

> 每节三块：**功能清单**（= 能力注册表里的条目）/ **界面分区** / **验收判据**。
> 能力 id 用点分命名 `<域>.<动作>`；这张 id 表就是面板、CLI、AI 三侧共用的那**一份真源**。

### 3.1 美术（`art`）

**定位**：一切"一张图"的事 —— 生成、改、抠、修、统一风格、后处理。

| 能力 id | 功能 | 输入 | 输出 | 同步/异步 | 需要提供方 |
|---|---|---|---|---|---|
| `image.generate` | 文生图 | 提示词/负向词/尺寸/比例/**n 张**/seed/风格预设 | n 张候选图 | 异步 | 是（图像模型） |
| `image.generate_from_ref` | 图生图 / 参考图约束 | 参考图 + 强度 + 提示词 | 候选图 | 异步 | 是 |
| `image.inpaint` | 局部重绘（涂抹区域） | 原图 + 蒙版 + 提示词 | 候选图 | 异步 | 是 |
| `image.outpaint` | 扩图 / 补边 | 原图 + 目标尺寸 + 方向 | 候选图 | 异步 | 是 |
| `image.remove_bg` | 抠图 / 去背景 | 原图 + 容差或模型 | 透明 PNG | 同步（色距）/ 异步（模型） | 可选 |
| `image.upscale` | 放大 / 增强 | 原图 + 倍率 + 算法 | 大图 | 同步/异步 | 可选 |
| `image.quantize_style` | **风格统一**：量化到项目色板 + 线宽/描边归一 | 原图 + 色板来源 | 合规图 | 同步 | 否（内置） |
| `image.icon_set` | **批量图标生成**：从清单/配表按文法批量出图 | 清单 + 尺寸 + 品质档 + 文法参数 | n 张图标 + 映射表 | 同步（程序化） | 可选 |
| `image.texture` | 程序化贴图（光斑/圆环/星形/噪点/渐变/圆角块/九宫格底） | 类型 + 尺寸 + 颜色 + 参数 | PNG | 同步 | 否 |
| `image.svg_render` | SVG/HTML → PNG（透明） | svg/html + 尺寸 | PNG | 同步 | 否（本地渲染器） |
| `image.transform` | 尺寸 / 裁剪 / 旋转 / 翻转 / 补边 / 圆角 / 描边 / 水印 | 原图 + 参数 | 图 | 同步 | 否 |
| `image.compose` | 拼图（网格/长图/对比图/精灵表雏形） | 多图 + 布局 | 图 | 同步 | 否 |
| `image.analyze` | 体检：尺寸/体积/alpha/主色/空图/重复（感知哈希） | 图或目录 | 报告 JSON | 同步 | 否 |
| `image.convert` | 格式转换（png/webp/jpg/avif） | 图 + 目标格式/质量 | 图 | 同步 | 否（本地编解码） |

**界面分区**（单面板，左侧能力导航 + 右侧工作区）：

```
┌ 美术 ────────────────────────────────────────────────┬──────────────┐
│ 能力          │ 参数（schema 渲染）      │ 候选 ▣▣▣▣  │ 预览         │
│ ▸ 生成        │ 提示词 [风格预设 ▾]      │ ▣▣▣▣       │ 大图/          │
│ ▸ 图标批      │ 尺寸 [1024] 张数 [4]     │ ▣▣▣▣       │ before-after  │
│ ▸ 抠图        │ seed [随机] ☑缓存        │            │ 元数据         │
│ ▸ 后处理      │ [预览命令] [运行] [交给AI]│ [采用][丢弃]│ 色板符合度     │
│ ▸ 风格统一    ├──────────────────────────┴────────────┴──────────────┤
│ ▸ 贴图        │ 历史：本目标最近 10 次生成的参数 + 缩略图 + 一键回到那次   │
└───────────────┴──────────────────────────────────────────────────────┘
```

**验收判据**：① 生成类能力**必须**产出"候选"而不是直接入库（默认不写 `assets/`）；
② 采用才进工程且可撤回；③ `image.quantize_style` 后主色落在色板容差内；
④ 同一参数 + 同 seed 缓存命中（不重复计费）。

### 3.2 UI 工作台（`ui`）

**定位**：UI 的**源**是结构（稿），图只是产物。这是"分层 / 编辑 / 元素提取"能成立的前提。

| 能力 id | 功能 | 输入 | 输出 |
|---|---|---|---|
| `ui.new` | 新建 UI 稿（空白模板 / 从预设 / **AI 按描述生成稿**） | 描述或模板 | HTML-IR + tokens |
| `ui.import` | 导入外部稿（HTML/图片参考） | 文件 | HTML-IR |
| `ui.slice` | **分层切图**：逐层透明 PNG + `layout.json` | HTML-IR | 图 + layout |
| `ui.edit` | **可视化编辑**：文案/颜色/间距/层序/九宫格/显隐 | 交互 | 更新 HTML-IR（幂等再切一次结果一致） |
| `ui.extract_from_prefab` | **从现有预制件反向提取** | `.prefab` | HTML-IR + 元素清单 |
| `ui.extract_element` | **UI 元素提取/入库**：把某层或某截图区域抽成可复用组件 | 稿/图 + 区域 | 组件（图 + 规格） |
| `ui.build_prefab` | 转预制件（节点树 + Sprite/Label/Button + 九宫格 + 层级） | layout.json | `.prefab` |
| `ui.validate` | 校验：色板符合度 / 间距体系 / 最小点击区 / 字号阶梯 / 多分辨率适配 | layout + 规范 | 报告 |
| `ui.compare` | 稿 vs 预制件渲染对照（差异像素报告） | 两者 | 差异图 + 报告 |

**界面分区**：三栏 **稿 ｜ 层 ｜ 产出** + 底部作业条；编辑在面板内实时重渲染（不开编辑器）。
**关键口径**：
- 文本**不切图**：导出为 `label`（文案/字号/颜色/对齐），由 Cocos `Label` 承载；
- 自动布局**不推断**：需要 `Layout/Widget` 的地方在 `layout.json` 里显式声明；
- 稿内**禁用** `<canvas>`、复杂 SVG 滤镜、自定义字体（否则切图失真，`ui.slice` 主动告警）。

**验收判据**：① 层叠加回原稿像素差 < 阈值；② 稿 → 预制件 → 稿 往返，布局差异在容差内；
③ 面板里改一个文案，再切一次结果一致（幂等）；④ 产出的预制件符合工程的 UI 规约（两层体系、不加 `@uiview`、`sizeMode` 顺序）。

### 3.3 动画（`anim`）

**定位**：帧动画为主，三级来源（本地程序化 → 视频模型 → 逐帧生成），统一汇入"表 + clip"。

| 能力 id | 功能 | 说明 |
|---|---|---|
| `anim.bake_params` | **程序化参数动画**：把形状/图形的参数沿时间轴插值 → 逐帧图 | 零成本、秒级、风格 100% 一致（主路） |
| `anim.from_video` | 视频 → 抽帧（ffmpeg） | 需视频模型；图生视频一致性更好 |
| `anim.from_frames` | 逐帧图/序列导入 | 手工或模型产出 |
| `anim.align_frames` | **帧对齐去抖**（锚点/质心/首帧锁定） | 决定"角色会不会跳" |
| `anim.sheet_pack` | 合精灵表（网格 + 统一 trim + 锚点） | 输出表 + 每帧 rect 描述 |
| `anim.sheet_split` | 拆表（导入现成精灵表） | 反向能力，做"提取"必备 |
| `anim.build_clip` | 生成 AnimationClip（帧序列 / 属性轨道） | 落 `.anim` 或返回构建脚本 |
| `anim.build_ui_tween` | UI 动效（淡入/位移/缩放/序列） | 给 `UIOpacity`/`UITransform` |
| `anim.export_gif` | 导出 GIF/WebP/MP4 预览 | 交付与评审用 |
| `anim.preview` | 面板内 scrubber 预览 | 不依赖编辑器 |

**界面分区**：左"配方与关键帧表"（可手改数字，也可让 AI 生成）｜中"帧序列条"｜右"表预览 + clip 描述"；底部 scrubber。
**验收判据**：① 锚点漂移 < 容差；② 帧数/帧率/时长与规格一致；③ 生成的 clip 在场景里能播；
④ 表内无重叠、无裁切；⑤ 视频路线下必须过 `anim.align_frames` 才算合格。

### 3.4 特效（`vfx`）

**定位**：特效 = 数据（参数）+ 贴图 + 挂点。先把"参数化生成"做透，Shader 留到最后。

| 能力 id | 功能 |
|---|---|
| `vfx.particle_build` | 生成粒子配置（发射率/寿命/速度/加速度/颜色 ramp/缩放曲线/混合模式）→ `.plist` |
| `vfx.particle_preview` | 面板内近似预览（同一份参数用 canvas 画） |
| `vfx.flipbook_build` | 序列帧特效（复用 `anim.*` 管线） |
| `vfx.prefab_build` | 特效预制件（粒子节点 + 贴图 + 播放脚本挂点） |
| `vfx.library` | 特效库：常用组合（受击/爆炸/升级/治疗/光环）参数模板，可复制改写 |
| `vfx.shader_template` | Shader 特效模板（**标注为实验性**，不承诺可自动生成） |

**验收判据**：① `.plist` 能被引擎解析、节点能跑不报错；② 参数与规格一致（面板读回来的值 == plist 里的值）。

### 3.5 音频（`audio`）

| 能力 id | 功能 | 说明 |
|---|---|---|
| `audio.sfx_synth` | **程序化音效合成**（波形 + ADSR + 滤波 + 变体） | 零依赖/零成本；适合点击/金币/受击/升级/失败 |
| `audio.generate` | 模型生成音效 / BGM | 需要提供方 |
| `audio.bgm_compose` | 程序化作曲（和弦进行 + 音色 + 节奏 + 段落） | 适合极简 ambient 循环 |
| `audio.edit` | 裁剪 / 淡入淡出 / 循环点 / 变调 / 变速 / 拼接 / 反转 | |
| `audio.normalize` | 响度归一（LUFS）+ 峰值限制 + 首尾防爆音 | **统一口径，防"有的吵有的听不见"** |
| `audio.convert` | wav/ogg/mp3 转换、采样率/位深/声道规整 | 本地 ffmpeg |
| `audio.waveform` | 波形/频谱图（面板里画 + 供审阅） | |
| `audio.manifest` | 音频台账：事件名 → 文件 + 时长/响度/循环点 | 供代码接线与门禁 |

**界面分区**：上"事件清单"（事件名 + 状态：缺 / 已生成 / 已接线）｜中"合成参数 + 生成 + **试听**"｜下"BGM 与响度体检"。
**验收判据**：① 响度/峰值/时长达标；② 首尾无爆音；③ 试听可用；④ 台账与文件一致。

### 3.6 资源库（`assets`）

**定位**：工程级（不是单图）的批量与治理。**注意**：这个面板的"处理动作"与美术面板共用同一批能力 id，
它只是**批量与工程视角**的入口（同一份能力，两个界面，避免抄第二遍）。

| 能力 id | 功能 |
|---|---|
| `asset.scan` | 扫描资源库：尺寸/体积/格式/命名/引用关系/孤儿 → 报告 |
| `asset.compress` | 批量压缩（按预算/按目录/按类型） |
| `asset.resize_batch` | 批量改尺寸（按规则；九宫格图保护边距） |
| `asset.convert_format` | 批量格式转换（webp/avif/png） |
| `asset.atlas_build` | 图集打包（合并小图 + 生成图集资产/目录约定） |
| `asset.import_settings` | 批量导入设置（图集归属/trim/packable/压缩档）——**Cocos 侧，需编辑器探活** |
| `asset.rename` | 按规范批量改名 + 同步引用 |
| `asset.dedupe` | 重复图检测（感知哈希）→ 合并建议 |
| `asset.reference_check` | 配表/预制件/代码引用的资产是否都存在、是否本地 |
| `asset.orphan_check` | 孤儿资产（没有任何引用） |
| `asset.budget_report` | 体积预算报告（按目录/类型/单张排行） |
| `asset.manifest_sync` | 台账同步与校验（工程里的生成物 ↔ 台账） |
| `asset.adopt` | 采用：作业区产物 → 工程目录（+ 可选回写配表列） |
| `asset.audit` | **总门禁**：上面所有检查的合并版，退出码 0/1 |

**界面分区**：报告优先（打开就看到问题排行）+ 批量操作 + 台账表 + 预算配置。
**验收判据**：`asset.audit` 可独立在 CI/命令行跑；故意塞坏数据必须报红。

### 3.7 任务中心（`jobs`）

**定位**：**统一调度的可见面**。人起的、AI 起的作业都在这里，队列、进度、审阅、历史一处收口。

| 能力 id | 功能 |
|---|---|
| `job.list` | 作业列表（来源 = 人/AI、状态、域、耗时、成本） |
| `job.status` / `job.log` | 单个作业的状态与日志 |
| `job.cancel` / `job.retry` | 取消（含进程树）/ 重试（沿用参数） |
| `job.adopt` / `job.reject` | 采用 / 丢弃（可批量） |
| `job.promote` | **把这次作业固化成流程/预设/recipe**（一键复用） |
| `job.prune` | 清理历史与缓存（保留策略） |

**界面分区**：一张队列表 + 详情（参数/日志/产物/降级链）+ 审阅操作 + 统计（成功率、耗时、成本）。
**关键性质**：AI 用 `asset_run` 起的作业**必须**也在这里出现（同一份台账），否则"统一调度"是假的。

### 3.8 设置与提供方（`settings`）

**定位**：你点名要的那个统一配置页。**所有外部依赖只在这里配置一次，功能面板里不出现任何 endpoint/key。**

分区：

| 分区 | 内容 |
|---|---|
| **① 提供方列表** | 卡片式：内置算法 / 本地 ComfyUI / 本地命令行 / 云 API（可多个）/ 离线桩（mock）。每个可启停、可排序（优先级）、显示健康状态与最近一次错误 |
| **② 连接配置** | 每家：`endpoint`、`认证`（keyRef）、`模型清单`、`超时`、`并发`、`重试`、`代理`；ComfyUI 额外：workflow 模板 + 变量注入点；云 API 额外：模型名/版本/区域 |
| **③ 能力路由与降级链** | 表格：能力（或模态）→ 提供方优先级列表。例：`image.generate: [云A, 本地ComfyUI, 内置程序化]`；**失败自动降级并在作业里标 `degraded`，绝不静默** |
| **④ 密钥** | 只显示掩码 + `keyRef`；三级解析 `环境变量 → 本机凭据库 → 加密文件`；**绝不写进工程目录**；「测试连接」按钮 |
| **⑤ 预算与限流** | 每家/每能力：张数、秒数、金额上限（日/月）、并发上限、超限行为（拒绝/降级/排队），超额告警 |
| **⑥ 全局默认** | 输出目录、命名模板、尺寸/体积预算、色板来源、语言、是否需人工采用、是否自动写回配表 |
| **⑦ 预设** | 风格预设（提示词前缀 + 负向词 + 参考图）、参数预设、特效/音频配方；**AI 可以引用预设名**（这样 AI 不用每次重复长提示词） |
| **⑧ 环境诊断** | 探测：node / ffmpeg / chromium / python / 网络 / 各 provider 连通性与 key 有效性；**能力可满足性**（"有 6 个能力当前没有可用提供方"） |

## 4. 统一调用接口（AI 统一调度的核心）

> 这一节是整份方案的技术心脏：**怎么让功能无限增长，而 AI 侧的工具数不变**。

### 4.1 能力注册表（唯一真源）

一份 JSON（工程内可 git；也可由插件内置一份默认）：

```jsonc
{
  "id": "image.generate",                    // 稳定 id，点分命名
  "title": "文生图",
  "domain": "art",                            // → 归属面板
  "summary": "按提示词生成候选图，产出落在作业区，采用后才进工程",
  "params": { "$schema": "…", "type": "object", "properties": {
      "prompt":   { "type": "string", "title": "提示词", "ui": "textarea" },
      "preset":   { "type": "string", "title": "风格预设", "ui": "preset-ref" },
      "size":     { "type": "string", "enum": ["512x512","1024x1024","1024x1536"], "default": "1024x1024" },
      "n":        { "type": "integer", "minimum": 1, "maximum": 8, "default": 4 },
      "seed":     { "type": ["integer","null"], "default": null }
  }, "required": ["prompt"] },
  "outputs": { "type": "array", "items": { "path": "string", "w": "int", "h": "int", "sha256": "string" } },
  "modality": ["image"],                      // → 用来查路由
  "async": true,
  "cost": { "unit": "image", "from": "n" },   // 预算/限流用
  "provider": { "required": true, "kind": "image-gen" },
  "preview": "grid",                          // 面板怎么显示产出
  "adopt": { "into": "assets/resources/<domain>", "writeBack": [{"table":"…","column":"…"}] },
  "examples": [                               // ← 给 AI 的少样本，比长描述有效
    { "note": "生成 4 张浅色几何风图标", "params": { "prompt": "…", "preset": "geometric-light", "n": 4 } }
  ],
  "verify": { "cmd": "assetforge audit --ids image.generate" }   // 可执行判据（对齐自进化"事实环"）
}
```

**这一份注册表同时喂三个消费者**：

| 消费者 | 用法 |
|---|---|
| **面板** | 按 `domain` 分组渲染功能导航；按 `params` schema **自动渲染表单**；按 `preview` 决定产出怎么显示 |
| **CLI** | `assetforge run <id> --params @p.json`，参数校验用同一份 schema |
| **AI** | `asset_capabilities` 直接返回它（或按域裁剪）；`asset_run` 按 id 调用 |

### 4.2 三个统一入口（三侧同一语义）

| 语义 | 面板 | CLI | AI 工具 |
|---|---|---|---|
| **发现** | 打开面板即渲染 | `assetforge caps [--domain ui] [--json]` | `asset_capabilities({ domain? })` |
| **调用** | 点「运行」（表单 → 命令） | `assetforge run <id> --params @file.json` | `asset_run({ id, params, mode: "async" \| "wait" })` |
| **作业** | 任务中心 | `assetforge job ls/status/log/cancel/retry/adopt/promote` | `asset_job({ action, jobId, ids? })` |

**AI 工具面的最终形态**：

```
已有：cocos_execute_code / cocos_describe_api / cocos_editor_state / cocos_capture_view   （4 个，不动）
新增：asset_capabilities / asset_run / asset_job                                          （3 个，永不增长）
```

**这就是"统一调度"的结构保证**（四条性质，每条可断言）：

1. **功能数量与工具数量解耦**：加 50 个功能，AI 侧工具数仍是 7。新增功能只是注册表 + 一个 handler。
2. **"面板上有的 = AI 能做的"**：两者读同一份注册表 → 脚本断言 `面板渲染出的能力集 == caps --json 的能力集`。
3. **AI 的认知负担恒定**：它只需要学 3 个工具 + 读一次 `asset_capabilities` 的输出（含 schema 与 examples）。
4. **参数契约三处不抄第二遍**：JSON Schema 一份，面板/CLI/AI 都从它来（对齐本插件「唯一真源，不许抄第二遍」的纪律）。

### 4.3 编排：能力 → 流程 → recipe

单次调用只是原子；真正的生产是**链**。三层递进：

| 层 | 形态 | 谁用 |
|---|---|---|
| 原子 | 一个 capability | 面板按钮 / AI 单次调用 |
| **流程（flow）** | 具名多步链：`{ steps: [{ id, params, binds: { "input": "$prev.outputs[0].path" } }] }` | 面板的「一键批处理」/ AI 现场编排 |
| **recipe** | 把跑通的 flow 存成可复用文件（本插件已有 recipe 机制，含复用门禁） | 跨会话复用 |

**AI 统一调度的真实形态**：它做的是"**编排 + 判断**"——
`asset_capabilities` 看有哪些原子 → 组一条链 → `asset_run` 逐步跑 → **`read_image` 自己看结果** →
不满意就改参数重跑（同 seed 有缓存，重跑便宜）→ 满意就让用户 `adopt` 或自己 `asset_job adopt` →
最后把整条链 `job.promote` 成 recipe/预设。

### 4.4 能力可以零重启地长出来（与既有自进化路线对接）

本插件的硬约束：改 `dist/**` 要重启编辑器。所以：

| 增长什么 | 落在哪 | 要重启吗 |
|---|---|---|
| 新增一个**能力**（handler + 注册表条目） | 工程内 `.dsh-assets/caps/*.mjs`（CLI 每次调用时按需加载）+ 注册表 JSON | **不要** |
| 新增一个**预设/流程** | 工程内 JSON | 不要 |
| 新增一个**面板**或改面板壳 | `dist/panels/**` | 要（低频） |
| 新增一个 **provider 适配器** | 工程内适配器文件（同 caps 机制） | 不要 |

门禁（防止"能力"变成绕过审查的后门）：① 注册表 schema 必填字段校验；
② handler 必须声明 `params/outputs/examples`；③ **不许直接写 `assets/`**（只能写作业区，采用是独立动作）；
④ 第一次被调用时在回执里注明"来自工程扩展目录"。

## 5. 统一提供方与配置（`settings` 面板的数据模型）

### 5.1 provider 模型

```jsonc
{
  "id": "comfyui-local",
  "kind": "local-comfyui",          // builtin | local-comfyui | local-cli | cloud | mock
  "title": "本地 ComfyUI",
  "enabled": true,
  "priority": 10,
  "endpoint": "http://127.0.0.1:8188",
  "auth": { "keyRef": "COMFYUI_TOKEN", "scheme": "bearer" },
  "modalities": ["image"],           // 它能生成什么
  "models": [ { "id": "sdxl-base", "capabilities": ["image.generate","image.inpaint"], "workflow": "flows/sdxl.json" } ],
  "limits": { "concurrency": 1, "timeoutMs": 600000, "retries": 1, "rpm": 20 },
  "pricing": { "unit": "image", "amount": 0, "currency": "CNY" },
  "health": { "lastTestAt": "…", "ok": true, "note": "8 个模型" }
}
```

### 5.2 适配器清单（设置页里可选的"厂商"）

| kind | 适配对象 | 适配点 |
|---|---|---|
| `builtin` | 插件内置确定性算法（SVG 文法渲染、图像处理、音频合成、切图） | 永远可用、离线、零成本；**是降级链的最后一环** |
| `local-comfyui` | ComfyUI（`/prompt` `/history` `/view` `/object_info` `/ws`） | workflow JSON 模板 + 变量注入；模型清单从 `/object_info` 读；进度走 WebSocket |
| `local-cli` | 任意本地命令行工具（Python 脚本、Real-ESRGAN、rembg、demucs、whisper…） | 用户填：可执行 + 参数模板 + 输入/输出约定 → 变成一等 provider（**这条让插件不必内置所有模型**） |
| `cloud` | 图像（通义万相/Seedream/Gemini/gpt-image/Stability/Krea/Liblib…）、音频（ElevenLabs/火山/MiniMax…）、视频（可灵/即梦/Runway/Veo…） | 每家一个薄适配器（提交/轮询/取结果）；**再加一个"自定义 HTTP"**：用户填 URL/headers/body 模板/响应取值路径 → 未知厂商也能接 |
| `mock` | 离线桩（返回占位图/静音音频） | 让面板与 AI 在**没有任何后端**时也能跑通整条链路（开发、演示、CI） |

### 5.3 密钥口径

**三级解析**：`环境变量 → 本机凭据库 → 加密文件（工程外，权限收紧）`。
工程内只留 `keyRef`（一个名字）。设置页只显示掩码 + 「测试连接」；**永不把 key 写进工程目录**（会被 git 带走）。

### 5.4 路由与降级（"云还是本地"这件事的答案）

用户在设置页配一条优先级链，**功能面板里永远不出现 endpoint/key**：

```jsonc
"routes": {
  "image.generate":  ["cloud:dashscope", "local-comfyui", "builtin:procedural"],
  "image.remove_bg": ["builtin:chroma", "local-cli:rembg"],
  "audio.sfx_synth": ["builtin:synth"],
  "*":               ["builtin:procedural"]           // 兜底
}
```

规则：① 按序尝试；② 失败/超时/超预算 → 下一环；③ **降级必须显式**（作业里标 `degraded: true` + 原因，
面板上给黄标）—— 对齐本插件"失败不静默"的纪律；④ 缓存命中直接返回，不再走 provider（省成本）。

## 6. 面板与编辑器集成

### 6.1 "和 Scene 同 tab 位置"

Cocos Creator 官方支持**一个扩展定义多个面板**（`panels` 字段），面板 `type: "dockable"` 可被拖到编辑器任意分栏。
三条路，从优到退：

1. **`Editor.Panel.openBeside('scene', 'dsh_chat.art')`** —— 直接停到 Scene 所在 tab 组。
   ⚠ **待实测**（编辑器里跑一次即可，不改代码）：`scene` 这个目标名与是否允许落中心区要现场确认。
2. **手动拖**：`Editor.Panel.open('dsh_chat.art')` 打开成浮窗，用户把标签拖到 Scene 旁边；
   dockable 面板的布局编辑器会记住（一次拖完长期有效）。
3. **退路**：做成 `simple` 浮窗 + 域切换下拉（退化成"一个面板多标签"）。

**已知代价要写清楚**：每个面板是**独立渲染进程**；面板轮询只在"可见 且 有作业"时开，
不要 9 个面板各 300ms 轮询一次（那是 9 份 IPC 流量）。

### 6.2 面板壳：为什么面板能薄到"不需要重启也能加功能"

| 层 | 内容 | 改动代价 |
|---|---|---|
| **壳**（进 `dist/`，所有面板共用） | 布局、schema 表单渲染、网格/列表/大图预览、作业条、日志、审阅、体检表 | 改壳 → 重启（低频） |
| **功能**（工程内 JSON + handler） | 有哪些能力、什么参数、什么预览、怎么采用 | 改 JSON → **刷新即生效** |

再叠加本插件**已有**的能力：`scripts/preview-panel.js`（真面板代码 + 真 CSS + 样例数据 → 浏览器里开）。
→ 新面板的开发循环**完全不需要编辑器**，只有"真停靠 / 真消息"那一下要重启验一次。

### 6.3 数据流

```
面板 ──「运行」──► 主进程 ──spawn(系统 node)──► CLI（handler）──► 作业台账（jobs/<id>/）
   ▲                    │                                              │
   └──── 轮询/广播 ──────┴────────────── 进度、日志、产物 ◄─────────────┘
AI ──asset_run──►（同一个 CLI、同一份台账）──► read_image 自检 ──► asset_job adopt
采用 ──► 工程 assets/ ──► 资源库刷新 ──► 可选：回写配表列
落预制件/场景 ──► 复用插件已有的 core/engine 调 cocos_execute_code（人也点得、AI 也调得）
```

### 6.4 面板 ↔ AI 双向

| 方向 | 机制 |
|---|---|
| 面板 → AI | 每个面板/每个产出旁都有 **「交给 AI」**：把当前上下文（域、选中的资产、参数、产出路径）打包成结构化 prompt 发给 agent；agent 未运行时按钮先启动它 |
| AI → 面板 | AI 的作业写同一份台账 → **任务中心与相关面板自动出现**，用户能审阅/采用/丢弃 |
| 断链保护 | agent 没跑时，所有生成/处理功能**照常可用**（它们是 CLI，不依赖 AI）——AI 是增强，不是前置 |

## 7. 数据契约与目录

```
工程内（可 git）：
  .dsh-assets/
    caps/*.mjs                 能力 handler（工程扩展，零重启）
```

## 8. 分批路线（一批一个界面闭环）

| 批 | 交付 | 判据（做完这一批应该能说"这个界面做完了"） |
|---|---|---|
| **0 · 地基** | CLI 骨架 + 能力注册表 + 作业台账 + 三个 AI 工具 + 设置页（含内置 provider 与 mock） | AI 能在没有任何外部模型的情况下跑通"发现 → 调用 → 看结果 → 采用"；面板能渲染 schema 表单 |
| **1 · 美术** | `art` 面板全量能力 + 审阅/历史/before-after | 生成 → 候选 → 采用 → 撤回全通；量化到色板生效；缓存命中 |
| **2 · 资源库** | `assets` 面板 + `asset.audit` 门禁 | 批量压缩/尺寸/格式/图集/引用/孤儿/预算；故意造假数据必须报红 |
| **3 · UI 工作台** | `ui` 面板 + 切图/预制件/反向提取 | 稿 ↔ 层 ↔ 预制件三向往返；面板内可编辑且幂等 |
| **4 · 音频** | `audio` 面板 + 合成/编辑/归一 + 台账 | 6~10 个音效 + 1 段 BGM；响度体检过；可试听 |
| **5 · 动画** | `anim` 面板 + 参数动画/抽帧/对齐/合表/clip | 三源（程序化/视频/逐帧）都能出表；clip 能播；锚点不漂 |
| **6 · 特效** | `vfx` 面板 + 粒子生成/预览/预制件 | plist 能跑；参数与规格一致 |
| **7 · 接外部模型** | 云 / 本地 ComfyUI / 本地 CLI 适配器 + 路由降级 + 预算 | 换 provider 不改功能面板；降级有标记；预算超限被拒 |
| **8 · 任务中心 + 能力自增长** | `jobs` 面板 + `job.promote` + 工程扩展能力目录 | AI 自己新增一个能力并当场调用（不重启）；作业历史可复用成 flow/recipe |

**批间依赖**：0 是地基；1/3/5/6 互不依赖可并行；2 依赖 1 的部分能力 id；7 可以在任意时刻插入（接口先留好）。

## 9. 风险与诚实边界

## 11. 总验收（怎么算这件事做成了）

1. **功能对等**：脚本断言 `面板渲染出的能力集 == assetforge caps --json 的能力集`。
2. **加功能不加工具**：新增一个能力后，AI 的工具清单**条数不变**，`asset_capabilities` 里能看到它，并能直接调通。
3. **AI 独立完成一次真实生产**：例如"做 20 个图标 + 1 段 UI 切图 + 3 个音效"，
   全程只用 `asset_capabilities` / `asset_run` / `asset_job` + `read_image` 自检 + recipe 固化。
4. **人能独立完成同样的生产**：不叫 AI，只用面板，产出与上面等价。
5. **产出可控可追溯**：工程里每个生成物都能追到作业 → 能力 → 参数 → 提供方 → 规范版本。
6. **门禁可跑**：`asset.audit` 退出码 0；故意塞坏数据必须报红。
7. **换后端不改功能**：把 `image.generate` 的路由从云换成 ComfyUI 再换成内置，**功能面板一个字不改**。
8. **离线可用**：断网时第 1~6 批的能力仍然工作（内置算法 + mock 兜底）。
