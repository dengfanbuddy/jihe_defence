## §0 怎么用这份手册描述问题

### 0.1 一句话原则

> **凡是"能被另一个人独立复现或验收"的描述，才是一份好需求。**
> 「优化一下手感」「数值调平衡点」这类说法无法验收，我一定会反问 —— 与其来回，不如按下面模板填。

### 0.2 报 Bug / 描述现象的模板（定位五要素）

```
【场景】哪个场景 / 界面 / 面板（如：局内战斗场景 → 肉鸽商店弹窗）
【时机】什么时候会发生（进关时 / 第 3 阶段刷 Boss 时 / 点确定后）
【条件】需要满足什么前提（英雄是火枪、身上有 3 件遗物、已升级到 5 级）
【现象】你观察到什么（可含具体数字、报错文本、坐标）
【期望】你认为正确的结果是什么
【复现】1… 2… 3…（能稳定复现吗？改了哪张表之后开始出现的？）
【严重度】卡死 / 回不了主界面 > 玩法不可玩 > 数值不对 > 表现瑕疵
【相关】涉及的文件、配表、文档（不确定就写你怀疑的部分）
```

例（可直接抄）：

> 【场景】局内 → 结束面板；【时机】点「确定」；【现象】控制台每帧刷 `Cannot read properties of null (reading 'equals')`，画面卡死在结算界面，回不到主界面；【期望】点确定 → 退回 Scene_Menu；【复现】必现；【严重度】卡死；【相关】`View_Game_Stage.end_title`、结束面板的 `onDestroy`。

### 0.3 描述"规则"的模板（机制七问）

描述一个技能 / 遗物 / Buff / 怪物行为时，把这七项说清就**可以直接落表**：

```
① 对象：谁对谁（施加者是玩家英雄 / 怪物 / 遗物光环）
② 触发：什么条件下发生（受到伤害时 / 每 3 秒 / 击杀时 / 血量低于 30%）
③ 效果：发生什么（改属性 / 造成伤害 / 加状态 / 召唤）
④ 数值与口径：具体数字 + 是固定值还是百分比（本项目：`add` 还是 `percent`）
⑤ 叠加：重复获得怎么办（刷新时长 / 叠加层数 / 并存 / 取最强 / 不叠加）
⑥ 上限与时长：最多叠几层、持续几秒、有没有内置冷却
⑦ 表现：美术/音效/飘字要什么反馈
```

### 0.4 描述"数值"的模板

```
【目标 TTK】普通怪 ___ 秒、Boss ___ 秒
【属性锚点】该单位基准攻击 ___、生命 ___（或"按 1 DPS ≈ 10 HP 换算"）
【成长】每级 ___%（线性 / 指数，底数 ___）
【封顶】该项属性上限 ___
【经济锚点】每分钟产出 ___ 金币，单件道具价格区间 ___ → ___
【参照物】我想让它比「赏金猎人」强 ___%，或与「某怪物」相当
```

### 0.5 描述"美术/资源"的模板

```
【类型】立绘 / UI 切图 / 序列帧动画 / 骨骼动画(Spine) / 粒子特效
【风格】写实 / 半写实 / 卡通 / Q版（几头身）
【规格】画布 ___×___ px、序列帧 ___ 帧 @ ___ fps、动画时长 ___ 秒
【层级/锚点】中心点在哪、要压在谁上面、要不要描边
【交付】png 序列帧 / 图集 / Spine 工程文件 / 尺寸与命名规范
【反馈】打击感要素（顿帧 / 闪白 / 震屏 / 飘字）
```

### 0.6 三个"不要"

| ❌ 不要说 | ✅ 改说 |
|---|---|
| "优化一下手感" | "普攻间隔从 1.2s 降到 0.8s，并加 0.06s 顿帧" |
| "有点卡" | "进入第 3 阶段后掉到 20 FPS，怪物 60 只，飘字层开启" |
| "数值不平衡" | "第 4 阶段怪物 EHP 增长 2.4× 而英雄 DPS 只涨 1.3×，出现输出断层" |
| "加个特效" | "受击时 0.15s 白色闪白 + 0.1s 震屏，幅度 3px" |
| "这个英雄太弱" | "同装备下该英雄对 Boss 的 TTK 是基准英雄的 1.8 倍" |

## §2 策划 · 通用设计术语

### 2.1 体验与结构

| 术语 | 英文 | 含义 | 本项目的例子 |
|---|---|---|---|
| 核心循环 | Core Loop | 玩家反复做的最小闭环 | 打怪 → 掉金 → 买道具 → 变强 → 打更难的怪 |
| 局内循环 / 局外循环 | In-run / Meta Loop | 单局内的循环 vs 跨局成长循环 | 局内：刷怪升级抽卡；局外：装备收集 |
| 心流 | Flow | 挑战与能力刚好匹配的沉浸状态 | 阶段难度曲线贴着英雄成长走 |
| 难度曲线 | Difficulty Curve | 难度随时间的增长形状 | 阶段系数底数 1.05~1.15 |
| 节奏 / 张力曲线 | Pacing / Tension Curve | 松紧交替的起伏设计 | 波次间隙 → 商店 → Boss |
| 正反馈 / 负反馈 | Positive / Negative Feedback | 强者更强 vs 自我修正（追赶机制） | 击杀商店 Buff = 正反馈；阶段门槛 = 节流 |
| 爽点 | Payoff | 强烈正向反馈的时刻 | 满配暴击秒 Boss、遗物联动成型 |
| 摩擦 / 阻塞 | Friction | 阻碍玩家的设计（未必是坏事） | 抽卡费用递增 = 决策摩擦 |
| 上手成本 | Onboarding Friction | 学会玩所需时间 | 新手引导、首局体验 |
| 首局体验 | FTUE (First-Time User Experience) | 第一次进入游戏的完整体验 | `Loading → Main → Scene_Menu → 第一局` |
| 引导 | Tutorial / Guide | 教玩家操作与规则 | `platform/guide/` |
| 深度 vs 复杂度 | Depth vs Complexity | 易学难精 vs 难以理解 | 遗物 293 件但规则统一 |
| 涌现 | Emergence | 简单规则组合出复杂玩法 | 遗物 × 技能 × 属性的组合 |
| 策略退化 | Degenerate Strategy | 存在一套无脑最优解 | 唯一最优 build → 需削弱或加代价 |
| 主导策略 | Dominant Strategy | 明显强于其他选择的打法 | 同上 |
| 决策点 | Decision Point | 玩家必须做选择的时刻 | 三选一抽卡、是否花广告次数 |
| 风险回报 | Risk / Reward | 高风险的收益设计 | 花金币刷新抽取 vs 攒钱升级 |
| 可读性 | Readability | 玩家能否一眼看懂局面 | 飘字配色/字号分级 |
| 信息层级 | Information Hierarchy | 重要信息更醒目 | 血条 > 金币 > 警告 |
| 手感 | Game Feel | 操作到反馈的延迟、力度、清晰度 | 普攻间隔、顿帧、震屏 |
| 打击感 | Hit Feel / Impact | 命中的"重量"反馈组合 | 伤害飘字 + 闪白 + 顿帧 + 震屏 |
| 容错 | Forgivingness | 允许玩家犯错的余量 | 英雄被小怪打 3~8 下才死 |
| 死亡螺旋 | Death Spiral | 劣势自我放大到必败 | 掉血 → 打不动 → 更掉血 |
| 毒性组合 | Toxic Combo | 规则叠加出破坏体验的 bug 级组合 | 无敌 + 吸血 + 无限叠层 |

## §3 策划 · 数值术语（锚点 / 预算 / 曲线 / 乘区）

> **这一节是数值沟通的核心。** 你举的"经济锚点""属性锚点"就在这里。
> 本项目的落地口径（哪个文件、写成 int 还是 float、用 add 还是 percent）见 `docs/数值配置参考手册.md`。

### 3.1 数值体系的三层结构

```
① 锚点（Anchor）      →  先钉死基准点：不变量、汇率、目标时长
② 预算（Budget）      →  每个单位/装备/波次能花多少"战力点"
③ 条目（Entry）       →  具体填进配表的属性与数值
```

**锚点是最上游的**：锚点一变，下面全变；条目改了不影响锚点。沟通时先说"我要改哪一层"。

### 3.2 锚点（Anchor）—— 类型全表

| 锚点类型 | 别称 | 它钉住的是什么 | 本项目已用的取值（见 `docs/数值配置参考手册.md` §3.1） |
|---|---|---|---|
| **属性锚点** | 属性基准 / 数值基准 | 一组基准属性的绝对量与相互关系 | 某英雄 5 级时 攻击 __、生命 __；全项目 1 DPS ≈ 10 HP |
| **经济锚点** | 产出锚 / 收入锚 | 单位时间产出 与 单位价格 的兑换关系 | 一局 ≈ N 分钟产出 M 金币；抽取费用 50→200 封顶 |
| **战斗时长锚点** | TTK 锚 | 一次击杀该花多久 | 普通怪 **0.5~3 秒**；Boss **10~30 秒**（收官 30~60s） |
| **手感锚点** | 容错锚 | 玩家有多少反应窗口 | 怪物打死英雄需要 **3~8 下** |
| **成长锚点** | 等级锚 | 每级/每阶段的增幅 | 每级经验需求底数 ×1.10~1.20 |
| **难度锚点** | 压力锚 | 阶段间难度增长倍率 | 难度指数底数 1.05~1.15（HP/伤害分开给） |
| **天花板锚点** | 封顶 / Cap | 属性的硬上限 | 暴率 ≤60%、闪避 ≤40%、攻速 ≤3.0、局外总膨胀 ≤+50% |
| **汇率锚 / 等价锚** | 换算锚 | 不同属性的"等价交换率" | **1% 暴率 ≈ 2% 暴伤**；1 DPS ≈ 10 HP |
| **参照锚** | 基准单位 | 用来对比的标杆对象 | "以赏金猎人为基准英雄""以普通怪为 1.0 强度" |

**为什么必须先定锚点**：① 单一真源（以后所有数值都能反推）；② 可回归（改完能算出偏差多少）；③ 可沟通（"这比锚点强 30%"比"感觉强一点"清楚）；④ 防通胀（有封顶才不失控）。

### 3.3 预算（Budget）—— 锚点的下游

| 术语 | 含义 | 例子 |
|---|---|---|
| 战力预算 | 一个单位总共能有多少"价值点" | 一件红装总预算 = 2.5 × 白装 |
| 属性等价 / 战力等价 | 把不同属性折算成同一分值 | 1% 暴率 = 2% 暴伤 = X 战力点 |
| 分配比例 | 预算拆到各属性的比例 | 输出 60% / 生存 30% / 功能 10% |
| 品质阶梯 | 稀有度间的预算倍率 | 白→红：×1.0 / 1.3 / 1.6 / 2.0 / 2.5 |
| 波次预算 | 一波怪的强度总和 | 第 N 波 = 基准怪 × 数量 × 难度系数 |
| 局外/局内预算分离 | 永久乘区 vs 单局乘区 | 局外养成总膨胀 ≤ +50% 永久乘区 |

### 3.4 战斗数学口径（沟通数值时必须统一的公式）

| 术语 | 英文 / 公式 | 说明 |
|---|---|---|
| DPS | Damage Per Second = 攻击力 ÷ 攻击间隔 | 普攻持续输出 |
| 爆发 | Burst | 短时间内的集中输出 |
| 期望伤害 | EV = 单发 × (1 + 暴率 × (暴伤 − 1)) | 含暴击后的数学期望 |
| 有效生命 | EHP = HP ÷ (1 − 减伤) | 生存能力的统一度量 |
| 有效 DPS | Effective DPS = DPS 期望 × (1 − 目标减伤) × 增伤倍率 | 实际打出去的输出 |
| TTK | Time To Kill = 目标 EHP ÷ 有效 DPS | 击杀耗时，手感的核心输入 |
| 减伤 | DR = 护甲/(护甲+k)，或 Dota 双曲式 `0.06a ÷ (1 + 0.06 × abs(a))` | **本项目代码用 Dota 式**，配表里的 `defenseFormula` 字符串未被消费 |
| 命中期望 | 命中率 × 命中效果 | 闪避/未命中会摊薄输出 |
| 溢出伤害 | Overkill | 超出剩余血量的部分（浪费或刻意） |
| 期望与方差 | EV / Variance | 平均值 vs 波动；**方差决定体感**（脸黑/欧洲） |
| 下限 / 上限 | Floor / Ceiling | 最差与最好情况，用于反推极端值安全性 |
| 边际收益 | Marginal Gain | 再投 1 点资源换来的收益增量 |
| 收益递减 | Diminishing Returns | 投入越多单位收益越低（护甲天然如此） |
| 破防点 / 阈值 | Breakpoint | 越过某数值后质变（如攻速档位、减伤 70%） |
| 档位 | Tier / Step | 离散化的取值点（攻击间隔量化到帧） |
| 数值密度 | Stat Density | 单位时间里玩家获得多少数值成长 |

### 3.5 叠加与结算规则（**最容易沟通翻车的一项**）

| 术语 | 本项目枚举 `AttributeStackMode` | 公式 | 配置写法 |
|---|---|---|---|
| 固定值 / 加法 | `add` | `final = base + Σv` | 原值（缩放型属性 ×100） |
| 百分比（加算） | `percent` | `final = base × (1 + Σv/100)` | **百分数**：`14` = +14% |
| 乘法（乘算/复利） | `multiply` | `final = base × Π(1+v)` | **小数**：`0.14` |
| 补数乘法 | `complement` | `final = 1 − (1−base) × Π(1−v)` | 用于魔抗/闪避这类"永远到不了 100%" |
| 取最优 | `best` | `final = max(base, v…)` | 用于暴击倍率等"取最大"语义 |

**乘区（Damage Bucket / Multiplier Zone）**：伤害由若干个**独立相乘**的因子构成。
本项目大致为：`攻击力 → 增伤倍率 → 暴击 → 目标受伤倍率 → 护甲/魔抗减免`。

| 术语 | 含义 | 陷阱 |
|---|---|---|
| 同一乘区内加算 | 同区多个来源相加 | 越多越不划算（收益递减） |
| 不同乘区间乘算 | 独立乘区互相放大 | 堆同一属性不如分散堆 |
| 独立乘区 / 最终乘区 | 单独一项、只此一处 | 极强，需谨慎投放 |
| 加算与乘算之争 | "是 +20% 还是 ×1.2" | **本项目遗物百分比一律用 `percent`（对基础值加算，不复利）** |

### 3.6 成长与曲线术语

| 术语 | 形状 / 公式 | 用途 |
|---|---|---|
| 线性 | `y = a + b·x` | 直观、后期偏弱 |
| 分段线性 | 多段不同斜率 | 常见于等级经验 |
| 指数 | `y = a·r^x`（r = 底数） | 成长与难度膨胀（本项目 exp 底数 1.12~1.18） |
| 幂函数 | `y = a·x^p` | p<1 递减、p>1 加速 |
| 对数 | `y = a·ln x` | 强递减，用于长线收益 |
| S 曲线 | 慢—快—慢 | 引导期与封顶期 |
| 天花板 | Ceiling | 明确上限（防无限成长） |
| 软上限 / 硬上限 | Soft / Hard Cap | 软上限边际递减、硬上限直接截断 |
| 数值膨胀 | Power Creep | 新内容整体强于旧内容导致旧内容作废 |
| 数值断层 / 悬崖 | Cliff | 某阶段难度骤增（体验杀手） |
| 通货膨胀 | Inflation | 货币产出 > 消耗，钱不值钱 |
| 通缩 | Deflation | 消耗 > 产出，玩家攒不起 |

### 3.8 常见"数值病"（描述问题时的诊断词）

| 病名 | 症状 | 诊断口径 |
|---|---|---|
| 刮痧 | 打不动，TTK 过长 | 有效 DPS 远低于目标 EHP |
| 被秒 | 无反应窗口 | 单次承伤 > 容错锚点 |
| 数值爆炸 | 后期数字失控 | 指数底数过大或乘区叠加过多 |
| 一刀 999 | 无策略的数值碾压 | 主导策略存在 |
| 最优解唯一 | 没有选择空间 | 决策点退化 |
| 断层 / 悬崖 | 某关卡突然打不过 | 阶段系数跳变 |
| 无意义选择 | 选项强弱差距过小 | 差异 < 感知阈值（经验值 ~10%） |
| 通货膨胀 | 金币用不完 | 产出 >> 消耗，缺"下水道" |
| 通缩 | 永远买不起 | 产出 << 价格梯度 |
| 死亡螺旋 | 劣势不可逆 | 缺负反馈/追赶机制 |
| 空转 | 后期无事可做 | 成长曲线早于内容曲线封顶 |

### 4.2 经济设计的三问（沟通经济时先答）

1. **产出**：玩家每分钟赚多少？（来源 + 数值）
2. **消耗**：他必须花在哪？花不完会怎样？（下水道清单 + 价格梯度）
3. **汇率**：1 单位货币换多少战力？（等价锚点，防通胀）

> 经济锚点的本质就是第 3 问：**把"时间"锚定成"资源"，再把"资源"锚定成"战力"。**

同一句中文在不同语境下是完全不同的东西。**说的时候请带上语境，或直接用右列的准确说法。**

| 词 | 语境 A | 语境 B | 语境 C | 建议说法 |
|---|---|---|---|---|
| **锚点** | 数值锚点：设计基准点/汇率 | UI 锚点：节点缩放旋转的参考点（Cocos Anchor） | 参照物：用来对齐的基准对象 | "数值锚点" / "UI 锚点" / "基准单位" |

| **池** | 对象池（复用实例） | 道具池/卡池（抽取候选集） | 资源池（内存缓存） | "对象池" / "抽取池" |

## 附：使用建议

1. **提需求前**先过一遍 §0 的模板，能省掉 80% 的来回确认。
2. **改数值前**先确认三层里的哪一层：锚点（§3.2）→ 预算（§3.3）→ 条目（配表）。
3. **说"手感/打击感/爽"** 时，用 §7.5 的词替换掉形容词。

5. **同一个词意思说不通**时查 §9。
6. 本手册只管**术语**；术语对应的**项目口径**（哪些数能改、改了要不要回灌 Excel）永远以 `AGENTS.md` 与 `docs/数值配置参考手册.md` 为准。
