尼尔《机械纪元》UI · 借鉴对照板

配套文档：docs/art-style/nier-ui-reference.md。本板只做一件事：把 6 组「现在的做法 / 借用后的做法」并排画出来。 颜色全部取自 docs/art-style/tokens.json；圆角只用 4/8/16；零阴影、零渐变、零发光、零纹理、零 emoji（§10）。 面板底用 #EFEEED（局外纸面）与 #EBF4FB（局内战场）区分两个界面族。

1

离散量读数：连续条 → 分段刻度

B1 · 小改造

尼尔把数得清的量画成方格读数，把连续的量留给条。判据：技能 max_level、成就 tier、遗物份数、Boss 库存 → 分段刻度； HP / EXP / 倒计时 → 保持连续条。不要把 HP 条改成分段，那会把"还差几格"的语义用错地方。

现 在
技 能Lv 2/3
成 就银 2/3
库 存x2/3
借 用 后
技 能Lv 2
成 就银
库 存2

落点：SkillSlot.ts · AchievementItem · View_Game_Stage 的 Boss 条目 count。 新登记项：格 9×9 + 间距 4（这是我唯一要求新增的间距档，见文档 §8-2）。

2

状态表意：换颜色 → 换字重 + 形状

A1 · 直接采纳

尼尔监督的原始指令是"尽量避免使用大范围的色彩"，于是设计师改用字体的粗细与深浅表达状态变化。 我们现状是就地发明颜色：技能详情的「当前等级」染了一个没登记进 §1 的绿；Boss 条目的「场上限时」借用了英雄受击红（§10 明写这个通道已被"打谁"占用）。

现 在
lv.1攻击力 +14%
lv.2攻击力 +22%← 绿字 = 当前级
lv.3攻击力 +30%
Boss01:12← 红字 = 限时
借 用 后
lv.1攻击力 +14%
lv.2攻击力 +22%
lv.3攻击力 +30%
Boss01:12+ 前置小三角 = 限时

落点：SkillDetailPanel.ts:25（删掉 ACTIVE_LEVEL_COLOR）· View_Game_Stage.ts:21-26 · AbilityDesc.ts 的 +N%/-N%。 连带：tools/skill-slot-audit/audit.mjs:457 的 GREEN 期望值要一起改 —— 那条体检正在保护这个违规。

3

数据行：三件挤一行 → 左标签 / 右等宽数字

A3 · 直接采纳

尼尔的基本单元是「细线框 + 左上角小标签 + 右侧读数」：标签极小、字距很宽，数值等宽右对齐，中间用极淡的引导线连起来。 我们现在是"图标 + 条 + 当前/上限 三者水平对齐挤在一行"，扫读时眼睛要来回找。

现 在
300/300
48/64
借 用 后
最 大 生 命300/300
最 大 魔 法48/64
攻 击 距 离2.20 m

落点：英雄详情弹窗 Cmp_HeroDetail 的属性行（HERO_DETAIL_ATTR_ROWS 那 5 行）· 结算面板 · 遗物详情。 代价：改框尺寸的 Label 先用场景侧助手 labelFit 算一遍会不会裁字（AGENTS.md 已规定）。

4

母题：装饰线 → 图纸语法（图框 / 标题栏 / 尺寸线）

A2 · 直接采纳

尼尔靠「乐谱」这一个母题把扁平设计救活（五线谱、低音谱号、乐曲结束的双小节线）， 设计师的原话是"太执着于扁平化，设计会变得干瘪而没有灵魂"。 我们的母题早就写在 §0 里了 —— 工程图纸（"参考的物：蓝图与工程图纸"），只是从没变成语法。 下面这套零新增颜色、零新素材。

现 在
第 3 阶段
只有一条 1px 灰分隔线。再问"这里该放什么装饰"就只能加颜色或加图标。
借 用 后

六件套：图框 / 裁切角 · 标题栏（图号·版本·比例 = 一个天然的元信息容器）· 尺寸线（两端箭头 + 中间断口写数值）· 引出线（标注与 tooltip）· 圆圈编号（序号 / 技能槽角标）· 剖面线（禁用 / 未解锁 / 空槽，替代现有的纯灰底）。 注意：剖面线用 SVG <pattern> 斜线实现，不是 CSS 渐变 —— 不触碰"禁渐变"。

5

破损态：唯一允许的情绪破格

C1 · 需拍板

尼尔最有名的 UI 语言之一是自爆之后那套"坏掉了"的界面 —— 克制到极点的设计只留一个破格口子。 我们的禁用清单禁的是发光 / 粒子 / 后处理 / 纹理，不禁"线稿的缺失" —— 所以在浅底图纸风里，破损态可以零新色、零新素材、零新特效地做出来。 建议只用在两处（失败结算 / 濒死），幅度极小。

正 常 状 态
破 损 态（幅 度 极 小）

四件破损语汇：图框缺一段 · 虚线断裂 · 读数被划掉（唯一用 c-danger #C0392B 细线的地方）· 尺寸线箭头错位 1~2px。 风险：做过头会变成"故意做旧"，与"干净图纸"冲突 —— 建议先只在阵亡结算面板做一处看观感。

6

HUD：写死的画布 → 玩家可关 + 三套预设

B2 · 小改造

尼尔把 HP 条 / 经验条 / 小地图 / 伤害数字 / 敌血条 全做成插件芯片：拔掉就真的不显示，还能存三套预设随时切。 只借结论，不借机制（"占容量"会和我们的遗物系统语义打架）。 我们的 View_Game_Stage 现在挂了 12+ 个元件，打击反馈 B2/B3 又往屏幕上加了印痕层 / 连击 / 落款 / 角标 / 墨闪 —— 再加就该有人喊停了。

核心信息（建议恒开） 可选信息（可关） 表现层（可关，关了不掉信息）

简洁

小屏 / 老手 / 录屏

标准 （默认）

大多数玩家

全部

想看清一切的玩家

落点：新增 game/common/HudPrefs.ts（纯 TS 无 cc，存 DataModule）+ View_Game_Stage 按它写 active； HitScreenLayer / HitVfxLayer 的开关也归它管（那两层现在无条件画）。顺带收益：低端机去掉两层 Graphics = 实打实的填充率。 建议不给游戏内好处（尼尔是给容量的）—— 纯无障碍，避免和遗物系统的"装载预算"语义撞车。

三个提醒
① 本板是参考研究，不改变规范。视觉口径的唯一权威仍是 docs/美术风格预设.md；采纳要走文档 §8「待拍板」。
② 尼尔的米色不要抄：它比我们深（社区取样 ≈ #B0AB98），低对比是靠"大屏 + 暗环境"撑住的，手机小屏会糊。我们的 #EFEEED / #EBF4FB 更亮是对的。
③ 第 2 组的绿字不要直接删：audit:slot 的检查项 ⑯ 把 34,177,76 钉成了期望值，改色必须连测试判据一起改，否则下一个人会以为是自己改坏的。
