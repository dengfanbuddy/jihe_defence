# 尼尔《机械纪元》UI 拆解 · 我们能借鉴什么

> **本文定位**：**参考研究**，不是规范。视觉口径的唯一权威仍是 `docs/美术风格预设.md` ——
> 本文只回答两个问题：**尼尔这套东西是怎么想出来的**、**里面哪些能搬进《集合防御》，落到哪个文件/节点**。
> 采纳与否见 §8「待拍板」，拍板后才回写进《美术风格预设》。
> **配套**：`docs/art-style/nier-borrow-board.html`（可双击打开的对照板：6 组「现在的做法 / 借用后的做法」并排看）
> **一句话结论**：**结构上我们和尼尔是同源的，纪律上我们比尼尔松得多** —— 该借的全是"纪律"，不是"外观"。

---

## 0. 先破一个流传很广的误读

很多人对尼尔 UI 的印象是**黑底白字**（游戏开场、标题画面、"YoRHa" 启动序列），于是得出"尼尔是暗底极简"。
**那是错的**：**真正的系统菜单是一整片暖米色浅底**，扁平、大量留白、细线分隔、墨色字。
设计师貴島久芳（Hisayoshi Kijima）写得很清楚——他接到的第一条需求就是横尾太郎的
「**做成好看的、温暖的米色**」；他自己是先画了一版**高对比黑白**，再一步步推向米色的。

| | 尼尔 · 系统菜单 | 集合防御 · 局外 | 集合防御 · 局内 |
|---|---|---|---|
| 底色 | 暖米色（社区取样 ≈ `#B0AB98`/`#C3BDA8`，**偏深**） | `#EFEEED` 暖米白 | `#EBF4FB` 冷蓝白 |
| 文字 | 墨色 / 近黑 | `#445054`~`#000000` | 同左 |
| 强调 | **1 个**低饱和红橙 | 青绿 4 档 + 暗红 | 同左 + 品质/档位/金币 |

→ **结构完全同源**（浅底 + 墨字 + 极少彩色 + 扁平无阴影），这正是我们敢大段借鉴的前提。
→ ⚠ **但米色不要抄**：尼尔的米色比我们**深**，它的低对比是靠「大屏幕 + 暗环境」撑住的；
手机小屏 + 户外光下会直接读不清。我们 §1.4 的「浅底可读」比尼尔更狠，**这是我们的优点，别退回去**。

## 1. 尼尔 UI 的六条一手事实

来源：白金工作室官方博客《UI Design in NieR:Automata》（貴島久芳 自述，[原文](https://www.platinumgames.com/official-blog/article/9624) /
[中文翻译](https://indienova.com/indie-game-development/ui-design-of-nier-automata/)）。这一节只写**设计者自己说过的**，不做二次演绎。

### 1.1 三条来自监督的原始指令（最值钱的部分）

| 指令 | 原文大意 | 这条指令的**真正含义** |
|---|---|---|
| **米色** | "做成好看的、温暖的米色" | 先定**一个**基调，再让所有东西服从它 |
| **少用色** | "想尽量避免使用大范围的色彩" | 于是"在不影响信息显示的前提下，**改变字体的粗细和颜色深浅**来表示状态变化"；非用不可时**只限一个低饱和红橙** |
| **奶奶也能用** | "菜单操作简单到不常玩游戏的人、**我的奶奶**也能用" | 全功能只用**摇杆 + O/X** 可达；屏上操作提示**最多讲三条**；给老手留**隐藏快捷键但不写进提示** |

> **注意第二条的因果**：不是"尼尔顺便少用色"，是**"为了少用色，才发明了用字重和明度编码信息"**。
> 先有约束，后有手法。我们 §10「一屏不许出现第三种强调色」是同一条约束 —— 但我们**只抄了禁令，没抄解法**。

### 1.2 设计过程：扁平 → 怕干瘪 → 加一个「象征母题」

貴島的原话是关键：**"如果太执着于扁平化，最终设计会变得干瘪而没有灵魂。"**
他的解法不是加特效，而是**从乐谱里借象征**：五线谱、低音谱号、**乐曲结束的双小节线**，
以及**游戏标题和辅助机台词里的冒号**（同样是乐谱符号）。
**不做直接挪用，而是象征性暗示**；菜单上下缘的装饰则沿用了前作《人工生命》的边框，
用这种"模拟感"来调**幻想与科幻的比例**。

> **这就是"母题（motif）"**：一套**不增加颜色、不增加素材**的装饰语法，
> 每个"这里该画什么"的问题都由它回答。尼尔用乐谱，我们用**工程图纸**（见 §6）。

### 1.3 扁平之外的两笔"拟物"

在扁平设计上叠了**极淡的网格纹理** + **屏幕边缘的失真与明暗处理**，
让菜单看起来像显示在一台**凸面显像管**上 —— 设计师自称这是让扁平设计"活起来"的拟物化处理。
另外他特意把动效调成看起来**"湿润"而不是干瘪**（原话：a little "moist"），菜单呼出时的流动感是他最满意的部分。

> ⚠ **这两笔我们一条都不能抄**（网格 = 纹理禁令、失真 = 后处理/移动端填充率），
> 但"**动效要有湿度**"这个**目标**可以抄 —— 见 §4-B4。

### 1.4 组件与版式的既有形（社区设计系统取样）

一份非官方的复刻设计系统（[NieR-Automata-Design-System](https://github.com/Kndgy/NieR-Automata-Design-System)）
把菜单组件归纳成：`Widget`（**框 + 标题 + 内容 + 一个 `lvl` 读数**）、`Bar`（Light / Dark 两态）、
`NavLink`（button / nav / transparent / neutral 四变体）、`ScrollElement`、`Footer`。
→ 可见它的基本单元就是「**一个细线框，左上角标签，右侧读数**」，字号极小、字距很宽、大量留白。

### 1.5 HUD 本身是"装备"（最反直觉、也最该借的一条）

尼尔的**每一个被动能力都是一枚插件芯片**；而**显示 HP 条、经验条、小地图、伤害数字、敌人血条、
声音指示、分数显示的那些芯片，也是插件芯片** —— 拔掉它，屏幕上的那一块就真的消失。
芯片占一个**存储容量预算**，于是"要小地图"意味着"少一枚防御芯片"。
玩家还能存 **A/B/C 三套预设**随时切换（战斗套精简 HUD / 探索套全开）。
极端情况：死亡掉芯片、二次死亡永久丢失 —— 有玩家**把小地图消失当成 bug**，其实是上一次死亡的后遗症。
（机制细节见 [Plug-in chips](https://saschb2b.github.io/game-mechanics/games/nier-automata/chip-system)）

> **要借的是结论，不是机制**：**HUD 元件应该是玩家能关的、并且有预设**。
> 抄"占容量"会和我们自己的遗物系统正面打架 —— 那是尼尔的机制，不是它的 UI 语言。

### 1.6 破格：一个"坏掉的 UI"

横尾的第一条需求其实是「**加一点怪东西**……已经有太多游戏 UI 很正常了，我要做一个怪的」。
最终落地成两处：**自爆功能之后整套 UI 呈现"坏掉了"的状态**，以及**三周目里一段战斗的怀旧滤镜**。
—— 一个克制到极点的设计，**只留一个情绪破格的口子**，而且这个口子本身是叙事的一部分。

## 2. 我们 vs 尼尔：逐维度对表

| 维度 | 尼尔 | 集合防御（实测） | 判定 |
|---|---|---|---|
| 底色 | 暖米色（偏深） | 近白（暖/冷两区） | **我们赢**，别退 |
| 扁平无阴影 | ✅ | ✅（§10 硬禁） | 平 |
| **彩色 token 数** | **≈1**（+极少量白与淡绿） | **≈20**（青绿 7 + 暗红 1 + 品质 4 + 档位 3 + 金 2 + warn 1 + 禁用 1 + 受击 1） | **尼尔赢，差距最大** |
| **信息编码手段** | 字重 / 明暗 / 形状 | **大量依赖颜色** | **尼尔赢** |
| 装饰语法 | 有母题（乐谱） | **无母题**（只有颜色与圆角规范） | **尼尔赢** |
| 形状语言 | 直角、细线框、仪器感 | 圆角 4/8/16、药丸按钮 | 我们保留（改动面 60+ 预制件），借"角"补仪器感 |
| 层次/留白 | 极简、边缘化 | ✅ 大留白 | 平 |
| **HUD** | **玩家可装可卸 + 三套预设** | **固定写死在预制件里，还在加** | **尼尔赢** |
| 操作收敛 | 摇杆+O/X 全功能、提示≤3 | 部分达成（"全屏页只有一颗实心按钮"、返回自关） | 半平 |
| 情绪调性 | 疏离 / 悲哀 / 存在主义 | 明快青绿 / 纸面图纸 | **我们赢**，只借结构不借情绪 |

**一句话**：**结构我们赢了，纪律我们输了。** 所以"借鉴"的正文是纪律，不是外观。

## 3. 现役证据：我们的颜色纪律漏在哪（都可复现）

不是假想问题，是工程里现在跑着的代码：

| 位置 | 现状 | 违反了哪条 | 尼尔的解法 |
|---|---|---|---|
| `SkillDetailPanel.ts:25` | `ACTIVE_LEVEL_COLOR = Color(34,177,76)` = `#22B14C` —— 技能详情里「当前等级」的标签染**中饱和绿** | 这是一个**未登记进 §1 的第四种强调色**（§10：「界面里出现新的青绿/墨色必须先进 §1」）；浅底上还和"可点"的青绿打架 | 当前级用**字重 + 前置标记**（实心菱形/加粗/左侧竖条），不换色 |
| `tools/skill-slot-audit/audit.mjs:457` | `const GREEN = '34,177,76'`，检查项 ⑯ 把它**钉成期望值** | 体检脚本在**保护这条违规** | 判据改成"当前级 = 加粗 + 标记"，测试跟着改 |
| `View_Game_Stage.ts:23` | `BOSS_TIME_LIMIT_COLOR = Color(255,76,76)` = `#FF4C4C` —— Boss 条目「场上限时」用**英雄受击色**当警示 | §10 明写「颜色通道已被"打谁"占用」；同一个红现在既表示"我掉血"又表示"快点处理" | 限时态用**形状/位置/字重**（加粗 + 前置小三角 + 倒计时框）表达紧迫 |
| `View_Game_Stage.ts:25` | `BOSS_COUNT_IDLE_COLOR = (160,160,160)` | 又一个不在 ramp 上的灰（`c-ink-400` 是 `#999999`） | 归并到 ink ramp |
| §9-1 / §9-2 / §9-13 | 青绿四胞胎、墨色两调、**金币图标四套色** | 同族色重复 | 每族收敛到 2 档，其余用明度/字重区分 |
| §9-5 / §1.8 | 品质 4 档 + 档位 3 档都靠**色相** | 浅底上色相差异在小尺寸下会糊 | 档位**靠形状与位置**（刻度条、角标数量），色只做**细线**（成就卡 2026-11 已按这条落地 ✅） |

> **共同点**：每一处都是"**一件事找不到非颜色的表达方式，于是就地发明了一个颜色**"。
> 尼尔那条铁律（**先约束颜色，再发明非颜色编码**）正好是这六处的统一解法。

## 4. 借鉴清单（按性价比排序）

### A 档 · 直接采纳（零风险、零新素材、当轮可落）

**A1. 把"用字重与明度代替颜色"立成硬规则**
- **借什么**：尼尔监督的原始指令 + 貴島的落地手法（**改变字体粗细与深浅**表示状态变化）。
- **立成什么规则**（建议写进《美术风格预设》§4 排版）：
  | 语义 | 表达 | 禁止 |
  |---|---|---|
  | 常态数值 | `c-ink-600` 常规 | — |
  | 生效 / 加成 / 当前档 | `c-ink-900` **加粗** + 前置**实心小菱形** | 换色（含绿字） |
  | 未生效 / 未解锁 / 已超限 | `c-ink-400` + 前置**空心菱形** | 只用变灰（对比度不够） |
  | 警示（唯一彩色） | `c-danger` `#C0392B`，**只许文字与细线** | 铺面、做底、做环 |
- **落点**：`SkillDetailPanel.ts`（绿字 → 加粗+标记）、`View_Game_Stage.ts` Boss 条目（红字 → 形状）、
  遗物/技能描述里的 `+N%` / `-N%`（`AbilityDesc.ts` 现在输出纯文本 `攻击力 +14%`，染色是上层的事，正好在这层定规矩）。
- **代价**：改预制件颜色 + 改 `audit:slot` 的 ⑯ 判据。**无新素材。**

**A2. 抽象出我们的"母题"：工程图纸**（详见 §5）
- **借什么**：尼尔用乐谱母题把扁平设计"救活"的思路 —— **一个母题回答掉所有装饰问题**。
- **我们的母题不是乐谱，是图纸**（`docs/美术风格预设.md` §0 已经写着"参考的物：蓝图与工程图纸"，只是从没变成语法）。
- **产出**：§5 的六件套（图框 / 标题栏 / 尺寸线 / 引出线 / 圆圈编号 / 剖面线），**零新增颜色**。

**A3. 数据行的标准形：小号宽字距标签（左） + 等宽数字（右对齐）**
- **借什么**：尼尔 `Widget` = 「细线框 + 左上角小标签 + 右侧 `lvl` 读数」这个基本单元。
- **落点**：英雄详情弹窗属性行（`Cmp_HeroDetail`）、结算面板、遗物详情、成就卡读数。
  我们现在是"图标 + 条 + `当前/上限` 挤一行"，改成**左标签 / 右等宽数字**两栏对齐，一屏的"仪器感"立刻出来。
- **代价**：纯版式 + 一个 `labelFit` 复核（AGENTS.md 已规定改框尺寸要跑它）。

### B 档 · 需要小改造（1~3 天，仍无新素材）

**B1. 离散量用"分段刻度"读，连续量才用条**
- **借什么**：尼尔那套**方块读数**（数得清的东西画成方格，而不是一根平滑的条）。
- **判据（建议写死）**：
  | 量的性质 | 画法 | 我们的落点 |
  |---|---|---|
  | **离散、数得清** | **分段刻度**（`▮▮▯`） | 技能 `max_level` 1~3（`SkillSlot`）、成就 `tier` 1~3、遗物**份数**、Boss **库存** `x3`、难度 100 档（已是格阵）、背包 80 格（已是格阵） |
  | **连续、无级** | 条（现有 `ProgressBar`） | HP / EXP / 阶段倒计时 |
- **为什么值**：① 分段天然回答"还差几格"，连续条要靠读数字；② 方块是**图纸语汇**（网格纸上的格），
  比平滑条更贴母题；③ **纯 Graphics/Sprite 九宫格，零新素材**。
- **落点**：`SkillSlot.ts`、`AchievementItem`、`View_Game_Stage` 的 Boss 条目 `count`。
- ⚠ **不要把 HP 条改成分段** —— 尼尔的 HP 也是连续条，分段的语义是"数得清的量"，用错就变成噪音。

**B2. HUD 元件可关 + 三套预设**（借 §1.5 的结论，不借机制）
- **现状**：`View_Game_Stage` 已挂 12+ 个元件（头像格 / HP / EXP / 阶段倒计时 / Buff 行 / 武器 4 格 /
  暂停退出 / 右下三连 / Boss 提示栏 / 金币 / 击杀 / 结算面板），
  打击反馈 B2/B3 又往屏幕上加了**印痕层 / 连击计数 / 击杀落款 / 受伤角标 / 墨闪 / 奖励飞入 / 残影条**。
  **再加就该有人出来喊停了。**
- **借什么**：**可关 + 预设**（不抄"占容量"）。
- **三套预设（建议）**：
  | 预设 | 开什么 | 给谁 |
  |---|---|---|
  | **简洁** | 头像格 + HP + 阶段倒计时 + 技能格 | 小屏、老手、录屏 |
  | **标准**（默认） | 上面 + EXP + 金币/击杀 + 右下三连 + Boss 栏 | 大多数 |
  | **全部** | 上面 + Buff 行 + 连击计数 + 击杀落款 + 受伤角标 + 伤害数字 | 想看清一切的玩家 |
- **落点**：`game/common/HudPrefs.ts`（新，纯 TS 无 cc，存 `DataModule`）+ `View_Game_Stage` 按它写 `active`。
  **注意**：`HitScreenLayer` / `HitVfxLayer` 的开关也归它管（那两层现在无条件画）。
- **顺带的收益**：低端机去掉两层 `Graphics` = 实打实的填充率。

**B3. 「一屏一个实心按钮 + 可点物 ≤3 类」写成总则**（借"奶奶也能用"）
- 我们的商城规范里已经写了「全屏页**只有一颗实心按钮**」—— 这条**其实就是尼尔原则**，
  但它现在只写在 `docs/shop/README.md` 里，没升级成全局规则。
- **建议**：把三条写进《美术风格预设》§6 开头 ——
  ① 一屏**一个**视觉重量最大的主操作；② 同类可点物**≤3 类**（青绿实底按钮 / 卡片 / 图标按钮）；
  ③ **每个全屏页必须能回答"返回在哪"**（已落地：返回自关）。
  再补一条尼尔的：**每屏屏上操作提示不超过三条**（超出的做成隐藏手势，不写进提示）。

**B4. 动效要有"湿度"：先画线，内容后到**
- **借什么**：貴島说的"湿润、不干瘪"，以及尼尔菜单呼出时那条**先展开的线**。
- **落点**：面板开合（`View_Shop` / `View_Bag` / `ui_hero_detail` / 技能详情）改成
  **① 细线从一侧展开（80ms）→ ② 内容整体淡入 + 极短位移（120ms）**，
  而不是现在这种"整块 `SCALE` 弹出"。
- **代价**：每个面板一个短 Tween 或帧驱动；`Button` 的 `SCALE` 态**不动**（§6 已定）。
- ⚠ **不要碰顿帧账本**（`HIT_FEEL_BUDGET` 1s 内 ≤30ms）—— 面板动效走真实时间，不缩 `ctx.Tick`。

### C 档 · 有辨识度但有风险（建议只做 1 个）

**C1. 「破损态」——唯一允许的情绪破格，用"线的缺失"表达**
- **借什么**：尼尔自爆后那套"坏掉的 UI"的思路（**整场克制的设计只留一个破格口子**）。
- **我们能怎么做**：禁用清单禁的是**发光 / 粒子 / 后处理 / 纹理**，
  **不禁"线稿的缺失"** —— 所以破损态在浅底手绘风格里完全成立，而且**零新色、零新素材、零新特效**：
  | 破损语汇 | 画法 | 用在哪 |
  |---|---|---|
  | 图框缺一角 | 边框少画一段（`Graphics`，不画那条线） | 阵亡结算面板、濒死时的 HUD 外框 |
  | 虚线断裂 / 抖动 | 范围圈虚线随血量降低出现缺口 | 英雄濒死（HP < 25%）时的攻击范围圈 |
  | 读数被划掉 | 数值上叠一条 1px 斜线（`c-danger` 细线） | 失效的遗物/Buff 行 |
  | 尺寸线错位 | 尺寸线的箭头偏移、数值框错位 1~2px | 结算面板的数值区 |
- **为什么不违反规范**：全程只用**现有墨色 + `c-danger` 细线**，没有渐变/发光/纹理。
- **风险**：做过头会变成"故意做旧"，与"干净图纸"冲突。**建议只用在"失败/濒死"两处，且幅度极小（缺一段线 + 一个错位）。**
- **这是全篇**最不像别人、也最贴我们母题的一条 —— 但**先看 §8 待拍板**。

## 5. 母题方案：把"乐谱"换成本土等价物 = 工程图纸

尼尔：`扁平设计` + `乐谱象征` = 有灵魂的系统界面。
我们：`扁平双色` + `工程图纸语法` = 同一件事，而且**我们 §0 早就写了"参考的物：蓝图与工程图纸"**。

**六件套**（全部零新增颜色、零新素材；线宽沿用 §3 的 `1.2~1.6px` / `2.2~3px` 圆头）：

| 图纸元素 | 视觉 | 在我们的界面里承担什么 | 具体落点 |
|---|---|---|---|
| **图框** | 距屏幕边 30 的一圈**细墨线**，四角可留**裁切角** | 给整屏一个"这是一张图"的边界；也给破损态一个可缺的对象 | 每个全屏页的根节点（`View_Shop` / `View_Bag` / `Scene_Menu` / 战斗 HUD 外圈） |
| **标题栏** | 右下角小矩形分格：`图号 · 版本 · 比例` 三格 | **一个天然的"元信息"容器**：关卡号 / 难度 / 版本号 / 局内时间 | 结算面板右下、局内 HUD 右下空位（现在那里只有三个功能图标） |
| **尺寸线** | 细线 + 两端箭头 + 中间断口写数值 | **任何"两个东西之间的距离/对比"**：`HP 300/300`、`+14%`、进度 `阶段 2/4` | 技能详情数值行、结算数值区、遗物描述里的加成 |
| **引出线** | 斜细线 + 末端小圆点，指向被标注处 | **tooltip / 标注**：遗物效果说明指向遗物格、Buff 说明指向层数 | 遗物详情、Buff 行、`flashHint` 提示行 |
| **圆圈编号** | 细线圆 + 内写数字 | **序号 / 顺序 / 步骤**：技能槽编号、难度档位、新手引导步骤 | `SkillSlot` 的角标（现有 `conor.png` 可以退休）、引导 |
| **剖面线** | 45° 细斜线填充（`c-ink-200`） | **禁用 / 未解锁 / 空槽** | 背包空槽（现在是纯灰底）、未解锁英雄卡遮罩、不可点药丸 |

> **为什么这比"再加一套颜色/图标"好**：母题一旦定下来，**后面所有"这里该怎么装饰"的问题都不需要再开会**。
> 尼尔就是靠这一条把一套扁平设计撑了一整部游戏。

## 6. 明确不借的六条（含替代）

| 不借 | 为什么 | 替代 |
|---|---|---|
| **尼尔的米色**（`#B0AB98` 一线） | 它是"大屏 + 暗环境"的可读性预算，手机小屏会糊 | 保持我们的 `#EFEEED`/`#EBF4FB`（**更亮是对的**） |
| **网格纹理 + 屏幕边缘失真 + 暗角** | 直接违反 §10（纹理/后处理），且移动端填充率划不来 | 不做。"仪器感"改由**图框 + 分段刻度 + 等宽数字**承担 |
| **尼尔的字体** | 授权 + 无中文字形 | 保持 Arial + 系统黑体；只借**排版习惯**（小号宽字距标签、等宽数字、两档字重） |
| **黑屏开机大字 / 长打字机文本** | 塔防的对局节奏不允许停下来看字 | 只在"进入关卡"用 **0.6s 短版**：一条横扫的线 + 阶段名/难度读数（§4-B4 同一套） |
| **HUD 芯片"占容量"机制** | 会和我们的**遗物系统**正面打架（两个都叫"装载预算"，玩家会混） | 只抄"可关 + 预设"（§4-B2） |
| **尼尔的情绪调性**（疏离 / 悲哀 / 存在主义） | 我们是明快青绿纸面 | 只借**结构**，不借情绪；破格只留"破损态"一处（§4-C1） |

## 8. 待拍板（需要主美/策划点头才能回写进规范）

1. **A1 的语义表**要不要进《美术风格预设》§4？进了就意味着 `#22B14C` 绿字与 `#FF4C4C` 限时红**要改**，
   且 `audit:slot` 的 ⑯ 判据要一起改（测试与规范同步，否则下一个跑体检的人会以为是我改坏了）。
2. **B1 分段刻度**的**档位规格**（格宽 / 格间距 / 格高）：建议 `8×8 格 + 4 间距`，落在 6/10/20/30 步进之外，
   所以要**新登记一个间距档**（这是我唯一要求新增的 token）。
3. **B2 HUD 预设**：三套够不够？默认是哪套？**"设成简洁"要不要给一点游戏内好处**
   （尼尔是给容量的）—— 建议**不给**，纯无障碍，避免和遗物系统语义打架。
4. **C1 破损态**：做不做、做在哪两处、幅度多大。**建议先只做"阵亡结算面板的图框缺一角"一处**，看观感再决定扩不扩。
5. **§5 母题六件套**：是否升格为《美术风格预设》的正式章节（§3.5「图纸语法」）？
   升格后 §10 禁用清单要补一条：「**不许使用图纸语法之外的装饰**（花边、徽章、花纹、拟物边框）」。
