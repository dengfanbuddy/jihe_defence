1架构总览：四层分层 + 两条通道
Scene_Game_Stage 是"总控"，连接四个层次。怪物/弹道遵循"逻辑对象 + 表现 View"双对象模式，中间通过 view 字段和事件解耦。
四层架构：配置（TbRoot）→ 逻辑（battle/ 纯 TS）→ 表现（entityview/ cc）→ UI（响应式 store）
核心原则：逻辑层不 import 任何 cc 模块，所以可以脱离场景做单元测试、无头模拟，甚至未来接服务端权威。表现层通过 entity.view 字段绑定，通过 ctx.bus 事件感知战斗变化。
2生命周期流程：show → initBattle → selectHero → 战斗 → finish
Scene_Game_Stage 是 BaseView 子类，由 UIManager 控制显隐；内部由 FSM（HeroSelection → Battle → Pause）管理阶段。
生命周期主线（左）+ FSM 状态机（右）。注意 selectHero 里 heroNode 上的 Hero 组件跨局持久，复用分支需重建实体到新 ctx
注意：Hero 组件挂在 heroNode 上，跨局持久。二次开局时走 hero.entity 复用分支：旧实体须 ctx.RemoveEntity 移出旧上下文，再 CreateEntityFromDef 建到新 ctx，且必须重新 bindBattleEvents()（新 ctx 是新的事件总线）。
3每帧战斗循环（tick）
这是战斗每帧的推进顺序，也是理解"谁驱动谁"的关键。
每帧循环：checkStage（刷怪）→ heroAI（英雄行动）→ 弹道视图 → ctx.Tick（世界推进）
顺序说明：英雄 AI 在 ctx.Tick 之前，保证"英雄命令 → 世界结算"同帧生效；弹道视图在 Tick 前创建，使新发射的弹道当帧就有表现。
4对象池配对：MonsterPool = EntityPool + EntityViewPool
怪物是"逻辑实体 + 表现节点"的 1:1 配对，场景层只面对一个组合池，配对顺序由池内部保证。
组合池：逻辑池与表现池 1:1 配对，释放顺序"先表现后逻辑"（unbind 需要 entity 引用还在）
异步竞态防护：viewPool.acquire 是异步的（resources.load 预制件）。若实体在视图创建前就死亡/回收：EntityViewPool.release 先置 _viewRecycled 标记，晚到的回调看到标记即放弃创建 → 节点不泄漏。实体复用前 Reinit() 清除标记。
弹道池同理：ProjectileViewPool 用 _viewAlive 标记（acquire 置 true / release 置 false），弹道飞行极快时命中先于预制件加载，回调看到标记放弃创建。
5事件驱动：ctx 发事件 → 场景订阅 → 统计/回收/UI 同步
战斗上下文只"发事件 + 管状态"，统计与回收由订阅方（Scene_Game_Stage）负责。发布端与监听端统一用 BattleEvents.xxx 常量。
事件流：逻辑层发事件 → ctx.bus（实例总线）→ 场景层订阅 → 回收/统计/UI 同步
统一口径：发布端 publish(BattleEvents.OnDeath) 与监听端 onBattleEvent(BattleEvents.OnDeath) 都用常量，全局搜 BattleEvents.OnDeath 即可看到完整链路。全局事件（跨场景/UI）走静态 EventBus.emit/on，与战斗内实例总线互不干扰。
6核心类职责速查
各模块一句话职责 + 关键入口，方便定位代码。
类 / 模块层次职责关键入口
Scene_Game_Stage 总控 战斗场景总控：生命周期、刷怪、英雄 AI、事件订阅、对象池编排 show / update / tick / selectHero / bindBattleEvents
BattleContext 逻辑 单场战斗容器：实体表、弹道、调度器、事件总线、伤害管线 CreateEntityFromDef / AddEntity / RemoveEntity / Tick
Entity 逻辑 战斗实体：属性 + Modifier + 状态 + 技能 + AI；位置由 AI 驱动 Attack / Cast / Tick / Reinit / ResetForPool
AbilitySystem 逻辑 技能实例管理、冷却、施放分发；script_id 逃逸到代码类 AddAbility / CastAbility / Tick / Clear
ModifierSystem 逻辑 Modifier 生命周期/叠加/事件回调；属性贡献汇总到 AttributeSystem AddModifier / RemoveModifier / Tick / DispatchEvent
DamagePipeline 逻辑 伤害 5 阶段结算（增伤/暴击/格挡/抗性/扣血死亡）；深度保险丝防递归 ApplyDamage
MonsterAI 逻辑 怪物行为脚本（chase/wander/orbit/boss），通过 entity.position 驱动移动 update / findTarget / moveToward / tryAttack
MonsterPool 池 组合池：EntityPool + EntityViewPool 配对编排，场景层唯一入口 acquire / release / preload / releasePrefabs
EntityView 表现 怪物/英雄节点组件：绑定实体、update 同步位置、unbind 解绑 bind / unbind / update
Projectile 逻辑 弹道逻辑：位置推进（tick）、两阶段结算（onHit 重新校验） tick / onHit / snapToEnd / getProgress
ProjectileViewPool 池 弹道节点池：按预制件分桶、命中回收、异步竞态防护 acquire / release / preload / releasePrefabs
EventBus 基础 事件总线：静态全局门面 + 实例总线双形态；off 支持按 handler 精确移除 emit/on/off/clear（静态） + subscribe/publish（实例）
battleStore UI 响应式战斗状态（hp/gold/enemiesAlive），UI 组件 watchData 订阅 hp / gold / enemiesAlive / reset
Hero 表现 heroNode 上的组件，持有 entity 引用（跨局持久） bind(entity)
