总览：击杀经济的设计定位、设计原则、与现有配置的关系。

设计定位

金币

局内经济：刷新 / 买装备 / 升级。局终清零，用于一局之内的战力爬坡。

局内经验

局内英雄升级 → 加属性（heroes.json growthValues）。局终清零。

局外经验

对局结束按配置一次性发放（玩家 + 英雄等级），与局内击杀经验无关。

一句话痛点：金币和经验是两种职能完全不同的资源，不能套同一个成长公式。且经验还分局内（击杀产出→局内升级加属性）与局外（结算配置一次性发）两套——局内经验绝不能累加进局外。

核心循环

击杀 → 结算（阶段×时间缩放） → 金币(局内) / 局内经验(升级加属性) → 战力提升 → 挑战更强敌人。对局结束才走一条独立支线：局外按配置一次性发经验（与局内无关）。

设计原则

原则含义用以解决的分歧
时间只做弱通胀奖励随时间缓慢爬升，有上限；不做纯线性膨胀。避免拖后期=挂机白嫖奖励，奖励随难度跳变显得割裂。
金币跟难度 / 局内经验跟强度金币奖励对应用户消费能力；局内经验奖励对应用户成长曲线。两资源同涨同落会导致某一资源迅速溢出。
局内外经验解耦局内经验只在局内升级加属性（局终清零）；局外经验只在对局结束按配置发。防止局内击杀经验污染局外账号等级。
经济 Boss = 拆分而非双份金币 Boss 只给金币，经验 Boss 只给经验，不做又给金币又给经验。一刀下去双资源爆掉，直接废掉整局经济。
配置驱动所有基数在 units.json，缩放系数在 battle_constants.json，策划可调。改奖励不用动代码。

与现有配置的关系

配置职责本次改动
units.json运行时怪物（id 1-11），goldReward/expReward/rewardType新增奖励字段；怪物补数值；新增黄金魔像/经验贤者两个经济 Boss
battle_constants.json缩放系数 + 局内等级公式 + 结算基数新增局内/局外两套经验常量
Scene_Game_Stage.onDeath击杀结算：金币发局内、局内经验升级加属性接入 grantKillReward + addBattleExp
Scene_Game_Stage.finish对局结束：按配置一次性发局外经验接入 settleMetaRewards
useBattleStore局内等级/经验投影（HUD 响应式）新增 level / exp / expToNext

交付状态

已落地

局内经验升级加属性；局外配置结算；HUD 等级/经验接入；两套经验已解耦。

待调优

阶段难度系数 0.15 为 待定 样例值；局外英雄经验取第一个已解锁英雄兜底发放。
