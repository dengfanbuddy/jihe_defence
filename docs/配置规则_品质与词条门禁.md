# 配置规则 · 品质 × 词条门禁

> **本文是「品质能给什么词条」的唯一权威文档**（2026-07 定案）。
> 规则的可执行版本在 `tools/excel_export/scripts/lib/affix-rules.mjs`（迁移脚本与校验脚本都只 import 它）；
> **改规则必须同时改这两处 + 跑 `npm run check:affix`**。
> 相关文档：《数值配置参考手册》（数值口径/锚点）、《游戏开发术语速查手册》（术语）。

---

## 0. 一句话规则

| 词条类别 | 例子 | 最低品质档 |
|---|---|---|
| **数值属性 + 固定值** | 攻击力 +8、最大生命 +90 | **白档**（所有品质都能给，只是多少不同） |
| **百分比加成**（对基础属性乘算） | 攻击力 +14% | **黄档** |
| **百分比型属性**（属性值本身是百分比） | 攻速 +15%、闪避 +8%、暴击率 +10% | **黄档** |
| **功能性固定值** | 击杀敌人金币 +2 | **蓝档** |
| **功能性百分比** | 局内金币获取 +13% | **红档**（最高品质专属） |

设计目的：**低档给"平坦的白值"、高档才给"会随成长放大的乘区"**，从而
① 让「白→红」是一条明确的强度阶梯，② 不让局外成长过多影响局内（局外永久乘区收口在黄/红档），
③ 避免低品质物品提前给出后期会失控的百分比。

## 1. 品质全局统一 4 档

此前局外装备用数字 `1 / 1.3 / 1.6 / 2 / 2.5`（5 档）、局内遗物用 `common/rare/epic/legendary`（4 档），
两套不一致。**现统一为 4 档，且局内局外存在同一张表 `relics.json` 里**（见 §1.1），
品质列一律用 `rarity` 枚举：

| 档位 | 名称 | 遗物 `rarity`（局内 + 局外） | 旧装备 `quality`（已废弃，仅作换算参考） | 商店 `stage` | UI 品质色 |
|---|---|---|---|---|---|
| 1 | 白（普通） | `common` | `1` | 1 | `#DDDDDD` |
| 2 | 蓝（稀有） | `rare` | `1.3` | 2 | `#5096FF` |
| 3 | 黄（史诗） | `epic` | `1.6` | 3 | `#CF68FF` |
| 4 | 红（传说） | `legendary` | `2`（旧 `2.5`「独特」并入此档） | 4 | `#FF6464` |

> · 商店 `stage` 由 `rarity` 推导（`ShopConfig.getStageOfRarity`），本规则不改抽取概率表（`shop_draw.json`）。
> · 档位名如表与 UI 色不完全同名（表口径「黄」= UI 色板里的紫 `#CF68FF`），历史遗留见《美术风格预设》§1.7。
> · **英雄专属装备已删除**（2026-07「无英雄专属」），所以 `hero_id` 列与 `category: hero_specific` 都不再存在；
>   旧 `2.5`「独特」并入红档后 4 档自洽。

### 1.1 局内 + 局外 = 同一件遗物一行（`scope` 列）

**局内版与局外版是同一件遗物**：共用**一行**、共用 `id` / `name` / `code` / `icon` / `rarity` / `category`，
只有**效果与描述分两侧**（`modifiers_inner` / `description_inner` 与 `modifiers_outer` / `description_outer`）。

| `scope` | 含义 | id 段 | 例子 |
|---|---|---|---|
| `inner` | **只有局内版**：本局内生效，进肉鸽商店抽取池 | 1~5（手工 demo）、1001~1293（肉鸽道具） | 压制之刃、荆棘护甲 |
| `outer` | **只有局外版**：跨局永久收集（图鉴式累加） | **1294~1302**（9 件 dota2 道具，多是中立道具） | 敏捷手套、贤者之石 |
| `both` | **两侧都有**：同一件遗物的两套效果（id 用**局内 id**） | 1001~1293 里那 28 件 | 力量手套、狂战斧、蝴蝶 |

- `scope` 是**必填列**；说了有某一侧，就必须有那一侧的 `description_*` / `modifiers_*`（`check:affix` 与 `crossCheck` 都会拦，
  填了某一侧却把 `scope` 写成另一侧是**错误**）。
- **商店池必须按「有局内版」过滤**（`ShopConfig.getRelics()` → `relicHasInner`），否则只有局外版的遗物（1294~1302）会混进局内抽卡池。
- **局外 id 段与局内共用一套**：合并时用**局内 id**（`EquipmentCollection` 存的也是这个 id）；
  两次 id 迁移的历史映射见 `tools/excel_export/reports/equipments-into-relics.md`（→ 2001~2045）
  与 `reports/relics-scope-restructure.md`（→ 局内 id / 1294~1302）。
- 原 `equipments.json` 的 `attributes` 对象已统一成 `modifiers_outer[0].kv.attrs`（**int 口径**，见 §2 末表）；
  `allPercent`（全属性百分比）只对**数值属性**展开成 `percent` 条目（百分比型属性基础值为 0，percent 无效）。
- **一件遗物只有一个品质**，升档会连带另一侧 —— 若局外版的词条全是百分比型（如「闪避护符」+8% 闪避），
  它在蓝档会被门禁判违规，`migrate:affix` 的处理是**升档保身份**（`rare → epic`），而不是把词条删空。

## 2. 属性分两类

判定以 `assets/scripts/game/battle/core/AttributeScaling.ts` 的 `SCALE` 表为准（**那是代码侧真源**）：

**① 数值属性**（配置值 = 原值）：
`1 最大生命`、`2 最大魔法`、`3 攻击力`、`5 移动速度`、`6 护甲`、`9 生命恢复/秒`、`10 魔法恢复/秒`、`16 攻击距离`

**② 百分比型属性**（配置值 = 实际值 × 100，`100 = 100%`）：
`4 攻击速度`、`7 魔法抗性`、`8 闪避`、`11 伤害输出倍率`、`12 物理受伤倍率`、`13 魔法受伤倍率`、`14 暴击率`、`15 暴击伤害`

> ⚠ **百分比型属性禁止用 `percent` 叠加**（`AttributeStackMode.Percent`）。
> 原因：`percent` 是 `base × (1 + Σv)`，而闪避/暴击率/回血这些属性的 `attributes.json.base` 是 **0**（英雄配置也不再给），
> 乘出来恒为 0；魔抗虽非 0，但同一条属性出现两种百分比语义极易配错。
> **百分比型属性一律用 `add`，配置值即"百分点"**：`[14, 10, "add"]` = 暴击率 +10%。

### 2.1 基础值为 0 的数值属性：同样禁止 `percent`（2026-09 补）

`attributes.json` 里 `base = 0` 的**数值属性**有三个：**护甲(6) / 生命恢复(9) / 魔法恢复(10)**
（英雄条目收口后不再配这三项，实际基础值就是 0）。对它们用 `percent` 与百分比型属性是同一个坑：
`0 × (1 + Σv/100) = 0`，**词条恒不生效**。

> 踩过：传说「统御头盔」护甲 +22% / 「白银之锋」生命恢复 +16% —— 属性系统里护甲仍是 0、回血仍是 0，
> 玩家看到的是"加了属性没生效"。共 36 条词条（13 条护甲 + 23 条回血）受影响。

规则：**`ZERO_BASE_ATTRS = [6, 9, 10]` 上的 `percent` 一律报错**（`classifyAttrAffix` 返回
`numeric_percent_zero_base`），改成 `add` + 固定值，折算基准走同一张 `FLAT_CONVERT_BASELINE`
（护甲 15% → +1.5、回血 14% → +0.28）。迁移由 `npm run migrate:affix` 自动完成（幂等）。

### 2.2 暴击的数值合同（2026-09 定案）

| 项 | 值 | 说明 |
|---|---|---|
| 属性 15 暴击倍率 `base` | **150**（1.5 倍） | `DamagePipeline.rollCrit` 要求 `倍率 > 1` 才可能暴击 —— base = 100 → 1.0 → **全项目永远不暴击** |
| 词条值口径 | int = 倍率 × 100 | `225` = 暴击造成 225% 伤害 |
| 词条叠加方式 | **`best`**（显式写第三项） | **条目 mode 会覆盖属性默认 mode**：写 `add` 会变成 `base + Σv` 累加（`+225%` 算成 1.5+2.25 = 375%），`best` = 「取最强的一件暴击装」（Dota 语义） |
| 暴击率(14) | `add` + 百分点 | `[14, 14, "add"]` = 暴击率 +14%；只要为正即按上面的倍率结算 |

规则真源 = `affix-rules.mjs` 的 `CRIT_MULT_BASE` / `CRIT_MULT_MODE` / `critTextToMultiplier`，
数据修复由 `npm run fix:crit` 完成（幂等：`attributes.json` 的 base、文案承诺但未落表的暴击词条、叠加方式归一）。

**全项目只有一套数值口径了（容易配错，记住这张表）**：

| 位置 | 百分比型属性怎么写 | 例 |
|---|---|---|
| `relics.json` 的 `kv.attrs`（**唯一权威口径**） | **int，`100 = 100%`** | 闪避 +8% → `[8, 8, "add"]` |
| 旧 `equipments.json` 的 `attributes` | 运行时小数（**该表已删除**，仅历史参考） | 闪避 +8% → `"dodge": 0.08` |
| 运行时 `OuterBonusGroup`（`EquipmentConfig` 产出） | 运行时 float | 闪避 +8% → `0.08` |

## 3. 门禁矩阵（可执行版见 `affix-rules.mjs` 的 `classifyAttrAffix`）

| 词条 | 判定 | 最低档 | 违规示例 |
|---|---|---|---|
| 数值属性 + `add` | `numeric_flat` | 1 白 | —— |
| 数值属性 + `percent` | `numeric_percent` | 3 黄 | 白档遗物给「攻击力 +14%」（应折成固定值） |
| **base = 0 的数值属性 + `percent`**（护甲/回血/回蓝，见 §2.1） | `numeric_percent_zero_base`，**并额外报错** | —— | 任何档位的「护甲 +22%」用 percent 写（恒为 0，改用 add） |
| 百分比型属性 + `add` | `percent_attr_flat` | 3 黄 | 白档遗物给「攻速 +3%」（应删或整件升档） |
| 百分比型属性 + `percent` | 同 3，**并额外报错** | 3 黄 | 任何档位的「闪避 +6%」用 percent 写（改用 add） |
| 数值属性 + `multiply` | 全项目禁用 | 4 红 | `multiply` 是复利，百分比加成不要用它 |
| 功能性固定值 | `functional_flat` | 2 蓝 | 白档给「击杀金币 +2」 |
| 功能性百分比 | `functional_percent` | 4 红 | 蓝档给「金币获取 +13%」 |

**功能词条暂无结构化字段**：`relics.json` 没有专门的功能词条列，功能效果只能写进
`modifiers` 的 `events`/`effects`（如 `steal_gold`/`lifesteal`/`reflect`），而「金币获取 %」「冷却缩减 %」这类
**派生的功能属性还没有 `AttributeType`**（见《数值配置参考手册》遗留项）。因此：
- 属性词条门禁 = **硬校验**（`npm run check:affix` 报错即失败）；
- 功能词条门禁 = **文案层人工复核**（校验脚本对 `description` 做启发式提醒）。
- **文案里的属性词条也过门禁**：校验脚本对**局内与局外两侧**的 `description` 逐子句解析
  （兼容「攻击力 +8」与「+0.1 攻击速度」两种写法），把当前档位不允许的词条列为警告；
  迁移脚本对**局外段低档**会**自动删掉**这类子句（局内段的机制原文保留，只报不改 —— 见 §8 第 3 条）。

## 4. units.json 英雄配置规则（本次收口）

英雄条目（`team=1` / `category: hero`）**只允许两类属性列**：

| 列 | 允许的属性 | 说明 |
|---|---|---|
| `base_attributes` | **只有 5 项**：最大生命(1)、最大魔法(2)、攻击力(3)、攻击速度(4)、攻击距离(16) | 百分比型属性按 `100 = 100%` 填（攻速 120 = 1.2 次/秒） |
| `growthValues` | **只有 3 项**：最大生命(1)、最大魔法(2)、攻击力(3) | **float 语义**（不是 ×100），如 `0.005` = 0.5%/级 |

**被剔除的 6 项**（移动速度 5、护甲 6、魔法抗性 7、闪避 8、生命恢复 9、暴击率 14）与暴击倍率成长
不再由英雄配置提供，运行时回落到 `attributes.json.base`：

```
移动速度 300 / 护甲 0 / 魔法抗性 25 / 闪避 0 / 生命恢复 0 / 魔法恢复 0 / 暴击率 0 / 暴击伤害 100（=1.0）
```

> 含义：**英雄的差异只剩「5 项基础 + 技能」**；护甲/闪避/暴击/回血这些靠**局外遗物 + 局内遗物**给。
> 这也让「低档给固定值」成为必要手段 —— 基础值为 0 时，只有固定值能生效（percent 乘 0 还是 0）。
>
> ⚠ **平衡影响（需策划关注）**：迁移后 4 个现役英雄初始 **护甲 0 / 闪避 0 / 暴击率 0**，
> 斧王少 8 护甲 + 1.5 回血/级后明显变脆；移速则统一成 300（火枪 280 / 赏金 200 / 斧王 240 都涨了）。
> 手感与生存预算需要在「局外遗物/局内遗物」或 `attributes.json.base` 上重新校准，详见迁移报告 §1。

## 6. 低档 `percent` → 固定值 的折算基准

迁移/新配低档数值词条时，`percent X%` 折成固定值 `= round(X/100 × 基准)`：

| 属性 | 折算基准（= 100%） | 取整 | 依据 |
|---|---|---|---|
| 最大生命 | 500 | 整数 | 4 英雄 Lv.1 生命 320/520/340/560 的中位量级 |
| 最大魔法 | 150 | 整数 | 120/100/220/80 |
| 攻击力 | 60 | 整数 | 40/200/26/34，按 Lv.10 中位量级上调 |
| 移动速度 | 300 | 整数 | `attributes.json.base` |
| 护甲 | 10 | 2 位小数 | 手册 §4.2 区间上沿（基础 0 —— percent 对护甲完全无效） |
| 生命恢复/秒 | 2 | 2 位小数 | 现役 1~3 |
| 魔法恢复/秒 | 2 | 2 位小数 | 同回血 |
| 攻击距离 | 300 | 整数 | 200~600 |

示例：`攻击力 +14% → 攻击力 +8`；`最大生命 +18% → 最大生命 +90`；`护甲 +12% → 护甲 +1.2`；`生命恢复 +7% → 生命恢复 +0.14`。

> 口径说明：基准取的是**局内 Lv.1~Lv.10 的量级**，所以低档遗物「前期基本持平、后期自然稀释」——
> 这正是"低档给固定值、高档给百分比"想要的效果。

- **改表流程铁律不变**：改 `excel/*.xlsx`（或在 JSON 上跑脚本后 `npm run import -- --force --table …` 回灌）→
  `npm run export` → 复核 `git diff`。**只改 JSON 不回灌，下一次导出会被 xlsx 覆盖。**
- ⚠ `node scripts/gen-shop-from-hero-design.ts` 会按设计稿**重写局内版**（`modifiers_inner` 用设计稿的百分比原值），
  所以重跑它之后**必须再跑 `npm run migrate:affix`**，否则低档折算会被打回。它不会动局外版与身份列。

**运行时同规则**：`assets/scripts/game/data/configs/EquipmentConfig.ts`（**局外遗物门面**）读 `modifiers_outer`，
把 **int 口径**换算成 `OuterBonusGroup` 的**运行时 float**（闪避 8 → 0.08），
并按同一套档位分层（`add` → flat；`percent` → percent 层且需黄档起，低档降级并 warn）。
`ShopConfig.getRelics()` 按 `relicHasInner()` 过滤商店池 —— **只有局外版的遗物不会进局内抽卡池**；
`BattleEquipSystem`（局内挂载）读 `modifiers_inner`，且拒绝挂载没有局内版的遗物（`relicHasInner` 判一次）。
