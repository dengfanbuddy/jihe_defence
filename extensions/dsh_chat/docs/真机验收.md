## 4. S1 坐标空间 · 判据一：用编辑器自己的选中当尺子（编辑态）

**思路**：`pick`（编辑器自己的命中测试）说"这个页面坐标上是节点 X"；真点一下之后 `Editor.Selection` 说"选中的是节点 Y"。
**X 与 Y 相同 ⇒ 页面 CSS 像素这个口径成立** —— 两条互相独立的代码路径对同一个坐标的看法一致。

**步骤**

1. 选一个点，并记下编辑器认为那儿是什么：
   ```js
   // cocos_execute_code({ context:'scene', args:{x:<px>, y:<px>}, code: "return pick(args.x, args.y)" })
   ```
   先点哪儿：`x = pageCss.cssWidth/2, y = pageCss.cssHeight/2`（画面正中）。
   返回里记 `verdict` / `hit`（名字 + uuid）/ `hits` 的条数。
   若 `verdict === 'editor-overlay'`（那儿只有编辑器 gizmo）—— 换个点（比如画面 1/4 处）重来。
2. 清空选中：`cocos_execute_code({context:'editor', code:"Editor.Selection.clear('node'); return 1"})`
3. 真点：`cocos_click_node({ x: <同一个 px>, y: <同一个 px>, space:'view', probe: true })`
   记 `point`（应当与上一步一致）与 `probe.hit`。
4. 读选中：`cocos_execute_code({context:'editor', code:"return Editor.Selection.getSelected('node')"})`
5. **反面对照**（这一条不能省）：把 `y` 挪开 **+50px** 再点一次 → 选中**不该**还是那个 uuid。

**判据**

- 第 4 步的 uuid（或路径）**等于**第 3 步 `probe.hit` 指的那个节点 ⇒ **S1 通过**；
- 第 5 步之后选中变了（或为空）⇒ 对照通过（说明第 4 步不是"本来就在选中"）。

**若不通过**：连着换两个点都不选中 —— 把"场景视图的合成点击不改变编辑器选中"这条**当作事实记下来**（它本身也有价值：说明编辑器的选中不走这条输入路径），然后进 S2。**不要**为了让选中变化去改代码或动场景。

出处：`Editor.Selection` 的 `clear/select/getSelected`（编辑器声明 `@editor/creator/@types/editor.d.ts:756-811`）。

## 5. S2 坐标空间 · 判据二：运行态探针（量化）

**思路**：在**运行中的场景**里塞一个全屏、吞事件的探针，它把**引擎真收到**的触摸坐标记下来；我们发两个相距很远的点，比较"**发出去的两点之差**"与"**引擎收到的两点之差**"。
差值能同时验掉**缩放**与**偏移**；只点一个点的话，偏 20px 也会绿。

### 5.1 进运行态

```
cocos_runtime({ action: 'play' })
（等 1~2 秒）
cocos_runtime({ action: 'state' })      // 确认 running: true（若还是 false 隔几秒再看一次，记下等待时长）
```

### 5.2 装探针（**这段代码原样跑**）

```
cocos_execute_code({ context: 'scene', timeoutMs: 15000, code: `
const sc = cc.director.getScene();          // ⚠ 别写 const scene —— 沙箱里 scene 是保留标识符
const canvasNode = (sc.getComponentsInChildren(cc.Canvas)[0] || {}).node;
if (!canvasNode) return { ok: false, note: '运行场景里没有 Canvas —— S2 跳过，并记下这条' };
const old = canvasNode.getChildByName('__dshProbe');
if (old) old.destroy();
const probe = new cc.Node('__dshProbe');
canvasNode.addChild(probe);
probe.layer = canvasNode.layer;                  // 必须与 Canvas 同 layer，否则 UI 相机看不见
const ut = probe.addComponent(cc.UITransform);
ut.setContentSize(cc.view.getVisibleSize());
ut.setAnchorPoint(0.5, 0.5);
probe.setPosition(0, 0);

    const ui = e.getUILocation();

### 5.3 先确认探针真的抢到了事件（**安全闸**）

```
cocos_click_node({ x: 0.5, y: 0.5, space: 'uv' })
cocos_execute_code({ context: 'scene', code: 'return globalThis.__dshHits' })
```

- `__dshHits` 里出现 1~2 条 ⇒ 拦截层生效，可以继续；
- **一条都没有** ⇒ 立刻停 S2：把"全屏拦截层抢不过游戏的 UI（或事件根本没进引擎）"记进结果文件，
  跑 `cocos_runtime({action:'stop'})` 收尾，**不要**继续点（继续点就是往游戏本体上点）。

原因（为什么"先到先得"）：UI 指针分发按优先级取**第一个命中的处理器**，命中即 `break`，下层节点收不到
（`cocos/2d/event/pointer-event-dispatcher.ts:125-179`）；全屏拦截用的 `BlockInputEvents` 就是让命中它的事件 `propagationStopped`
（`cocos/ui/block-input-events.ts:31-58`）。

cocos_click_node({ x: 0.75, y: 0.70, space: 'uv' })      // 同上
```

（运行态下 `probe` 会自动 `skipped`，属正常，照抄即可。）

### 5.5 取回记录

```
cocos_execute_code({ context: 'scene', code: `
const hits = globalThis.__dshHits;
const cv = document.querySelector('canvas'); const cr = cv.getBoundingClientRect();
const vs = cc.view.getVisibleSize();
return { hits, canvas: { left: cr.left, top: cr.top, cssW: cr.width, cssH: cr.height, devW: cv.width, devH: cv.height },
         visible: { w: vs.width, h: vs.height }, page: { w: window.innerWidth, h: window.innerHeight } };
` })
```

**`hits` 与两次回执的 `point` 一起原样抄进结果文件**（算术由主会话做）。期望 `hits` 有 4 条（两次点击 × 按下/抬起）。

**你先粗看这两条**：

- 两次 `ui` 之差，与两次 `point` 之差**成比例**，比例 ≈ `canvas.cssW / visible.w`（x 轴）、`canvas.cssH / visible.h`（y 轴），且 y **符号相反**（页面 y 向下、UI y 向上）；
- 若比例是"另一个固定倍数" ⇒ 真机上坐标系差了一个缩放（**把那个倍数算出来写上**）；
- 若两条 `ui` 完全一样 / 乱序 / 为零 ⇒ 事件没进引擎或投错了空间 —— 补一次 `cocos_runtime({action:'pause'})` 之后再点一次，把两份都记下来。

### 5.6 命中测试（二元判据，三条一起才算过）

把探针换成一个**小方块**（同 5.2 的做法，尺寸 `80×80`、位置在可见区正中、**不加** `BlockInputEvents`）：

1. 点正中 `{x:0.5, y:0.5, space:'uv'}` ⇒ 方块**应当**收到（`hits` 多 2 条，`ui` 落在 ±40 内）；
2. 点右偏 30px ⇒ **也应当**收到，且 `ui.x` 比第 1 条大约大 `30 / (canvas.cssW / visible.w)`；
3. 点右偏 100px（超出方块右缘 40px 以上）⇒ **不应当**收到。

右偏 30px / 100px 换算成 uv：`0.5 + 30 / page.w`、`0.5 + 100 / page.w`（`page.w` 来自前置第 5 条）。

## 6. S3 `PreviewPlay.pause(true)` 到底停了什么

**读数**（每次调用都用这同一段，把它叫 `R()`）：

```js
// cocos_execute_code({ context:'scene', code: ` ... ` })
return {
    frames: cc.director.getTotalFrames(),
    dt: cc.director.getDeltaTime(),
    directorPaused: cc.director.isPaused(),
    gamePaused: cc.game.isPaused(),
    previewIsPause: (globalThis.cce && cce.PreviewPlay && cce.PreviewPlay.isPause) ? cce.PreviewPlay.isPause() : null,
    isPreviewProcess: globalThis.isPreviewProcess ?? null,
};
```

**序列**（顺序别改；每次之间照表里的等待）：

| 步 | 调用 | 记什么 |
|---|---|---|
| 1 | `cocos_runtime({action:'state'})` | `scene.sources` 全套（顺便给 S4 用） |
| 2 | `R()` | 基线（编辑态） |
| 3 | 等 ~1.5s → `R()` | `frames` 应当 **+≈90**（60fps） |
| 4 | `cocos_runtime({action:'play'})` → 等 ~2s → `R()` | `running` 与 `frames` 都在动 |
| 5 | `cocos_runtime({action:'pause'})` → `R()` | **`gamePaused` 与 `directorPaused` 哪个变 true** |
| 6 | 等 ~1.5s → `R()` | `frames` **动没动** ← 最关键的一条 |
| 7 | `cocos_runtime({action:'step'})` → `R()` | `frames` **+几** |
| 8 | `cocos_runtime({action:'resume'})` → 等 ~1s → `R()` | `frames` 又动起来 |
| 9 | `cocos_runtime({action:'stop'})` → `R()` | 回编辑态 |

**判据（记录用，别写成最终结论）**：

- 第 5 步 `gamePaused: true` ⇒ 它走的是 `game.pause()`。引擎原文（`cocos/game/game.ts:576-596`）：停**逻辑 + 渲染 + 输入派发**，注释里还写着"Web 和小游戏平台除外"。
- 第 5 步只有 `directorPaused: true` ⇒ 它走的是 `director.pause()` —— **只停逻辑，渲染还在跑**（`cocos/game/game.ts:582` 明写二者不同）。
- 第 6 步 `frames` **没动** ⇒ "冻住再截图/取数"成立；**还在动** ⇒ 那句话是假的，**这条必须记下来**。
- 第 7 步 `frames` **恰好 +1** ⇒ `step` = 前进一帧（`cocos/game/game.ts:551-553`：`director.tick(固定 dt)`）；`+0` = 没生效；`+N` = 它自己的实现。

## 7. S4 场景侧三个来源在真机上的取值

`cocos_runtime({action:'state'})` 的两块，**编辑态 / 运行态 / 暂停态各抄一次**：

- `editorMessage`：`message` / `mode` / `raw` / `ok` / `error` / `note`（那条 `query-scene-mode` 消息到底回不回、回什么）
- `scene.sources`：`facadeMode` / `queryMode` / `previewPlayPresent` / `previewIsPause` / `isPreviewProcess`，以及任何 `*Error`

**判据**：`facadeMode` 或 `queryMode` 至少一个给出已知串（`general` / `prefab` / `animation` / `preview`）⇒ `mode` 可信；
**全是 null 或认不出 ⇒ 记明"真机上模式恒为 unknown"**（那意味着 `view` 参数、运行态不裁图、运行态拒绝按节点点这三条会**一直**生效 —— 它们不是 bug，但也帮不上忙）。

键名出处：`source/scene.ts:620-677`（`readSceneMode`）。
