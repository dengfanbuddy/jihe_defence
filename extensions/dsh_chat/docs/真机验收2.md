## 0. 第 1 轮查明了什么（为什么有第 2 轮）

| 事 | 结论 |
|---|---|
| 认页（S0） | ✅ 通过：`matchedBy: 'href'`，打到的就是场景视图那一页，窗口有焦点，三条事件坐标与 `point` 一致 |
| 合成点击到不了引擎（S1/S2） | 全屏探针 **0 条**；连**页面里自己 dispatch DOM 事件**（16 条，target 都是 `GameCanvas`）引擎也是 0 条 |
| 为什么（**已从引擎源码查明**） | 编辑器构建里引擎**根本不注册 DOM 监听**：`pal/input/web/mouse-input.ts:57-60` 写着 `// In Editor, we receive mouse event from manually event dispatching.` + `if (!EDITOR) { this._registerEvent(); }` ⇒ 真人点击是**编辑器自己手动转发**进引擎的，合成 DOM 事件永远进不去 |
| 引擎给编辑器留的口子 | `cocos/input/input.ts:174-209`（注释：`exposed for Editor Only`）：`cc.input._dispatchMouseDownEvent` / `_dispatchMouseMoveEvent` / `_dispatchMouseUpEvent` / `_dispatchMouseScrollEvent` / `_dispatchKeyboardDownEvent` / `_dispatchKeyboardUpEvent`。原生场景视图就是这么接的（`builtin/scene/dist/script/3d/preload/native/native-scene.js` 里那张 `{"mouse-down":"_dispatchMouseDownEvent", …}` 映射表） |
| 运行态识别（S4） | ❌ 前提不成立：预览**真在跑**时 `facadeMode`/`queryMode` **仍然是 `"general"`**，`isPreviewProcess` 恒 `false`，`mode` 恒 `general`、`running` 恒 `false` ⇒ 现有那三条来源**判不出运行态** |
| pause 语义（S3） | ✅ 真机确认（走兜底直调）：`PreviewPlay.pause(true)` 之后 `director.isPaused()` 与 `game.isPaused()` 同时 true、`frames` 1.5s **+0**（冻住是真的）；`step()` **恰好 +1 帧** |
| 工具那两条消息 | ❌ `editor-preview-set-play(true)` **120s 不回执**（编辑器主进程直发也 20s 不回）；`editor-preview-call-method('pause',true)` **报错** `Cannot read properties of undefined (reading 'setAttribute')`；`step`/`resume` 回 `ok:true` 但**一条帧都没动**；`stop` 回 `value:false / didApply:true` 而**预览还在跑**（假绿） |

**这一轮要定的两件事**：
1. **A3 换路**：改用引擎给编辑器留的那六个 `_dispatch*` 口子（在场景进程里直接调），并用它把**坐标空间**一次测准。
2. **C12 换路**：`play` 到底走"消息（fire-and-forget）"还是"直调 `PreviewPlay`"，以及 `_state` 能不能当运行态的判据。

### 2.2 装全屏探针 + 用 `_dispatchMouse*` 在**画面正中**点一下

```js
// cocos_execute_code({ context:'scene', timeoutMs: 15000, code: `
const sc = cc.director.getScene();
const canvasNode = (sc.getComponentsInChildren(cc.Canvas)[0] || {}).node;
if (!canvasNode) return { ok: false, note: '运行场景里没有 Canvas' };
const old = canvasNode.getChildByName('__dshProbe');
if (old) old.destroy();
const probe = new cc.Node('__dshProbe');
canvasNode.addChild(probe);
probe.layer = canvasNode.layer;
const ut = probe.addComponent(cc.UITransform);
ut.setContentSize(cc.view.getVisibleSize());
ut.setAnchorPoint(0.5, 0.5);
probe.setPosition(0, 0);
try { probe.addComponent(cc.BlockInputEvents); } catch (e) { /* 记下来 */ }

globalThis.__dshHits = [];
globalThis.__dshGlobal = [];
const recNode = (e) => { const ui = e.getUILocation(); globalThis.__dshHits.push({ node: e.type, ui: { x: ui.x, y: ui.y } }); };
probe.on(cc.Node.EventType.TOUCH_START, recNode);
probe.on(cc.Node.EventType.TOUCH_END, recNode);
try {
    cc.input.on(cc.Input.EventType.MOUSE_DOWN, (e) => { const l = e.getLocation(); globalThis.__dshGlobal.push({ t: 'MOUSE_DOWN', x: l.x, y: l.y }); });
    cc.input.on(cc.Input.EventType.MOUSE_UP, () => globalThis.__dshGlobal.push({ t: 'MOUSE_UP' }));
    cc.input.on(cc.Input.EventType.TOUCH_START, () => globalThis.__dshGlobal.push({ t: 'TOUCH_START' }));
} catch (e) { globalThis.__dshGlobal.push({ err: '注册全局监听失败：' + e }); }

// 引擎级注入：编辑器自己也走这条路（native-scene.js 那张表）
const mk = (clientX, clientY) => ({ clientX, clientY, button: 0, buttons: 1, movementX: 0, movementY: 0, repeat: false,
                                    stopPropagation() {}, preventDefault() {}, target: null });
const input = cc.input;
const api = {
    down: typeof input._dispatchMouseDownEvent === 'function',
    move: typeof input._dispatchMouseMoveEvent === 'function',
    up: typeof input._dispatchMouseUpEvent === 'function',
    scroll: typeof input._dispatchMouseScrollEvent === 'function',
    kdown: typeof input._dispatchKeyboardDownEvent === 'function',
    kup: typeof input._dispatchKeyboardUpEvent === 'function',
};
const cv = document.querySelector('canvas');
const cr = cv.getBoundingClientRect();
const px = Math.round(cr.left + cr.width / 2);
const py = Math.round(cr.top + cr.height / 2);
input._dispatchMouseMoveEvent?.(mk(px, py));
input._dispatchMouseDownEvent?.(mk(px, py));
input._dispatchMouseUpEvent?.(mk(px, py));
const vs = cc.view.getVisibleSize();
return { ok: true, api, sentAt: { x: px, y: py },
         canvas: { left: cr.left, top: cr.top, cssW: cr.width, cssH: cr.height, devW: cv.width, devH: cv.height },
         visible: { w: vs.width, h: vs.height }, page: { w: window.innerWidth, h: window.innerHeight },
         dpr: window.devicePixelRatio || 1, scaleX: cc.view.getScaleX(), scaleY: cc.view.getScaleY(),
         viewport: cc.view.getViewportRect(),
         hitCount: globalThis.__dshHits.length, hits: globalThis.__dshHits, global: globalThis.__dshGlobal };
// ` })
```

### 2.4 判据（先自己粗看，算术最终由主会话做）

| 看什么 | 期望 |
|---|---|
| `api.*` | 六个都应当是 `true`（哪一个 `false` 就照实记 —— 那说明这个版本的构建没暴露它） |
| 2.2 的 `hitCount` | **≥ 1**（探针全屏，画面正中的点必然命中）—— 这就是"注入真进引擎了"的铁证 |
| 2.2 的 `global` | 里面有 `MOUSE_DOWN`（引擎的输入源头这一层也收到了） |
| 2.3 的 `p1`/`p2` | 都应当命中；而且两次的 `ui` 之差应当 ≈ `Δclient / (dpr × scaleX)`（这里 dpr=1、scaleX≈0.56 ⇒ 120px → ≈214 UI 单位），y 同理 |
| 2.3 的 `p3`（画布外） | **不该**命中（这是反面对照：没有它，"命中"可能只是探针太大） |

## 4. R3 键盘（一条路顺带验）

```js
// cocos_execute_code({ context:'scene', code: `
```

## 5. R4 运行态开关：消息（fire-and-forget）能不能启动预览

**先回到 `stop`**（`cce.PreviewPlay.stop()`，或第 1 轮验过的那条），确认 `_state === 'stop'`。然后：

```js
// cocos_execute_code({ context:'editor', code: `
Editor.Message.send('scene', 'editor-preview-set-play', true);   // 注意是 send（不等回执）
return { sentAt: Date.now() };
// ` })

// 立刻在场景侧轮询 ≤30s：
// cocos_execute_code({ context:'scene', code: 'return { state: cce.PreviewPlay._state, frames: cc.director.getTotalFrames(), sceneName: cc.director.getScene().name }' })
```

**判据**：`_state` 会不会在 30s 内变成 `'play'`（`sceneName` 变成游戏首场景、`frames` 推进）。
- **会** ⇒ `play` 用"消息(不等回执) + 复探"这条路就够，编辑器工具栏的状态也是同步的（这条路优先）；
- **不会** ⇒ `play`/`stop` 只能直调 `cce.PreviewPlay.start()/stop()`，代价是**编辑器工具栏的状态会与真实状态不同步**（这一点必须写进工具的说明里）。

**顺带（若时间允许）**：从 `'play'` 态发一次 `Editor.Message.request('scene','editor-preview-call-method','pause',true)`，看它这次是否**仍然**报 `setAttribute` 错 —— 这能说明第 1 轮那个报错是"绕过了工具栏"造成的，还是这条消息本身在这台机器上就是坏的。

## 6.5 R6 **先重启一次编辑器与 agent，再验「这批修正」**（新加的，别省）

第 1 轮跑完之后，主会话按真机结论改了一批东西（`docs/对照-cocos-extensions.md` §9.8）：
`cocos_runtime` 改成**直调优先、消息兜底**（判据只有状态）、运行态判据换成 `PreviewPlay._state`、
抓图前一律排一次重绘、`stop` 后顺手治 paused。**这些也只在假件上验过。**

**前置**：让用户**重启一次 Cocos Creator**（改了 `dist/`）+ 面板里**重启 agent**（改了插件）。
然后按顺序跑，**每一步都把回执里的 `applied.by` / `after` 抄下来**：

```
cocos_runtime({action:'state'})     // 期望 scene.previewState 有值（stop/play/pause），mode 不再是恒 general
cocos_runtime({action:'play'})      // ⚠ 关键：**不再挂 120s**；期望 applied.by 有值、after.running=true
cocos_runtime({action:'pause'})     // 期望 after.paused=true
cocos_runtime({action:'step'})      // 期望 after.frames 比上一步 +1
cocos_runtime({action:'resume'})    // 期望 after.paused=false
cocos_runtime({action:'stop'})      // 期望 after.running=false；若 direct.call.healed 非空，说明它顺手治了 paused
cocos_capture_view({view:'game'})   // 期望回执里 mode.actual 会随 state 变
// ⚠ 2026-10-08 之后：`forcedRepaint` **默认是 false**（那次事故之后改的口径，见 `docs/冻结诊断.md` §5.4.1）——
//    本行原来的期望是 `forcedRepaint:true`，现在是 false；要它得显式传 `forceRepaint:true`（但那有代价）
```

**判据（判"修正有没有生效"）**：
| 看什么 | 说明什么 |
|---|---|
| `play` 在 ~30s 内**返回** | 流程没挂死（那条"120s 不回执"被绕过去了） |
| `applied.by === 'direct-previewplay'` | **这就是预期的路**（第 2 轮实测消息无效、直调有效）—— 若它反而是 `editor-message`，那说明这台编辑器的消息又能用了，**把回执原文抄下来**（那是新事实） |
| 每步 `ok` 与 `after` 一致 | 不再出现"报成功而状态没变"（第 1 轮那种假绿） |
| `state` 的 `scene.previewState` 有值 | `_state` 在这个版本上读得到（读不到会带 `note`，那也是结论） |
| `stop` 那步 `direct.call.healed` 非空 | `healPaused` 真的接上了（第 2 轮实测 stop 会留下 paused） |
| `capture_view` 回 `forcedRepaint:false` | 抓图前**没有**去排重绘（2026-10-08 之后这是**默认**口径；期望 `true` 的话得显式传 `forceRepaint:true`） |
| 全程没有出现 120s 级的长等待 | 旧实现那条"等消息回执"的路已经不在主路上 |

**不通过也照原样记**（把 `ok` / `error` / `applied` / `before` / `after` 全文抄进结果文件）——
这一节的意义就是"别让第二个假绿活到下一轮"。
