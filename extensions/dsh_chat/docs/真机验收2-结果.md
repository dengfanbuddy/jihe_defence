## 主会话的判定（2026-11，读上面原始事实之后下的结论）

**① A3 的路定了：引擎级注入 = 正路。** R1 的 2.2/2.3 把三件事一次说清：
`api` 六个口子**全在**；全屏探针在画面正中收到了 `touch-start`/`touch-end`，并且引擎输入源头那层
（`cc.input.on(MOUSE_DOWN)`）也收到了 `MOUSE_DOWN`；
两点差值 ÷ `Δclient` = `0.5599700149925038`，**逐位等于 `scaleX`/`scaleY`**（同一台机器同一个值）；
画布外的点 `p3` 在引擎层面仍记到了 `(-300, 1047)`（y 被 `747 - (-300)` 翻过），但**探针一条都没收到**。
⇒ **坐标空间就是"页面 CSS 像素"**（引擎的公式是 `clientX - canvasRect.x`），**注入真的进引擎**，
反面对照也成立。这与第 1 轮"合成 DOM 事件 0 条"正好构成对照，根因见 README 坑 64。

**② R2 那条"真人点击基线"不再需要**（本轮无人在场所以没测）：既然引擎级注入在同一现场能进引擎，
而合成 DOM 点击在同一现场**进不去**，A3 的取舍已经定了 —— 不必再请人点一次来区分。
但 R2 补的那条对照很有价值：**预览真跑着、探针全屏装着**的时候，`cocos_click_node` 的
`matchedBy:'href'`、`window.focused:true`、`events` 坐标三项全对，**`__dshHits` 却 0 条新增** ——
即"回执看着成功、引擎毫无感知"，正是第 1 轮那个结论的复现。

**③ R4 把"消息"这条路彻底判了死刑，并且**推翻了我原先的修正顺序**：
`send('editor-preview-set-play', true)` 之后 **30s（五次采样）`_state` 一直是 `stop`** ——
也就是说这条消息在这台编辑器上**连副作用都没有**（不只是"不回执"）；
`call-method('pause',true)` 在 `_state === 'play'` 时**仍然**抛 `setAttribute` 错。
而**编辑器工具栏的 `isPlay` 恰恰是靠这条消息的回执更新的**（`builtin/preview/static/toolbar/middle.js`：
`this.gameView.isPlay = i ? e : !e`）⇒ 它从不回执 ⇒ **走哪条路工具栏都同步不了**。
所以 `cocos_runtime` 的顺序**从"消息先试"翻成"直调优先、消息兜底"**（§9.8 已改），
省掉每次动作白白多等的一轮轮询。

**④ 顺带确认了两条**：`stop()` 之后 `director`/`game` **同时被留在 paused**（本轮又复现两次，
所以 `healPaused` 那条修正留对了）；**重起预览会重载运行场景**，运行期挂上去的 `__dshProbe`
随之消失（收尾那次 `removed:false` 的原因）—— 这条对"探针"这个手法本身是个提醒。

**⑤ R3 键盘口子也在**：`_dispatchKeyboardDownEvent({code:'KeyF'})` → `cc.input.on(KEY_DOWN)` 收到
`{keyCode:70}`，而 `cc.KeyCode.KEY_F` 也是 70 ⇒ `code → KeyCode` 映射成立。
（所以按键也能走引擎路；但 `key` 参数现在是 **Electron 加速键名**（`'Escape'`/`'A'`），
而引擎要的是 **DOM `code`**（`'Escape'`/`'KeyA'`）—— 换路时要一并做那张通用映射表。）

**下一步（第 3 批修正）**：把 A3 接成 `transport: 'engine' | 'page'`（`auto` 默认走 engine），
回执点名用了哪条；`page` 留着做"往 DOM 输入框打字"那类**必须落在页面**的事。
