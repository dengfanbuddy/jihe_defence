# .dsh-mcp/archive —— 退下来的 recipe（**不进索引**）

放这里的文件**不再是 recipe**：`findRecipes` / `readRecipe` / `runRecipe` 都看不到它们
（`listRecipeRecords` 是 `readdirSync('.dsh-mcp/recipes')` **非递归、只收本层 `*.js`**，
见 `extensions/dsh_chat/source/core/recipes.ts:214-226`）。

**为什么留着而不是删掉**：`.dsh-mcp/` 当时**未入库**（`git ls-files .dsh-mcp` = 0），
删掉就真找不回来了。归档 = 退出索引 + 保住参考实现 + 把判断理由留在盘上。

**为什么要有这个目录**：recipe 的价值靠**索引质量**，而索引质量靠**淘汰**。
一条按用途命名、结构写死的脚本占着 `findRecipes` 的检索预算，还会把后来的人带偏
（「原来 recipe 长这样」）。**错的 recipe 比没有 recipe 更贵。**

## 退下来的判据（三条，任一条不满足就该退）

1. **换个参数还能跑** —— 代码里没有写死的节点路径 / 文案 / uuid；参数不等同于「几个文案字段」。
2. **能说出 ≥2 个未来调用点**，且是**形状相同、用途不同**的两个。
3. **按形状命名，不按用途命名** —— 名字就是索引，用途化的名字检索时命不中。
